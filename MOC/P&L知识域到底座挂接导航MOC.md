# P&L知识域到底座挂接导航 MOC

## 一句话定义

这页把 `P&L知识域` 如何挂到公司级治理底座上，整理成一张可浏览、可回跳、可给 agent 调用的导航页。

它回答的是：

- 六张公司级底座卡在 P&L 里分别优先对应什么问题
- 想看 P&L 的口径、复核、判断、状态、异常治理时，应先调哪张底座卡
- 后续 P&L 接入 OB 时，agent 应如何从底座回落到 P&L 业务真相

---

## P&L 挂接公司级底座的总图

先把 P&L 当前的挂接关系压缩成一句话：

`先用公司级底座扫清经营分析与复核治理骨架，再回到 P&L 找口径、验证、复盘与责任链真相。`

对应关系可以先理解成两层：

### P0：结构治理挂接

- `公司级通用流程与验证标准` -> `P&L 口径通过标准 / 核算验证 / 复核标准`
- `公司级Owner与边界规则` -> `P&L 口径 owner / 复核 owner / 审批边界`
- `公司级交接与共享对象原则` -> `P&L 报表对象 / 预算对象 / 复盘对象 / 主记录`

### P1：高阶治理挂接

- `公司级判断决策闭环` -> `P&L 口径裁定 / 预算取舍 / 复盘结论`
- `公司级状态一致性与Crosswalk校验` -> `P&L 多版本口径 / 草稿测算 / 正式报表状态`
- `公司级SOP质量与异常暴露机制` -> `P&L 偏差暴露 / 超预算异常 / 复核失败复盘`

这说明 P&L 不是只围绕“算数”，而是天然覆盖：

- 口径定义
- 验证复核
- 责任链
- 状态对齐
- 异常回灌

因此它非常适合作为“分析型项目挂底座”的第一套验证样板。

## 一个最简单的调用顺序

后续不管是人还是 agent，处理 P&L 问题时，都可以优先按这套顺序走：

1. 先判断问题属于流程、边界、交接、判断、状态还是异常治理
2. 先调用对应的公司级底座卡
3. 再回落到 P&L 知识域和后续 P&L 结果性材料
4. 最后再下钻到 P&L 的具体口径、复核、复盘文件

## 本轮模板验证结论

1. 分析型项目可以按“知识域定义卡 + 挂接导航卡”方式接入 OB
