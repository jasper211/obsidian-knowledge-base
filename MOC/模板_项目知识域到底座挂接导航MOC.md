# 模板_项目知识域到底座挂接导航MOC

## 一句话定义

这页把 `[项目名]知识域` 如何挂到公司级治理底座上，整理成一张可浏览、可回跳、可给 agent 调用的导航页。

它不是解释该项目是什么，而是解释：

- 六张公司级底座卡在该项目里分别对应什么问题
- 想看该项目的流程、边界、交接、判断、状态、异常时，应先跳哪里
- agent 处理该项目问题时，应该先调哪张底座卡，再回到哪张项目专题页

---

## 为什么这页重要

只补 `知识域定义卡` 还不够。

如果没有这张挂接导航页，项目知识域通常只停留在“定义层”，还没有变成真正可导航、可调用的结构入口。

这页的作用就是把：

- 公司级底座
- `[项目名]` 专题页
- `[项目名]知识域`

三者真正接成一层“导航即调用”的结构。

---

## `[项目名]` 挂接公司级底座的总图

先把该项目的挂接关系压缩成一句话：

`先用公司级底座理解治理骨架，再回到 [项目名] 专题页找具体业务真相。`

对应关系建议先理解成两层。

### P0：结构治理挂接

- `公司级通用流程与验证标准` -> `[项目流程主链 / 验收 / 通过标准]`
- `公司级Owner与边界规则` -> `[项目角色职责 / 收口责任 / 边界结构]`
- `公司级交接与共享对象原则` -> `[项目交接点 / 共享对象 / 主记录]`

### P1：高阶治理挂接

- `公司级判断决策闭环` -> `[项目关键裁定 / 优先级取舍 / 例外判断]`
- `公司级状态一致性与Crosswalk校验` -> `[项目草稿 / 候选 / 正式状态对齐]`
- `公司级SOP质量与异常暴露机制` -> `[项目异常暴露 / SOP偏差 / 回写机制]`

---

## 第一组：流程与验证标准挂接

### 对应的公司级底座卡

- `公司级通用流程与验证标准`

### 在 `[项目名]` 中的主入口

- `[项目流程主链MOC]`
- `[项目知识域定义]`

### 这组挂接主要回答什么

- 该项目的关键流程节点是什么
- 每个节点靠什么通过
- 哪些地方靠 Gate
- 哪些地方靠人工复核或外部确认

### 适合 agent 的默认调用方式

当问题更像：

- “这步算完成了吗”
- “这里靠什么验收”
- “这个流程缺的是动作还是验证”

优先先调 `公司级通用流程与验证标准`，再回落到该项目的流程专题页。

## 一个最简单的调用顺序

后续不管是人还是 agent，处理 `[项目名]` 问题时，都可以优先按这套顺序走：

1. 先识别问题属于流程、边界、交接、判断、状态还是异常
2. 先调对应的公司级底座卡
3. 再回落到 `[项目名]` 的挂接入口
4. 最后进入该项目具体专题页或业务真相页
