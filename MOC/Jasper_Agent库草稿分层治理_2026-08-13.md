# Jasper Agent库草稿分层治理 2026-08-13

## 一句话结论

`Jasper AI协同经验引擎/AI工程能力整改项目/05_Agent库/草稿/` 不是普通“草稿区”。

它已经同时包含：

- 顶层架构总纲
- 已被真实项目验证过的方法论
- 各 Agent 的设计与运行说明
- 健康检测记录
- 大量运行状态与机器产物

所以它不能整体视为候选稿，而应拆成 4 层：

1. `主库候选`
2. `候选层`
3. `失效稿`
4. `源头运行资产`

---

## 当前总体判断

这块内容的真正价值核心，不在“草稿”二字，而在：

- 是否已经形成稳定方法
- 是否已有真实案例验证
- 是否仍代表当前有效版本
- 是否只是运行过程产物

因此后续处理 `05_Agent库/草稿/` 的默认顺序应是：

1. 先看顶层总纲与现行版本
2. 再看各 Agent 的 README / 需求定义 / 流程设计
3. 再看监控、检测、执行记录
4. 最后把工作区、分析运行产物、json 状态与缓存留在源头层

---

## 四层分流总表

| 层级 | 放什么 | 当前典型对象 | 处理原则 |
| --- | --- | --- | --- |
| 主库候选 | 已形成稳定方法、跨 Agent 可复用 | 顶层架构、搭建 SOP、验证标准、协作契约 | 优先进入 Jasper 主视图 |
| 候选层 | 重要但仍带阶段性或单 Agent 局部语境 | 各 Agent 的需求定义、流程设计、README | 保留归属，等待进一步收敛 |
| 失效稿 | 被新版本覆盖、仅保留追溯价值 | 旧版 v1.0/v1.1/v1.2 架构稿、旧 SOP 版本 | 不再作为主引用 |
| 源头运行资产 | 运行状态、缓存、测试产物、json、工作区 | `.vnw_workspace`、`.ait_workspace`、大批 `.json` | 只保留源头，不进主库 |

## 一、主库候选

当前最明确的主库候选是这几类：

### 1. 顶层架构总纲

- `三大主Agent体系架构_v1.4.md`
- `Agent体系搭建项目_项目章程_v1.0.md`

判断原因：

- 已经承担全局事实源作用
- 明确描述多 Agent 边界、现状、路线图
- 多处文档都在回指它们

处理建议：

- `v1.4` 作为当前架构主引用
- `项目章程_v1.0` 作为项目级总入口候选

### 2. 通用方法论总纲

- `Agent搭建SOP_v1.2.md`
- `Agent验证标准清单_v1.0.md`
- `双Agent协作契约_OB与方法论转正Agent.md`

判断原因：

- 已经超出单 Agent 局部设计
- 明确可复用于 PTA / VNW / AIT / OB / 方法论转正Agent
- 文档中直接写明来自真实实操，而非纯推演

处理建议：

- 优先视为 `Jasper AI协同经验主库候选`

### 3. 已被现实验证的结构模板

- `PTA/README.md`
- `VNW/README.md`

判断原因：

- 它们不是单纯介绍页，而是当前现行运行结构说明
- 尤其 `PTA` 已是被多次迁移与真实执行验证过的标准骨架

处理建议：

- 暂列主库候选，但仍保留“Agent 专属语境”标记

## 二、候选层

这层最主要是“高价值但仍带局部设计语境”的内容。

### 1. 各 Agent 的需求定义 / 流程设计

例如：

- `AIT/需求定义.md`
- `AIT/流程设计.md`
- `方法论转正Agent/需求定义.md`
- `方法论转正Agent/流程设计.md`
- `PTA/01_初始化项目_Initialize_Project/需求定义.md`
- `PTA/03_规划项目结构_Plan_Project_Structure/流程设计.md`

判断原因：

- 很有价值
- 但仍然带某个 Agent 的阶段性边界
- 部分还明确写着“早期原型”“草案”

处理建议：

- 进入候选层
- 后续待更高层规则抽出后，再决定哪些上升为 Jasper 主库

### 2. 单 Agent 的设计补充与说明书

例如：

- `VNW/03_规划项目结构_Plan_Project_Structure/*.md`
- `PTA/08_设计提示词_Design_Prompts/prompts/*.md`
- `OB/08_设计提示词_Design_Prompts/prompts/*.md`

判断原因：

- 有方法价值
- 但更像局部实现资产，不是全局稳定真相

处理建议：

- 优先保留候选层

### 3. Pipeline 健康设计页

- `_pipeline_health/Pipeline差距矩阵_检测机制设计_v1.0.md`

判断原因：

- 它描述的是一套跨 Agent 的检测思路
- 有明显方法价值
- 但仍是某一阶段的检测机制设计，不宜直接当总底座

处理建议：

- 候选层高优先对象

## 三、失效稿

这里的失效，不代表没价值，而是：

- 不再作为当前主引用

### 1. 旧版本总纲

- `三大主Agent体系架构_v1.0.md`
- `三大主Agent体系架构_v1.1.md`
- `三大主Agent体系架构_v1.2.md`
- `三大主Agent体系架构_v1.3.md`
- `Agent搭建SOP_v1.0.md`
- `Agent搭建SOP_v1.1.md`

判断原因：

- 已被更高版本覆盖
- 保留追溯价值
- 不宜继续在主视图并列引用

处理建议：

- 统一标记为 `历史版本`
- 当前主引用只保留最新版本

### 2. 明确带 `_retired_flat_structure`

例如：

- `PTA/_retired_flat_structure/`
- `VNW/_retired_flat_structure/`
- `OB/_retired_flat_structure/`

判断原因：

- 目录名已明确说明退役

处理建议：

- 默认判定为失效稿或历史结构

## 四、源头运行资产

这是当前最容易污染视图的一层。

### 1. 工作区与运行包

例如：

- `VNW/.vnw_workspace/`
- `AIT/.ait_workspace/`

### 2. 大量 json / 状态 / 缓存产物

当前整个 `05_Agent库/草稿/` 中：

- 总文件量约 `3660`
- 其中 `.json` 约 `2964`
- `.md` 约 `236`

这说明绝大多数并不是知识页，而是运行资产。

处理建议：

- 只保留源头
- 不参与主库叙事

### 3. 检测记录与执行批次产物

例如：

- `_pipeline_health/检测记录_*.md`
- 各 Agent `执行记录.md`
- `analysis_runs/`

判断原因：

- 它们更多承担证据、审计、复盘功能
- 不适合作为当前稳定方法真相

处理建议：

- 默认候选或源头层
- 只在需要证明某条经验来源时被引用

## 当前最该进入 Jasper 主视图的首批对象

如果这轮只选一批最值得进入主视图的对象，建议优先是：

1. `三大主Agent体系架构_v1.4.md`
2. `Agent搭建SOP_v1.2.md`
3. `Agent验证标准清单_v1.0.md`
4. `双Agent协作契约_OB与方法论转正Agent.md`
5. `Agent体系搭建项目_项目章程_v1.0.md`

这 5 份共同构成：

- 总架构
- 搭建方法
- 验证方法
- 多 Agent 协作规则
- 项目级治理入口

---

## 当前最不该误升主库的对象

这批内容当前不要误升：

- 旧版 v1.0-v1.3 顶层总纲
- `_retired_flat_structure`
- 工作区目录
- 大量 json 状态文件
- 检测记录周报
- 单批次执行记录

---

## 对 Jasper 工作文档治理的推进意义

这张分层页的意义是把一个很大的“草稿仓”变成可治理结构：

- 不再把所有草稿一视同仁
- 不再把所有版本并列看待
- 不再让运行资产混进知识主视图

它也说明了一件很关键的事：

- `Jasper AI协同经验引擎` 已经有一批不该再叫“草稿”的内容了

---

## 下一步建议动作

基于这轮分层，下一步最合理的是：

1. 先把这 5 份首批主库候选接入 Jasper 经验层主视图
2. 再给 `PTA / VNW / AIT / 方法论转正Agent / OB` 分别补一张归宿卡
3. 最后再处理各自的候选层和历史版本治理
