# P&L口径定义 MOC

## 一句话定义

这页负责把 `P&L知识域` 里的口径类知识收成一个专题入口，重点回答：

- 收入、成本、毛利、利润这些核心对象到底怎么定义
- 哪些口径已经可以作为正式判断依据
- 哪些口径仍处在比较、解释或待裁定状态

它的作用，是让后续 OBagent 在处理 P&L 问题时，不只是“看到一份报表”，而是先找到报表背后的正式口径骨架。

---

## 为什么这页重要

P&L 项目里最容易失控的，不是算表本身，而是口径。

如果口径不稳定，就会出现：

- 同一个指标在不同文件里有不同解释
- 分析结果成立与否取决于使用了哪一版口径
- 复盘、预算、审批、复核都失去共同基础

所以这页的重点不是收集所有财务定义，而是收束：

- 哪些定义已经是正式口径
- 哪些定义只是过程版本
- 哪些定义需要进入判断闭环

---

## P&L 口径定义的骨架

当前建议先把 P&L 口径分成 4 组来看。

### 1. 收入口径

关注：

- 什么条件下收入可以被确认
- 收入确认依赖哪些前置条件
- 哪些收入只是候选、预测或草稿，不应被当成正式结果

后续建议沉淀的正式对象：

- `收入定义`
- `收入确认条件`
- `收入例外口径`

### 2. 成本口径

关注：

- 成本如何归类
- 成本何时计入
- 哪些成本属于一次性、阶段性或特殊归集

后续建议沉淀的正式对象：

- `成本定义`
- `成本归集规则`
- `成本例外处理口径`

### 3. 毛利 / 利润口径

关注：

- 毛利和利润的计算边界
- 哪些调整项进入，哪些不进入
- 不同版本利润口径之间的差异来自哪里

后续建议沉淀的正式对象：

- `毛利定义`
- `利润定义`
- `利润调整项规则`

### 4. 版本与解释口径

关注：

- 哪些是正式口径
- 哪些是分析稿口径
- 哪些是为了比较、测算或特定场景临时建立的解释口径

这组最关键的不是“定义更多版本”，而是明确：

- 版本边界
- 适用场景
- 是否已获得正式解释权

---

## 口径问题最常见的四类风险

### 1. 同名不同义

表面上都叫“利润”“毛利”“收入”，但实际计算边界不同。

### 2. 草稿冒充正式

比较口径、临时测算口径、解释性口径，被误当成正式管理口径。

### 3. 多版本并存但无主版本

不同团队、不同报表、不同时间段各用一套，没有唯一解释权。

### 4. 口径变更无回灌

口径调整后，没有同步回写到复核、预算、复盘、审批上下文。

## 这页主要回答什么

后续这页应该能稳定回答下面几类问题：

- “这个指标到底按哪一版口径算”
- “为什么这份利润分析和上一份不一样”
- “这条口径已经正式了吗”
- “收入/成本确认到底靠什么成立”
- “某个调整项为什么进这一版、不进另一版”

## 当前阶段的实际用法

截至 2026-08-13，这页已经从纯专题骨架页升级为“已挂接真实口径候选主材料的口径导航页”。

当前最适合的用法是：

1. 作为 P&L 第一批白名单文件的收口入口
2. 先调用已识别的业务模型卡候选，判断当前口径是否仍属候选态
3. 作为未来 `收入定义 / 成本定义 / 利润定义` 等正式卡片的继续挂载页
4. 作为 agent 判断“这是正式口径还是过程版本”的第一跳入口

当后续 P&L 正式材料逐步补入后，这页就会从“专题框架”升级为“正式口径导航页”。
