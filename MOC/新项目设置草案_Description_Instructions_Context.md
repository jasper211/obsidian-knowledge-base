## 二、Instructions（自定义指令，完整版）

```
# OB（Obsidian巡检Agent）项目协作指南

## 项目定位
本项目前身是"第二大脑"（纯人工整理知识库，未接入AI、未实现自迭代）。
现改造为OB自身的建设与优化项目。OB是"个人Agent体系架构"（五Agent：
PTA/VNW/AIT/方法论转正Agent/OB）里的基础设施/治理层Agent，服务于其余
四个业务Agent+全部AI工具终端。PTA/VNW/AIT所在的"AI工程能力整改项目"
只负责对接OB，不负责建设OB——建设OB是本项目的范围。

## OB的三条能力线（不要把OB简化理解成"只做原子提炼"）
1. **①巡检**：symlink/MCP配置/Server连通性/vault统计等健康检查。
   成熟度最高，已有实际代码`ob_sync_agent.py`（648行，6项检查）。
2. **②检索服务**：给业务Agent提供"项目背景上下文包"（`get_context()`/
   `format_for_prompt()`），替代各Agent自己重新造检索能力。
   后端已完成混合检索(关键词+向量+图谱)+信任标注，但PTA/VNW/AIT
   目前零行代码真正调用过——服务端就绪不代表能力线闭环。
3. **③概念笔记提炼**：把项目原始文档提炼成结构化知识原子（concept_atom）
   +聚类枢纽（entity_hub）。当前是一次性批处理跑出的静态快照，
   **写入侧完全没有自动化**（新知识产生后不会自动变成新原子写回vault，
   要靠人工再跑一次`migrate_full_vault.py`）——这才是"没有自迭代"的
   真正病根，不只是治理字段没填这么简单。

## 当前架构（Obsidian vault: OB知识库_vault，2026-07-25核实）
- EA流程架构项目/ — 白名单收窄到8个"结果性"来源后持续提炼中，原子/枢纽
  实时数字见[[仪表盘_项目全景]]（不要用本文档任何历史快照数字），schema
  最完整（authority_layer/domain/confidence/decision_status/entity_type/
  entity_ref全字段，entity_type含7个白名单来源类分类），confidence多数
  已由LLM随提炼判断出真实值（不再是99%占位符），decision_status仍接近
  全UNSTATED——这是预期状态，因为白名单不含03_已锁定层内容，本来就没有
  走过Mark正式审核锁定
- Jasper AI协同经验引擎/ — 已提炼205个原子，schema与EA对齐（含治理
  字段），但**尚未跑过聚类，0个entity_hub**——这是真实差距，不是"没提炼"
- 方法论知识库/ — 方法论转正Agent的行业自学习线，独立schema
  （source_url/collected_at/staleness_review_date/info_type/
  evidence_basis），跟上面两个项目的concept_atom schema不共用，通过
  Claudian对话持续ingest中，不是Python批处理产出
- Rw权益项目 — vault里没有对应文件夹，明确不纳入OB知识库（是OB服务的
  对象项目，不是OB自身知识）
- MOC/ — 导航枢纽、仪表盘；旧版《OBagent诊断与整合路线图》已因内容
  基于白名单收窄前的旧数据而废弃归档，不再作为现状参照
- **四个顶层目录/两套schema体系，不是同一模板的多份实例**，处理前必须
  先确认在处理哪个项目、对应哪套字段结构

## 每次对话原则
1. 先看vault里的实际数据/文件，不要凭空假设原子数量、治理状态、
   哪个项目"提炼了没有"——起点笔记等导航文档里的描述可能是过期信息，
   以grep/实际文件为准；用户上传的《需求定义.md》《三大主Agent体系架构》
   是权威口径，如果vault内文档与之冲突，以这两份加上用户当场确认为准
2. 不要把"治理评分补齐"当成"自迭代问题"的完整解法——写入侧自动化
   （OB自巡检机制）没建之前，任何存量数据修补都只是让静态快照变好看，
   不会让知识库真正持续更新
3. 涉及去重、合并、拆解枢纽、补齐schema等会改写/删除原文件的操作，
   先小范围试跑，经确认效果后再批量执行
4. 每次产生重要诊断结论、决策或修复方法，主动提示更新对应的MOC文档
   （起点_从这里开始.md / 仪表盘_项目全景.md / 诊断路线图）
5. EA-KB（原第二大脑项目）里的历史文档，以最新版本号为准，已作废文档
   （如DEPRECATED开头、明确标注"已作废"的）不得引用
6. 本项目不负责实现PTA/VNW/AIT调用OB的接口代码（那是"AI工程能力整改
   项目"的范围），但要保证②检索服务的接口稳定、文档清楚，方便对方接入

## 记忆系统
- 保存三条能力线各自的进展、修复阶段完成情况、用户对优先级的裁定
- 跨对话自动访问，确保修复工作可追溯、不重复劳动
```
