## 两个Agent的定位与边界

依据《三大主Agent体系架构_v1.3》§6：
- **OB**：五Agent体系（PTA/VNW/AIT/方法论转正Agent/OB）里的基础设施/治理层，三条能力线（巡检/检索服务/概念笔记提炼）
- **方法论转正Agent**：两条并列线——内部治理线（未启动，等AIT真实案例）+ 行业自学习线（已启动，AI协同方法论方向）

完整协作契约（顶层目录归属/schema兼容/融合机制四件套/待裁定项）见代码仓库
`05_Agent库/草稿/双Agent协作契约_OB与方法论转正Agent.md`，本文档不重复，只做导航。

## 内容关联机制（四件套，摘要）

1. **硬关联**：方法论卡片若能对上EA正式编码（entity_ref），走entity_ref枢纽机制，同编码下项目原子和方法论卡片混合挂载
2. **软关联**：语义相似内容走embedding聚类（复用非正式主题枢纽机制，小样本先验证）
3. **晋升机制**：项目原子→方法论卡片，筛选条件 `confidence=HIGH 且 status=生效 且 backlink>=3 且未被entity_ref矛盾扫描标记冲突`
4. **冲突检测**：同entity_ref下若既有项目原子又有方法论卡片，拿方法论卡片当标尺比对项目原子

**当前实现状态**：entity_ref跨文件夹扫描代码尚未实现（`cluster_atoms.py`目前仍是单文件夹扫描），等方法论知识库积累更多真实卡片、双方验证过效果后再动这部分代码。

## EA流程架构项目的知识组织方式

按`entity_type`分类：
- **正式编码类**：L3流程 / KPI / 价值流 / 岗位族（对应EA自己的DIM_PROCESS/DIM_KPI等正式字典）
- **白名单来源类**（2026-07-24新增，覆盖原本"待聚类"的87%）：SOP / Agent机制 / 规则与GAP / 方法论标准 / 规则空白 / 信号基线 / 熔断规则

按`authority_layer`分层：00_治理 / 01_原始 / 02_定稿（白名单结果性来源专用） / 03_已锁定

详见 [[仪表盘_项目全景]]、[[知识枢纽索引]]。
