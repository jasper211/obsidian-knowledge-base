# P&L状态一致性与版本校验 MOC

## 一句话定义

这页负责把 `P&L知识域` 里的状态定义、版本边界、正式发布条件、多版本 Crosswalk 校验类知识收成一个专题入口，重点回答：

- 草稿版、分析版、审批版、正式版到底怎么区分
- 同一结果在不同文档、不同系统、不同知识层里的状态是否一致
- 哪一版可以支撑正式经营判断，哪一版只能作为候选或过程依据

它的作用，是让后续 OBagent 在处理 P&L 问题时，不只知道内容是什么，还能判断“这是不是正式版、这几份是不是同一版、能不能直接拿来决策”。

---

## 为什么这页重要

P&L 项目天然会出现多版本并存：

- 草稿测算版
- 分析讨论版
- 审批流转版
- 正式发布版

如果没有一张专门的状态与版本页，就很容易出现：

- 分析稿被误当成正式结果
- 审批中的版本被当成已经生效
- 不同团队各引用一版，最后都说自己“没错”
- 复盘结论没有说清作用于哪一版

所以这页的重点，是把 `对象一致 -> 语义一致 -> 状态一致` 这条校验链先钉住。

---

## P&L 状态一致性与版本校验的骨架

当前建议先把这条链分成 4 组来看。

### 1. 状态定义

关注：

- 哪些状态是 P&L 默认允许存在的
- 每种状态分别代表什么成熟度
- 哪些状态不能被下游当成正式依据

后续建议沉淀的正式对象：

- `draft状态定义`
- `analysis状态定义`
- `approval状态定义`
- `final状态定义`

### 2. 版本边界

关注：

- 同一个对象的不同版本如何标识
- 版本切换靠什么触发
- 哪些变更只是解释补充，哪些变更已经构成新版本

后续建议沉淀的正式对象：

- `版本命名规则`
- `版本切换条件`
- `主版本规则`

### 3. Crosswalk 校验

关注：

- 同一结果在不同文档、系统、知识层里是否在说同一对象
- 状态是否真正一致
- 是否存在一边 final、一边 draft 的高风险漂移

后续建议沉淀的正式对象：

- `存在性校验结果`
- `语义一致性校验结果`
- `状态一致性校验结果`

### 4. 正式发布条件

关注：

- 一份 P&L 结果需要满足什么条件才可进入正式版
- 是否必须完成复核、审批、证据留存
- 哪些条件不满足时必须留在候选或待确认状态

后续建议沉淀的正式对象：

- `正式发布门槛`
- `发布前校验项`
- `禁止冒用规则`

## P&L 状态问题最常见的四类风险

### 1. 草稿冒充正式

测算版、分析版或候选版被当成正式经营结果引用。

### 2. 多版本并存但无主版本

不同团队都引用“自己的最新版”，但没有唯一主版本。

### 3. 语义相近但对象不一致

表面看起来都在讨论同一个利润结果，实际上版本前提或输入范围不同。

### 4. 状态变了但下游没同步

上游已经更新为审批版或正式版，下游仍然沿用旧版或把旧版当最新依据。

## 这页主要回答什么

后续这页应该能稳定回答下面几类问题：

- “这版结果到底是草稿、审批中还是正式版”
- “这两份报表是不是同一版结果”
- “为什么分析侧和财务侧都说自己引用的是最新版”
- “这份材料能不能直接拿来支撑正式经营判断”
- “复盘结论到底作用在哪个版本上”

- 文件状态：`正式生效`
- 当前挂载身份：`Slot-05 首份主库材料`

这份材料当前最重要的价值，不是定义某个财务指标的业务口径，而是先把 P&L 项目的版本边界、层级边界和正式归位规则钉住。

基于该文件，当前已经可以先固定以下状态一致性真相：

- `01_原始材料-外部导入` 是原始输入层，不承接分析结论回写
- `02_过程成果-工作产出` 是草稿、过程稿和迭代工作层
- `03_发布成果-交付物` 是正式交付层，只放可正式引用成果
- 文件按生命周期单向晋升，默认走 `01 -> 02 -> 03`
- 一份文件只放一个正式位置，不重复存放
- 临时工作过程与正式交付必须分层管理

### 为什么这份材料可以进入主库

这份材料之所以可以直接进入 OB 主库，而不是只留候选层，原因是：

- 它已经明确标注 `正式生效`
- 它回答的是项目级治理真相，而不是某次过程讨论
- 它能直接支撑 Agent 对“这份材料当前处于哪一层、能不能当正式依据”的判断

### 当前仍不能从这份材料直接推出什么

即使它已进入主库，这份材料当前仍不能单独回答：

- 某个利润口径的正式业务定义是什么
- 某个分析结果的最终复核标准是什么
- 某个具体报表当前属于草稿版还是最终发布版

也就是说，它先解决的是 `分层与归位规则`，不是 `具体业务结果版本结论`。

## 当前阶段的实际用法

截至 2026-08-12，这页已经从纯专题骨架页升级为“有首份真实主库材料挂载的状态与版本导航页”。

当前最适合的用法是：

1. 作为 P&L 第一批状态定义、版本规则、Crosswalk 校验材料的收口入口
2. 先调用已挂载的目录治理与层级边界基线
3. 作为未来 `主版本规则 / 正式发布门槛 / 版本切换条件 / 禁止冒用规则` 等正式卡片的继续挂载页
4. 作为 agent 判断“这是不是正式版、这两份是不是同一版”的第一跳入口

当后续 P&L 正式材料逐步补入后，这页就会从“专题框架”升级为“正式状态与版本导航页”。
