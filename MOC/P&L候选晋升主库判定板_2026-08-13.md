## 候选晋升的统一总规则

### Slot-04选材复核（2026-08-30）

在真实项目的治理、过程成果、发布成果目录中按预算/复盘/裁定文件名定向检索，找到2026-08-25发表头前裁定回执及2026-08-27 P02专业批准授权执行副本。前者处理字段与模型范围，后者处理专业授权，均不是预算偏差或经营复盘结果，不能为填满槽位而纳入Slot-04。保持待选材；检索未覆盖所有命名、格式及目录，不证明项目完全没有偏差复盘材料。表头裁定回执可作为Slot-06治理回写候选线索，见 [[P&L异常偏差与回写机制MOC]]。

任一候选材料要晋升主库，默认至少同时满足 4 条：

1. `结论收敛`
   不再是明显过程稿，不再依赖临场口头补充

2. `证据闭环`
   关键事实、关键状态或关键规则已有足够证据支撑

3. `可稳定复用`
   后续 agent 或项目分析可以直接调用，而不容易误用

4. `版本状态清楚`
   能明确说出它是 `候选 / 正式 / 已生效 / 已验证` 中的哪一种

只满足一半时，继续留候选层。

## Slot-02 晋升判定

### 首版主库可用验收链（2026-09-01）

本轮定向复核 [证据文件登记表v1.1](</Users/a112233/Desktop/P&L_EA小组Jasper/02_过程成果-工作产出/校验与上下文/P0事实与证据/证据文件登记表_v1.1.md:1>)：当前只有两条会议事实来源，状态均为“已收到待核验”；登记表规则也明确文件存在不等于已验证。结合下方已核空白穿行底稿与E1—E16待补目录，Slot-02从候选到可作为主库验证依据至少需要形成这条链：

`原件登记且唯一物理路径可达 -> 核验人改为已验证并写结论/缺口 -> 真实季度数据进入穿行底稿 -> 收入、成本、分成可复算 -> 差异有Owner解释与处理状态 -> 专业复核/签署 -> OB切换主引用并保留旧版替代关系`

首版验收单位不是“整份材料看起来完整”，而是一组能闭环的真实季度样例。该样例需同时能回答：使用了哪些原件、由谁核验、怎么算、差异如何解释、谁确认可使用、适用哪个期间和版本。会议纪要、空框架、候选断言或单独签署均不能独自跨过全部门槛。

当前可用结论：Slot-02的骨架和缺口导航可供Agent查询；真实经营数字、复算结果和正式验证结论仍不可作为主库事实调用。新增原件、已验证状态或填充底稿出现时，只增量复核受影响事实，不重扫整个P&L项目。
