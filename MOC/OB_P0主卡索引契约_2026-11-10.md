# OB P0主卡、索引与字段契约

基础协议：[共享输出协议v0.2](../../初代-中代本体规划和搭建/共享输出协议.md)。沿用schema_version=0.2，不改上游协议文件；OB新增字段是兼容扩展，导出保留核心字段，不能声称上游消费者已测试支持。

## 选定落点

新主卡：`MOC/OB主卡/<card_id>.md`；待核候选先进入`MOC/OB候选/<batch_id>/`，不在主索引提供现行知识。已验收旧原子先以原位置登记为主卡，不强制搬迁；相同定义已有主卡则复用它，不创建第二份正文。

主索引：[[OB主索引]]；批次台账：[[OB批次台账]]。三专家视图使用索引expert_views列筛选并链接主卡，不复制正文；后续独立视图页只能引用同一card_id/version。P0仅初始化空索引，不假装已有主卡通过验收。

card_id采用`OBK-`加UUID，由执行批分配，分配后稳定且不含项目分类；source_id采用`OBS-`加UUID。移动或重分类不换ID；无法确认是否同一定义时分别候选，标related_to候选而非合并。首次登记前同时查新索引和直接相关旧MOC/原子，不能把空新索引当作不存在旧知识。

## 字段映射

独立核查后常规补齐：Source记录固定保存为`MOC/OB来源登记/<source_id>.md`，只存协议要求的元数据与必要定位，不存服务器原文件全文。source_refs.source_id必须解析至该确切路径；版本观测保留在同一Source记录的版本表，以sha256/source_version/mtime_utc及checked定位具体引用版本，不用后来的观测覆盖旧证据。Source记录的未知权限、Owner或主源状态须保留并阻止晋升。首批候选回执需逐项列出v0.2核心字段与Source解析检查结果，未经独立复核不发布主卡索引。

| 旧/来源字段 | v0.2及OB扩展 | 规则 |
|---|---|---|
| 标题/概念名 | definition_name, aliases | 名称相同不证明语义相同 |
| 原子正文 | definition_text, definition_quote | 整理与精确引文分开，不能整篇复制 |
| 旧project/entity_ref | project_domain, legacy_refs | project是原项目归属；entity_ref仅保留挂点，不能当card_id |
| 主域 | domain | 语义主域：香港保险/行业合规/公司上下文/待分类；与project_domain独立 |
| 跨专家分类 | expert_views | 数组，可多选；不改变原项目归属或审批 |
| 原路径/引用 | source_refs及独立Source记录 | source_id、locator、exact_quote、checked必查；不伪造行号 |
| 来源mtime | source_mtime_utc | 扩展观察字段，不映射为source_date |
| 旧status/completeness | legacy_status, status, chain_status | 不直接转accepted；结构complete不是链路完整或业务批准 |
| 旧版本 | version, supersedes, revision_reason | supersedes必须有依据，无依据保留冲突 |
| 来源审批/受众 | source_approval_status, sensitivity, allowed_audience | unknown不自动变为approved/public |

核心KnowledgeCard完整字段：card_id、definition_name、definition_text、definition_quote、domain、aliases、scope、status、canonical_ref、source_refs、analysis_chain、chain_status、gaps、relations、version、supersedes、sensitivity、allowed_audience。Source沿用source_id/path/sha256/source_version/produced_by/produced_by_evidence/source_date/ingested_at/source_approval_status/access_scope。未知日期null、作者unknown；正文定位需版本或摘要，缺失则checked=false。

## 生命周期与历史原子

status沿用draft/candidate/accepted/disputed/superseded。独立扩展review_state记录pending/current/stale/rejected/archived，避免另造含义冲突的核心状态。默认现行输出要求status=accepted且review_state=current、来源和受众条件满足；仍不代表业务批准。待核或冲突可在审查视图显示，不进入默认现行答案。

旧无效/重复/无来源原子先登记legacy_refs及拒收原因，不删除；不自动导入索引。过时但历史有效的原子保留历史适用范围。P&L及排除范围原子禁止进入新默认视图；旧目录仍存在，本批不宣称旧全库检索已物理屏蔽。

候选核查通过后：保存原版本快照于`MOC/OB主卡历史/<card_id>/<version>.md`（仅OB卡，不是服务器原文件），修订主卡，再更新索引。若写入中断，批次保持pending，完成一致性验证前不发布索引。canonical_ref指向实际主卡相对路径，同card_id仅一个现行索引行。

关系沿用depends_on/part_of/applies_to/constrains/contradicts/supersedes/related_to，每条保留来源和candidate/verified状态；无来源不能verified。document_chain与upstream_chain分别记录，缺失不补造。
