# HR Agent拆分待定

旧机制把HRA和HRM暂时合并为一个候选Agent，并把是否拆分留待运行后根据工作量和触发频率评估。其“规模太小”依据是当时只选5条L4，不能继续作为当前理由。

当前候选Agent目录v3仍保留“人力资源长尾合并Agent”，但口径已改为Agent拥有两个L3的全部16条L4，T26汇总为8条Aug、8条Hybrid、1个资金安全关卡和1个物理执行项。它证明候选建模仍采用合并名称，不证明Agent已经开发、运行或通过运行数据验证“应合并”。

流程导航已按 [[L3-HRM人员全生命周期管理]] 与 [[L3-HRA人力分析与决策支持]] 分开；L3边界拆分不等于Agent必须拆分。最终Agent边界仍需明确裁定或运行证据。
