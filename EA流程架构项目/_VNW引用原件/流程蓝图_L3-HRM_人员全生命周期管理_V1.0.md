## §1 流程概览

本流程覆盖员工从入职到离职的完整人员管理链路，包括定岗定编、招聘选拔、入职配置、试用考核、在职培训、绩效考核、薪酬发放、晋升调岗、退出归档九个阶段，输出统一员工档案体系。

**当前状态**：流程库完全缺失，招聘、绩效、薪酬、培训等模块分散执行，未形成端到端闭环；定岗定编做了半年多未落地；员工档案分散各环节，无统一归档。

**前置流程**：L3-SPE（提供岗位编制目标）
**后续流程**：L3-HRA（提供人员数据用于分析）

> ℹ️ **主体区分**：公司主体（RW Inc. 等）由 Fiona 负责；牌照公司主体与天领主体由袁林负责。人员归属确认路径：Fiona名单 → 敏然补充业务线 → 各部门分发。

> ⚠️ **P0缺口**：①定岗定编缺乏方法论，岗位设计不被业务部门认可；②招聘流程不规范，JD在招聘过程中反复修改；③员工18个月成长路径未成体系；④绩效与薪酬分散管理，未与人员发展挂钩；⑤员工档案分散在各环节，未统一归档。

## §2 触发条件与输入物

### 触发条件
- **持续性**：新员工入职/员工离职时触发
- **月度定期**：工资发放（每月10号）；内地下月预算编制（每月25号提交）；香港提前5天
- **按需**：晋升/调岗审批、薪酬调整

### 输入物

| 输入物 | 来源 | 实际状态 |
|--------|------|---------|
| 岗位编制需求（来自业务部门） | 各部门负责人/Mark | 口头提出，无标准JD模板 |
| 候选人简历 | 招聘渠道/内推 | 分散，无统一ATS系统 |
| 薪酬预算 | 财务/Mark | 有预算框架，执行口头确认 |
| 上期绩效结果 | 袁林（L3-SPE产出） | 散落各环节 |

## §3 主干步骤（9步）

```
[Step 1] 定岗定编与岗位设计
  L4-HRM-01 → 岗位编制方案 + 岗位JD(Human)
  · 基于业务目标确定各部门岗位数量
  · 设计岗位JD（当前：做了半年多未落地，业务部门不认可）
        ↓
[Step 2] 招聘选拔与面试评估
  L4-HRM-02 → 招聘面试记录 + 竞争性分析(Human)
  · 发布招聘需求，筛选简历
  · 组织面试，输出面试记录（当前JD在招聘过程中反复修改）
        ↓
[Step 3] 入职配置与合同签署
  L4-HRM-03 → 劳动合同/Offer + 系统权限配置(Human)
  · 签署劳动合同/Offer，完成入职手续
  · 配置系统权限，更新人员归属表
        ↓
        ◆ Q1：试用期考核是否通过？
        ↓
[Step 4] 试用期考核与转正
  L4-HRM-04 → 试用期考核结果 + 转正评估(Human)
  · 试用期满进行考核评估
  · 转正决策（通过/延长/终止）
        ↓
[Step 5] 在职培训与发展
  L4-HRM-05 → 培训记录 + 成长路径方案(Human)
  · 执行培训计划（当前：18个月成长路径未成体系）
  · 输出个人成长路径方案
        ↓
[Step 6] 绩效考核与结果应用
  L4-HRM-06 → 绩效考核结果 + 结果应用记录(Human)
  · 按L3-SPE绩效方案执行考核
  · 将绩效结果与薪酬/晋升挂钩（当前：未挂钩）
        ↓
[Step 7] 薪酬激励与发放
  L4-HRM-07 → 薪酬发放记录 + 激励方案(Human)
  · 每月10号发放工资
  · 内地预算每月25号提交财务；香港提前5天
  · 维护人员归属表（Fiona名单→敏然补充业务线→各部门分发）
        ↓
[Step 8] 晋升与调岗管理
  L4-HRM-08 → 晋升记录 / 调岗审批(Human)
  · 处理晋升/调岗申请，完成审批留痕
        ↓
[Step 9] 人员退出与档案归档
  L4-HRM-09 → 离职交接记录 + 员工档案（最终沉淀）(Human)
  · 办理离职手续，完成工作交接
  · 统一归档员工全周期档案（当前：档案分散，无统一归档）
```

## §4 判断节点

### Q1：试用期考核是否通过？（Step 3后）

| 结论 | 后续路径 |
|------|---------|
| 通过 | → Step 4转正，进入在职管理 |
| 延长试用 | → 继续试用，补充考核 |
| 不通过 | → 终止试用，进入Step 9退出流程 |
