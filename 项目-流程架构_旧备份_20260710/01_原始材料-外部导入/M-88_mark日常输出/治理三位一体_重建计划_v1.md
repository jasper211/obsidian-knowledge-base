# 治理三位一体重建 — 完整计划 v1（执行前置框架）

> 协调 2026-06-14 / 框架按 Mark 裁断 R7：需求痛点 → 目标锚点 → 差距分析 → 问题定义 → 解决措施 → 执行方案 →（才）执行
> 性质：这是"先重建健全治理体系"的**完整计划**。执行（草母 schema 等）在本计划 Mark 定形后才动。
> 代号当场解释（R2）

## 1. 需求 / 痛点 / 诉求

**痛点（本 session grep + 实证，非臆测）**：
- **验收语义错位**：节点验收是"流程跑通"，不是"达终态标准"——你只能在终点感知差距、无法保证"通过的节点 = 想要的终态"。
- **治理资产散（grep 实证）**：18 个审计脚本无登记表统管；12 份规划 spec 缺 5（S1 生命周期/S2 快照/S6 系统讲解/S11 门登记/S12 演示）；无前端架构总 schema；母图 L0 媒介/L2 传导层 0 spec；无架构完整性校核。
- **改一处不传导**：除 EE 的 gen_root_claude_md（改源自动重生那套）局部，治理资产改动不自动沿链路传导。
- **跨四系统不一致**：EE/IE/vault/数据中台 各有各的 CLAUDE.md/治理，不统一。
- **我自己反应式**："一问题一补丁"，越补越碎（你已纠）。

**诉求（Mark 6-14）**：建 **schema-spec-code/SOP/skill 三位一体**治理架构，保任务执行完整性，可**架构 + 质量双重校核**；先重建健全，优先于任何单项任务。

## 2. 目标锚点（锚点优先 / L0_03，非凭空设计）

- **战略锚**：**BO 程序（业务本体工程，统一四系统本体）的治理孪生**——治理统一。一个管"知识是什么"，一个管"工作怎么被治"，两根支柱并立。
- **方法论锚（已验证、反推非设计）**：EE 已跑通的 **CMP-0（机制化优于记忆化）+ gen_root_claude_md（改源传导）+ framework_patch_log + 18 审计脚本**——把这些**已验但散的机制**收成统一三位一体，不另起炉灶。
- **目标态**：任一交付物/任务 = **spec**（语义质量）治 + **schema**（结构传导）保一致 + **code/SOP/skill**（执行）兜，且可双重校核。

## 3. 现在的差距分析（current → target，三轴 + grep 标）

| 轴 | 现态（grep 实证） | 目标态 | gap |
|---|---|---|---|
| **spec 语义层** | 6/12 建 + 模板纪律；无分层/分主题/分类别骨架；L0/L2 层 0 spec | 全层全主题分类 spec + 统一骨架 | 🔴 大 |
| **schema 结构层** | 有数据 schema（view_model/surface_contract）+ 本体 schema（.ttl）；**无治理总 schema**；改一处不全传导 | 治理总 schema + 全链传导 | 🔴 大 |
| **code/SOP/skill 执行层** | 18 审计**散**无 registry；SOP 散各 CLAUDE.md/CMP；skill 封装 defer（500 门未到） | gate registry 统管 + SOP 归位 + skill（条件后） | 🟡 中 |
| **双重校核** | 质量校核 半-有但散；架构校核 **全-空** | 架构完整性校核 + 质量 gate registry | 🔴 大 |
| **跨项目一致** | 四系统各自为政 | 母 schema 跨项目落地 | 🔴 大 |

## 4. 问题的清晰定义

**核心问题（一句）**：治理资产**存在但散、无统一 schema 传导、无架构校核** → 框架≠机制（L0_01）→ 执行完整性无保障、验收无法锚定终态标准。

**分解为可逐个解的子问题**：
- **P1** 无治理总 schema（结构层根缺）
- **P2** spec 不分层、不全（语义层缺骨架 + 缺 5 件 + L0/L2 空）
- **P3** 无 gate registry + 无架构校核（双重校核缺）
- **P4** 改源不自动传导（一致性缺）
- **P5** 跨四系统不一致

## 5. 解决措施（对问题给方向，非执行细节）

- **P1 →** 立**治理母 schema**（三位一体宪法：定义什么算 spec/schema/code-sop-skill + 三者怎么咬合 + 分层/分主题/分类别的轴 + 双重校核入口）
- **P2 →** 定 spec **分层/分主题/分类别骨架** + 补关键缺件（S11 gate registry 优先）
- **P3 →** 建 **gate registry**（统管 18 审计）+ **架构完整性校核**脚本
- **P4 →** 扩**改源传导**机制（仿 gen_root_claude_md）到全治理资产
- **P5 →** 母 schema **跨项目落地**（IE 当 pilot → 推 EE/vault/数据中台）

## 6. 执行方案（分阶段 + 每阶段验证节点对照标准）

| Phase | 解决 | 产出 | Mark 验证节点（对照标准，非流程） |
|---|---|---|---|
| **0 立宪** | P1 | 治理母 schema 形态（pilot=前端） | 三位一体咬合 + 分层分主题分类别轴 + 双重校核入口，对得上你要的根吗 |
| **1 立 spec 骨架** | P2 | spec 分层/主题/类别骨架 + S11 gate registry | 骨架覆盖全不全、registry 统住 18 审计没 |
