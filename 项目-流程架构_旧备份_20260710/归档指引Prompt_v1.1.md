## 一、三条核心规则

**规则1：三层结构，不新建子文件夹**
云端知识库最多三层（根目录/业务层/文件），不允许在现有文件夹内再新建子文件夹。用文件名前缀代替子文件夹分类。

**规则2：文件名格式**
```
[分类前缀]_[内容描述]_[版本或日期（如有）].[扩展名]#[关系说明]
```
- 分类前缀：见第三章各职能速查表
- 关系说明：写在文件名最末尾`#`后，说明这个文件与已有文件的关系
- `#`关系说明举例：`#新增`、`#替换V1`、`#更新补充20260508`

**规则3：旧版文件归档不删除**
有新版本时，旧版移入`02/_归档/`，加`[来源维度]_归档_`前缀，不直接删除。

| 情况 | 文件名末尾写法 |
|------|-------------|
| 全新文件，之前不存在 | `#新增` |
| 替换某个旧版本 | `#替换V1`或`#替换旧版` |
| 在已有文件基础上补充 | `#更新补充` |
| 归档旧版，保留参考 | `#归档` |
| 临时过程产物 | `#过程文件` |

## 八、每日协同工作机制

### 8.1 机制总览

```
小组成员本地AI工作产出文件
        ↓
按本文档规范命名并归档到云端02层
        ↓
Syncthing自动同步到服务器
        ↓
watcher.py实时监听，记录变更到CHANGELOG.md
        ↓
每日09:30 自动推送日报到企业微信群
内容：昨日09:30至今日09:00的全部变更
      含文件路径、关系说明、内容摘要
        ↓
        ├──→ 小组成员：了解全组昨日进展，信息同频
        │
        └──→ Mark：将日报及相关文件喂给AI评估
                        ↓
                Mark AI输出评估与指示文档
                        ↓
                Mark上传指示文档到云端
                存放：01/M-88_mark日常输出/
                命名：日常持续更新_Mark指示_YYYYMMDD.md#新增
                        ↓
                次日09:30日报包含指示文档更新通知
                小组成员收到后执行指示
```

---

### 8.2 小组成员每日工作流

```
Step 1：早上09:30收到日报
        → 了解昨日全组变更
        → 查看是否有Mark指示文档更新

Step 2：读取Mark最新指示文档（如有）
        → 路径：01/M-88_mark日常输出/
        → 文件名前缀：日常持续更新_Mark指示_

Step 3：执行本日工作
        → 用AI工具产出文件
        → 按归档指引命名（含前缀和#关系说明）
        → 放入云端对应位置

Step 4：完成后无需额外操作
        → watcher.py自动记录变更
        → 次日日报自动推送给全组和Mark
```

---

### 8.3 Mark每日工作流

```
Step 1：早上09:30收到日报
        → 日报含：变更文件清单+每个文件摘要

Step 2：将日报内容喂给AI工具
        → AI可根据文件路径访问云端完整文件
        → AI输出评估意见、待决策项、任务待办

Step 3：Mark确认AI输出内容后
        → 上传指示文档到云端
        → 路径：01/M-88_mark日常输出/
        → 命名：日常持续更新_Mark指示_YYYYMMDD.md#新增

Step 4：小组成员次日收到通知后执行
```

---

### 8.4 文件晋升流程

文件从02层（过程产出）晋升到03/04/05层（正式交付）的标准流程：

```
触发条件：
Mark通过线下会议或指示文档明确确认某文件可晋升

执行方式：
小组成员将文件从02层移动到对应正式层
02层原文件移入02/_归档/加归档前缀

晋升目标层对照：
· 最终权威CSV数据 → 03/权威数据/
· Mark审核通过的标准MD → 03/治理规范/
· 正式Skill脚本 → 04/Skill库/
· 正式生产脚本 → 06/Scripts库/生产脚本/
```

**晋升操作命名规则：**

| 操作 | 文件名处理 |
|------|----------|
| 晋升到03层 | 去掉原有前缀，按03层命名规范重命名 |
| 原02层文件归档 | 移入02/_归档/，加`[维度]_归档_`前缀 |

### 8.5 CHANGELOG.md说明

CHANGELOG.md存放在云端根目录，由watcher.py自动维护，记录所有文件变更历史。

- 全组成员可随时查阅完整变更历史
- 日报内容超出企业微信字数限制时，完整内容见CHANGELOG.md
- 不需要手动编辑，由系统自动写入
