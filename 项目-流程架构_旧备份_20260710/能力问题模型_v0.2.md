# 能力问题模型 v0.2 — 本体的能力边界/分类/分层/分级（投影自 EA价值链 + EE诊断 baseline）

> 起草: 协调角色 2026-06-13 / 状态: 待 Mark 阅
> 缘起: Mark 两次纠正——①能力问题不能我即兴编，本体核心是先确定能力的边界/分类/分层/分级，这本身要有模型；②候选关系不能只从我概括的价值链草图来，要读全 EA 价值库。本文件即"能力问题模型"，四维**全部投影自既有 baseline，零自创**；关系推导改挂在本模型之下。
> 事实底座: ① EA 知识库价值链（共享文件夹_EA项目，正式建模）② EE 诊断维度库。每条带出处。

## 0. 一句话原则（修正版）

**能力问题不是设计的，是从已建好的价值链里"收割"的。** EA 价值库已经把能力做了正式建模——价值流/L1/L3/L4/价值节点 + S2B2A 分层 + Gate 分级 + 节点边界。能力问题模型 = 把这套既有结构投影成"本体必须能回答的问题集"，再由问题反推关系。我（协调角色）只做投影与对齐，不新造能力。

## 1. 四维 baseline（全部来自 EA/EE，标注出处）

### 1.1 分类（Classification）= 双轴，都是现成的

**轴 A — 利益相关者 / 价值流**（出处: `03_发布成果/权威数据/价值流_价值阶段_价值活动_全量表_V3.csv`）。这条轴**直接就是实体类型轴**：

| 价值流 | 利益相关者(=实体类型) | S2B2A 层 |
|---|---|---|
| VS-1 保司资源投放旅程 | 保险公司 | S 上游 |
| VS-2 机构合作伙伴旅程 | TOB 机构 | B 层 |
| VS-3 KA 上架旅程 | KA / TOA | B/A 交界 |
| VS-4 理财师发展旅程 | 理财师 / 代理人 | A 层 |
| VS-5 权益服务企业客户旅程 | 企业级客户 | B 层(服务采购方) |

**轴 B — 能力域 / L1**（出处: `L1_L3映射表_最终版.csv`），5 个能力域，每个下挂一批 L3 流程：
L1-01 资源获取与产品整合 · L1-02 市场设计与合作伙伴发展 · L1-03 运营反馈与路由决策 · L1-04 能力赋能与增长驱动 · L1-05 价值增值与生态绑定。

> 与 EE 对照: EE 的三柱(channel/financial/strategic)+15 子簇是同一业务的**诊断视角**切法；EA 的 5 价值流×5 L1 是**价值创造视角**切法。两者不冲突，EA 更适合做本体骨架(它是按"谁的旅程+创造什么价值"分的)，EE 子簇适合做诊断挂点。

### 1.2 分层（Layering）= EA 已有七级 + S2B2A，不自创

价值流 VS → 价值阶段 S → 价值活动 → L1 价值链 → L3 流程 → L4 交付物 → 价值节点 VN（物理资产）。叠加纵向 S2B2A（S上游=保司 / B=机构·KA·企业客户 / A=理财师·代理人 / C=终端客户）。
**边界铁律(出处: 价值节点清单V4.0 §1.1, Mark 拍板)**: "L3 属全公司，L4 属部门；严禁部门切碎 L3"——这是分层的硬约束，本体层级声明须遵此。

### 1.3 分级（Grading）= 不是"高中低"，是多套既有判据

- **价值节点三 Gate**（出处: 价值节点清单 §1.2）: Gate①挂数(≥1量化KPI) / Gate②落地(机器可读物理产物) / Gate③追溯(100%回溯L3+原始输入)。状态 pass / partial / fail。
- **优先级**: P0 / P1 / P0熔断（如 VN-PAY-04 转介费台账三 Gate 全 fail = 熔断）。
- **L3 成熟度跟踪**（出处: `流程库状态监控表_L3成熟度跟踪_V2.1.xlsx`）。
- **EE 独立维度诊断**（出处: sf_055 8 维 / mp_088 12 维）: 每维 GO/AMBER/NO-GO，**任一 NO-GO 不触发整体 NO-GO**（catalog 模式，非 AND 一票否决）。
> 关键: EE 与 EA 都拒绝"高中低成熟度"，统一用"独立维度 + Gate 判据"。能力问题模型的分级层直接采用，不另设等级。

### 1.4 边界（Boundary）= 四硬属性 + 多道既有门

- **价值节点 4 硬属性**（出处: §1.2）: ①业务定位(锚定≥1个 M0-M8) ②价值属性(可表述商业价值) ③物理对应(实体存在·机器可读) ④数据验证(真实数据跑通)。一个"能力"成立须四属性齐全——这是能力边界的硬定义。
- **EE KMR 8 步**（mp_158）/ **机制-实例分离**（principle_055）/ **业财法三角分离** / **持牌↔佣金 vs 转介↔服务费 100% 对应**（bp_206）/ **IA 硬指标**(非持牌占比≤50%、同行支付≤88%，出处 VN-PAY-04)。

## 2. 能力问题 = 从价值节点 Gate + 价值流阶段"收割"（示例带出处）

机制: 每个价值节点的三 Gate 本身就是一组能力问题；每个价值流阶段的"应做动作"反过来就是"是否具备该能力"的问题。逐条收割，不编：

| 能力问题（收割自） | 来源 | 对应能力域 |
|---|---|---|
| 这个价值节点有≥1个可提取的量化 KPI 吗？ | Gate① | 全域通用门 |
| 它有机器可读的物理产出物吗？ | Gate② | 全域通用门 |
| 它能 100% 回溯到 L3 + 原始输入吗？ | Gate③ | 全域通用门 |
| 佣金口径准确率/回收周期达标吗？ | VN-PAY-01 KPI#15/16 | L1-03 运营 |
| 应派计算能追溯到对账产出物吗？ | VN-PAY-03 Gate③ | L1-03 运营 |
| 转介费派发满足 IA 非持牌≤50%/同行≤88% 吗？ | VN-PAY-04 IA硬指标 | L1-03 + 合规边界 |
| 保司授权与合规前置审查到位吗？ | VS-1 阶段 S2 | L1-02 市场设计 |
| 机构合作伙伴尽调与资质审核通过吗？ | VS-2 阶段 S2 | L1-02 |
| 理财师首单陪跑五个动作完成吗？ | L3-FOR | L1-03/04 |

> 这张表是机制的演示，不是全集。**全集 = 对 5 价值流全部阶段 + 全部价值节点 Gate 做一遍收割**（见 §4 下一步）。这样每条能力问题都有 VN/L3/VS 出处，无一是我编的。

## 3. 关系如何从价值库落（方法已定，先给样本）

实体类型 = §1.1 轴 A 的 5 类利益相关者（+ 终端客户 C + 既有注册表的 牌照/项目/机构等）。**关系从两处落，都在价值库里**：

1. **价值流的阶段动作** = "实体 A 对实体 B 做了什么"。例: VS-1 保司→MGA 的全生命周期(评估→授权→资源整合→上架→数据回流→续约) = 一组 保司↔MGA 关系。
2. **价值节点的数据流** = 产出物在实体间流转。例: VN-PAY 链(出处 价值节点清单 §三/§八)给出佣金价值流——

   `保司 —源头佣金PDF→ MGA(中台制作市场佣金表) —应派清单→ 理财师/销售员`；`MGA —转介费→ 转介渠道`(受 IA 50%/88% 硬约束)。

这比我上一版从"价值链草图"拍的候选夯实得多——每条关系挂着一个具体价值节点 + Gate + KPI。
