# 共识触发规则 v0.1
> 版本：v0.1 | 日期：2026-06-09
> 适用：Kimi Code判断是否需要发起共识请求

## 触发条件（五选一即触发，无需全部满足）

### 条件1：新域
**定义**：任务涉及的业务域在历史任务包中从未出现过
**判断方法**：检索02_指挥执行指令/已完成/，无同类任务包 → 触发
**示例**：KA线第一个任务（历史上无KA线任务包）→ 触发

### 条件2：P0规则影响
**定义**：任务执行结果可能导致现有P0级别规则需要修改
**判断方法**：若任务产出与F2中任何P0规则存在潜在矛盾 → 触发
**示例**：发现某任务需要绕过R2授权规则才能执行 → 触发

### 条件3：跨岗双视角
**定义**：任务结论同时涉及业务判断和技术判断，单一视角不足以覆盖
**判断方法**：任务包中出现"业务规则正确性"AND"技术可行性"双重判断需求 → 触发
**示例**：规则提取任务同时需要判断"业务逻辑对不对"和"数据库能不能存" → 触发

### 条件4：高失败率
**定义**：同类任务在历史记录中失败率超过30%
**判断方法**：检索F3教训库，同类任务教训条目≥2条 → 触发
**示例**：Kimi跨域引用错误出现2次(LE-K-001/LE-K-002) → 同类任务触发

### 条件5：规范升级
**定义**：发现现有F2协作规范存在结构性缺陷（不是个案，是系统性问题）
**判断方法**：同一问题在≥2个任务中重复出现，且现有规范无法覆盖 → 触发
**示例**：出现LE-C-004类问题（同类错误重复）→ 触发规范升级讨论

## 不触发共识的情况

以下情况**不**触发共识，Kimi Code可自主规划：
- 有历史同类任务包可参考
- 任务边界清晰，风险低
- 教训库中无相关失败记录
- 仅是参数/内容变化，流程完全相同

## 共识超时规则

- Kimi Code发起共识请求后，Claude Code须在**同一工作日**回复
- 超时未回复 → Kimi Code标注"超时未回复"→ 升级Jasper裁定
- 紧急任务（Jasper标注P0）→ Claude Code须在**2小时内**回复

## Jasper紧急覆盖权

在任何情况下，Jasper可声明"紧急覆盖"：
- 直接向任意终端下指令，不经过共识流程
- 不需要事先通知Kimi Code或Claude Code
- 紧急覆盖后须在decision_log补记原因
- 紧急覆盖不影响该任务后续的正常流程
