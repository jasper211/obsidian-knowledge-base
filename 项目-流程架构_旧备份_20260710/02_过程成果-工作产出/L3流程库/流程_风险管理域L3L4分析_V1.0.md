## 一、分析说明

### 1.1 风险管理域的范围界定

本文档覆盖**以风险识别、合规监控、内控治理为核心目标**的 L3 流程，分三类：

| 类型 | 定义 | 包含 L3 |
|------|------|---------|
| **A 类：治理/风控/合规主导** | 管理层、合规部或风控为 A 责任人 | L3-RCM / L3-DAM / L3-ISM / L3-ARC（共 4 条） |
| **B 类：业务/职能主导、合规深度参与** | 业务或职能部门为 A，合规/风控承担 R 或关键 C | L3-FOB / L3-BMD / L3-IAC / L3-COM / L3-KASC / L3-MSI（共 6 条） |
| **C 类：已合并，不再独立** | 原独立 L3 已并入其他流程 | L3-UCR → L3-BMD；L3-SRE → L3-MSI（共 2 条，已归档） |

> **内部控制（内控）的特殊处理**：内控不独立为风险管理域 L3，而是以**控制点（KN）**形式横切嵌入各业务 L3（如 L3-PAY 的 L4-PAY-02 审核、L3-COM 的 KN4 合规验证），通过 EA 流程管理机制（mechanism_004 控制点识别 + mechanism_005 走查）统一治理。

### 1.2 关键边界说明

| 模块 | 归属说明 |
|------|---------|
| IA 监管合规申报（FRR） | 归财务域 L3-FRC，合规部为 C |
| 合同管理 | 按合同类型归属各业务域 L3，不独立为风险 L3 |
| 用印管理 | 归行政/经代，风险部门不主责 |
| 财务内控操作风险 | 作为控制点嵌入财务 L3（L3-PAY / L3-MCC 等） |

## 三、A 类 L3 的 L4 拆解

### 3.1 L3-RCM 风险管理与合规监控

**归属**：经代 / VS-2 S3（体系搭建阶段）/ L1-04 能力赋能与增长驱动
**触发**：周期性合规检查周期到达 / 业务异常预警触发 / 监管机构问询
**终点**：合规检查报告定稿 + 整改事项闭环
**覆盖对象**：经代机构合规行为监控（外部对手方合规）

| L4 编号 | L4 名称 | 物理交付物 | 主责(A) | 当前状态 |
|---------|---------|-----------|---------|---------|
| L4-RCM-01 | 合规风险评估 | 经代机构合规风险评估报告 | 合规部 | 不存在（原 L3-UCR 合并后内容未落地） |
| L4-RCM-02 | 日常合规监控与预警 | 合规异常预警记录 | 合规部 | 不存在 |
| L4-RCM-03 | 合规检查执行 | 合规检查底稿 + 证据包 | 合规部 | 不存在 |
| L4-RCM-04 | 整改跟踪与闭环 | 整改完成确认单 | 合规部 + 经代业务 | 不存在 |
| L4-RCM-05 | 合规风险台账维护 | 风险台账（持续更新） | 合规部 | 不存在 |

**主要风险/缺口**：整条 L3 框架为空壳，5 个 L4 全部不存在。原 L3-UCR（合规风险评估）并入 L3-BMD 后，该部分能力实际上也未在 RCM 中落地。

**与财务域的接口**：
- L3-RCM 发现经代机构异常交易 → 触发财务核查（L3-MCC L4-MCC-03 应收应付核对）
- L3-RCM 合规会议 → 与 L3-FRC L4-FRC-04 合规会议共享议题

### 3.2 L3-DAM 分级授权矩阵管理 ★新增

**触发**：组织架构调整 / 年度审查周期 / 发生授权越权或模糊事件
**终点**：管理层签发的分级授权矩阵正式版本下发
**当前状态**：完全不存在；财务域 L3-PAY 已将"权限矩阵不透明"记录为核心缺口
**覆盖范围**：付款审批（金额分级）、合同签署（金额/类型分级）、业务决策（战略级/执行级）、人事授权

| L4 编号 | L4 名称 | 物理交付物 | 主责(A) | 当前状态 |
|---------|---------|-----------|---------|---------|
| L4-DAM-01 | 授权场景梳理与矩阵起草 | 分级授权矩阵草案 | 财务 + 合规（联合起草） | 不存在 |
| L4-DAM-02 | 管理层审批与正式发布 | 管理层签发的授权矩阵（正式版） | 管理层(A) | 不存在 |
| L4-DAM-03 | 授权变更申请与审批 | 授权变更确认单 | 管理层 / CFO | 不存在 |
| L4-DAM-04 | 定期回顾与版本更新 | 更新版授权矩阵 + 变更说明 | 管理层(A) | 不存在 |

**主要风险/缺口**：付款授权依赖隐性惯例，没有书面化的权限边界；一旦人员变动或越权付款发生，无制度依据可追溯。

**与其他 L3 的接口**：
- L3-DAM L4-DAM-02 授权矩阵 → **前置输入** L3-PAY L4-PAY-03 管理层授权（当前该节点无明确权限依据）
- L3-DAM L4-DAM-02 授权矩阵 → **前置输入** L3-COM KN4 合规验证中的佣金封顶审批权限
- L3-DAM L4-DAM-03 变更审批 → 触发 L3-ISM L4-ISM-01 系统权限同步更新

## 七、内控的横切处理方式

内控不独立为风险管理 L3，以**控制点（KN）**形式嵌入各流程：

| 内控动作 | 嵌入位置 | 控制点类型 |
|---------|---------|----------|
| 重复报销拦截 | L3-PAY L4-PAY-02 财务审核 | 前置门控 |

| 欠款追收 | L3-MCC L4-MCC-03 应收应付核对 | 周期触发 |
| 佣金封顶合规 | L3-COM KN4 合规验证 | 前置门控 |
| 联合运营资质核查 | L3-BMD L4-BMD-02 | 前置门控 |
| 理财师入职合规 | L3-FOB L4-FOB-01~03 | 前置门控 |

**治理机制**：控制点的完整性由 EA 流程管理统一治理（mechanism_004 控制点识别 → mechanism_005 走查验证 → mechanism_006 冲突裁定）。
