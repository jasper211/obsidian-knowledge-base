## EP-047 保司Tier分级标准

### 1. 规则目的

将Mark脑中对各保司的差异化对待方式（"永明是战略级、某某是跑量级"）固化为可量化的Tier分级规则，实现：
- **资源差异化**: 不同Tier的保司获得不同级别的服务、资源投入和管理关注度
- **自动分级**: Agent根据数据自动计算Tier评分，减少主观判断
- **动态调整**: Tier不是终身制，定期重新评估

### 2. Tier分级体系

#### 2.1 分级定义

| Tier | 名称 | 一句话定义 | 预计数量 | Mark裁定 |
|------|------|-----------|---------|---------|
| **T1** | 战略保司 | 公司核心战略伙伴，高层直接对接，全资源投入 | ___家 | ☐ |
| **T2** | 重点保司 | 主力业务贡献方，标准化深度合作 | ___家 | ☐ |
| **T3** | 成长保司 | 有潜力但合作尚浅，需要培育 | ___家 | ☐ |
| **T4** | 基础保司 | 维持性合作，低投入标准化运营 | ___家 | ☐ |

> **Mark待决策**:
> - Q1: 以上4级是否合适？是否需要增减层级？
> - Q2: 每个Tier大概多少家保司？（确认金字塔结构合理性）

#### 2.2 Tier评估维度与权重

> **评估方式**: 对每家保司按以下维度打分（1-10分），加权计算总分，划定Tier区间。

| 维度 | 权重 | 评分标准 | 数据来源 | Mark裁定权重 |

| **业务贡献** | ___% | 年度保费规模 + 佣金利润贡献 | FACT_POLICY + Agg1 | ☐ |
| **战略价值** | ___% | 品牌背书力 + 产品独特性 + 市场卡位价值 | Mark主观评分 | ☐ |

| **增长潜力** | ___% | 过去12个月增长率 + 市场空间 | Agg3 + 行业数据 | ☐ |
| **合作意愿** | ___% | 高层互动频次 + 响应速度 + 独家/优先待遇 | BD反馈 + CRM | ☐ |

## EP-062 授权分阶段获取路径

### 1. 规则目的

将MGA向保司获取授权的路径从"随机谈判"变为"分阶段、有策略的推进"，实现：
- **路径可视**: 每家保司当前处于哪个授权阶段、下一步目标是什么，一目了然
- **策略匹配**: 不同Tier的保司用不同的授权获取策略
- **进度可追踪**: Agent自动监控授权获取进度，滞后时预警

### 2. 三类核心授权定义

| 授权类型 | 代码 | 含义 | 战略价值 | 获取难度 | Mark裁定 |
|---------|------|------|---------|---------|---------|
| **分销授权** | AUTH-D | 代理销售保司产品的基础授权 | 基础 — 没有它无法开展业务 | ___（低/中/高） | ☐ |
| **创新授权** | AUTH-I | 与保司联合开发定制产品的授权 | 高 — 差异化竞争力来源 | ___（低/中/高） | ☐ |
| **渠道管理授权** | AUTH-C | 管理保司在特定渠道分销的全权委托 | 最高 — MGA核心定位 | ___（低/中/高） | ☐ |

> **Mark待决策**:
> - Q8: 三类授权的获取难度排序是否为 AUTH-D < AUTH-I < AUTH-C？
> - Q9: 是否还有其他类型的授权需要纳入？

### 3. 授权获取阶段路径

```
阶段0         阶段1            阶段2           阶段3          阶段4
无授权 ───→ 基础分销 ───→ 扩展分销 ───→ 创新授权 ───→ 渠道管理
 (N)        (AUTH-D)      (AUTH-D+)     (AUTH-I)      (AUTH-C)
            │                                          │
            └─── 最小可行合作 ─────────────────── MGA终极形态 ──┘
```

#### 3.1 各阶段详情

##### 阶段0 → 阶段1：获取基础分销授权（AUTH-D）

| 项目 | 内容 |
|------|------|
| **前置条件** | 保司已通过L3-KAET评估定级，合作可行性确认 |
| **关键动作** | ① 签署基础合作框架协议 ② 完成保司合规审查（KYC） ③ 系统对接（产品数据+佣金结算） |
| **预期周期** | T1保司: ___周 / T2保司: ___周 / T3保司: ___周 |
| **成功标准** | 至少1个产品SKU上架并完成首单 |
| **决策人** | BD负责人 + A族确认 |
| **关联L3流程** | L3-KAEC → L3-KAET → L3-KASC（合同签署）→ L3-KAOP（上架准备） |

##### 阶段1 → 阶段2：扩展分销授权（AUTH-D+）

| 项目 | 内容 |
|------|------|
| **前置条件** | 基础分销运营满___个月 + 达到保费阈值___万 + 合规记录清白 |
| **关键动作** | ① 扩展产品线（多SKU上架） ② 争取更优佣金条件 ③ 获得更多渠道权限 |
| **预期周期** | ___个月 |
| **成功标准** | 产品SKU≥___个 + 月保费稳定在___万以上 |
| **决策人** | A族 |

##### 阶段2 → 阶段3：获取创新授权（AUTH-I）

| 项目 | 内容 |
|------|------|
| **前置条件** | 分销合作满___年 + 年保费>___万 + 保司有联合开发意愿 |
| **关键动作** | ① 提出联合产品概念 ② 保司精算/产品团队对接 ③ 签署产品联合开发协议 ④ 完成首款定制产品上线 |
| **预期周期** | ___个月 |
| **成功标准** | 至少1款联合定制产品上线销售 |
| **决策人** | Mark参与（战略对齐）+ A族执行 |
| **风险** | 保司精算审批慢 / 监管产品备案不确定性 |

##### 阶段3 → 阶段4：获取渠道管理授权（AUTH-C）

| 项目 | 内容 |
|------|------|
| **前置条件** | 创新合作验证成功 + 年保费>___万 + 保司高层信任（Mark级关系） |
| **关键动作** | ① Mark与保司高层战略对齐 ② 签署渠道管理委托协议 ③ 建立联合管理委员会 ④ 团队+系统全面对接 |
| **预期周期** | ___个月（最长，需高层深度信任） |
| **成功标准** | 签署渠道管理委托协议 + 联合管理委员会运作 |
| **决策人** | Mark（必须亲自参与） |

> **Mark待决策**:
> - Q10: 各阶段的前置条件（保费阈值、时间要求）具体数字？
> - Q11: 阶段是否必须顺序推进？能否跳级？（如T1保司直接从阶段0跳到阶段3）
> - Q12: 当前各保司分别处于哪个阶段？（会上快速标注）

### 4. 授权获取策略 × Tier矩阵

| Tier | 授权获取策略 | 目标阶段 | 推进节奏 | Mark介入点 |
|------|------------|---------|---------|-----------|
| **T1** | 全速推进 — 目标AUTH-C | 阶段4（渠道管理） | 激进，多阶段并行 | 全程深度参与 |
| **T2** | 稳步深化 — 目标AUTH-I | 阶段3（创新授权） | 稳健，按阶段推进 | 阶段3时介入 |
| **T3** | 先站稳脚跟 — 目标AUTH-D+ | 阶段2（扩展分销） | 保守，验证后再推 | 不介入 |
| **T4** | 维持现状 — AUTH-D即可 | 阶段1（基础分销） | 被动维护 | 不介入 |

### 5. 授权进度监控规则

| 监控项 | 触发条件 | Agent动作 |
|--------|---------|----------|
| **阶段停滞** | 某保司在当前阶段滞留超___个月 | 推送预警至A族+BD |

| **降级风险** | 保费连续下滑 或 合规事件 | 推送风险警告至Mark |

## EP-063 合同谈判让步边界

### 1. 规则目的

将Mark多年合同谈判中形成的"底线感"固化为分层的让步规则，实现：
- **BD赋能**: 一线谈判人员清楚知道哪些可以让、让到什么程度、找谁审批
- **风控前置**: 不可让的底线被系统性保护，不会因个案被突破
- **决策提速**: 绿区条款BD可当场拍板，不需要层层上报

### 2. 合同条款分区体系

> **核心框架**: 借鉴L3-KASC协同框架中的"绿/黄/红"三区分级，扩展为完整的让步边界规则。
