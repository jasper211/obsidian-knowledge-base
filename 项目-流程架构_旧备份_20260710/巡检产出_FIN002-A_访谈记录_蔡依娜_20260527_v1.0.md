## P0-001：蔡依娜SPOF——应派核心字段手填无复核
**关联价值节点**：VN-PAY-03 · 应派清单三件套
**问题组来源**：工具包A 问题组1
**访谈时间戳**：00:00–04:40

### 访谈回答摘要
蔡依娜说明，协议主体与打款主体在业务开展前期即通过沟通与合作模式确定，并记录在由商务负责维护的"人员关系表"中。同行直接与牌照签约，转介公司由内部公司（如海豚）代为处理转介费。FACT_SETTLEMENT_REFERRAL中的协议主体和打款主体信息来源于该人员关系表，数据来源相对统一且有固定规则。蔡依娜自己维护结算大表，存放在WPS共享文件夹中，每期单独立文件夹记录当期数据。蔡依娜表示目前没有因信息录入错误而导致打错款的历史情况，如果协议主体填写错误，财务后续环节可能会发现。

## P0-005：续保账单状态14种取值的状态转换规则未定义
**关联价值节点**：VN-PAY-03 · 应派清单三件套
**问题组来源**：工具包A 问题组3
**访谈时间戳**：13:30–19:30

### 访谈回答摘要
蔡依娜说明，续保派单依据实收表和佣金表来决定。hold住意味着暂时不派，后续会再次确认对方状态。如果合作伙伴对应的佣金表产品本身没有续保佣金则不派。已转户保单会向对接人询问是否需要继续派发，根据对方回复操作。德约多层分润结构方面，26年前的规则是计算机构佣金率、理财师佣金率和德约总部佣金，但现行续保分佣已调整为由德约总部直接计算并分配给理财师和机构，具体分配比例由德约总部与理财师沟通确定。14种状态的完整枚举及状态之间的转换路径在转录中未完整覆盖。

### 提取到的规则
- 如果收到实收表且佣金表上设置续保佣金，则正常派发续保佣金
- 如果合作伙伴对应的佣金表产品本身无续保佣金，则不派（标记为"不派"）

- 如果续保涉及德约业务，则德约应派=实收×德约率，再由德约总部拆分为理财师应派+机构剩余（具体分配比例由德约总部与理财师沟通确定）

## P1-001：协议主体为空但签约主体BASIC/OR有值时字段关系
**关联价值节点**：VN-PAY-03 · 应派清单三件套
**问题组来源**：工具包A 问题组4
**访谈时间戳**：19:30–23:40

### 访谈回答摘要
蔡依娜说明，协议主体与打款主体由于费用结构的变化，从25年起不再是一一对应关系。25年之前签约主体中BASIC费用签约方为SERES，OR费用签约方为转介公司。当前OR被拆分为权益费用和商务引介费两部分，这两部分的打款主体不同。例如转介协议主体是海豚，打款主体是seres。协议主体指签订转介协议的主体，打款主体指实际执行转账的主体，两者需根据具体合作方签订的协议类型来确定。

### 提取到的规则
- 如果OR费用结构已从单一拆分为权益费+商务引介费两笔，则协议主体和打款主体不再一一对应，需按各自费用类型确定打款主体
- 如果协议主体（如海豚）与打款主体（如seres）不一致，则以实际签订的协议类型来确定对应的打款主体
- 如果签约主体BASIC有值（如SERES），则该笔费用对应的打款主体为SERES
- 如果签约主体OR有值（如转介公司），则需看该OR具体拆分成的费用类型（权益费/商务引介费），分别对应不同的打款主体

### 数据锚点
- FACT_SETTLEMENT_REFERRAL.协议主体 — 口述确认（指签订转介协议的主体）
- FACT_SETTLEMENT_REFERRAL.签约主体BASIC — 口述确认（BASIC费用签约方，如SERES）
- FACT_SETTLEMENT_REFERRAL.签约主体OR — 口述确认（已拆分为权益费用+商务引介费，分别对应不同打款主体）

### 外化状态
- [x] 口头经验（持有人：蔡依娜、商务）
- [x] 完全未记录（费用拆分后协议主体与签约主体的字段关系无书面文档）

### 仍有Gap

## P1-003：权益激励hold解除后的派发动作是手工还是自动
**关联价值节点**：VN-PAY-03 / VN-PAY-05 · 应派清单三件套 / 增值服务台账
**问题组来源**：工具包A 问题组5
**访谈时间戳**：23:40–26:59

### 访谈回答摘要
蔡依娜说明，权益激励解除后的派款动作是基于服务价值判断的。如果服务价值不足以全额发放，则只能派发一部分，下一期结算时再找权益部门获取更新的服务价值。权益部门会根据服务价值通过公式自动计算剩余可派发金额，并通过邮件通知蔡依娜。整个过程并非系统自动触发，而是由权益部门手工更新服务价值后通知蔡依娜，蔡依娜再据此执行派发。

### 提取到的规则
- 如果权益激励被hold且服务价值不足，则按当期可用服务价值上限折算可派发金额，剩余留待下期
- 如果服务价值更新（权益部门每半月更新一次），则权益部门通过公式计算可派发金额并通过邮件通知蔡依娜
- 如果收到权益部门的可派发金额通知，则由蔡依娜手工执行解除hold并派发
- 如果服务价值不足以全额发放，则按档位上限分配激励金，剩余可分配金额由公式自动计算

### 数据锚点
- DIM_EQUITY_RULE.累积使用服务价值 — 口述确认（权益部门每半月更新，通过邮件通知蔡依娜）
- FACT_EQUITY_HOLD_STATUS.hold动作 — 口述确认（蔡依娜手工操作解hold，触发依据为权益部门邮件通知）
- FACT_EQUITY_HOLD_STATUS.操作人 — 口述确认（操作人为蔡依娜）

### 外化状态
- [x] 口头经验（持有人：蔡依娜、权益部门）
- [x] 完全未记录（解hold触发流程无代码化，依赖邮件手工衔接）

### 仍有Gap
- [x] 是（说明：①解hold后"已派发激励"和"剩余待派"字段由谁更新、如何更新在转录中未明确；②服务价值更新后系统是否自动重算激励TOTAL未确认；③权益部门计算可派发金额的公式参数未提及）

### 回填建议
**已回填·明确**

## P1-004：DIM_PAYEE_MAPPING除已知约定外还有哪些业务约定

**问题组来源**：工具包A 问题组6
**访谈时间戳**：23:40–26:59

### 访谈回答摘要
蔡依娜确认，V1宽表转V3长表时，同一个人在不同阶段出现的资金需要合并成一笔支付，默认按人名合并。已知特殊约定：吴竞的钱归到白博文名下；宁波贴牌的转费由欣村商务公司统一收取。蔡依娜表示除此之外"没有特殊规定"。新增成员的收款规则由原有规则决定，如有变更会通过邮件通知，变更规则需按规定条件和生效时间执行。新加入成员的收款规则由商务确定，如发生变更则由商务通知。
