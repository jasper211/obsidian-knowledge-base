# 业务查询工具箱 — 结构分析与应用场景

> 日期: 2026-04-17 | 基于 mga_platform 39张表分析

---

## 1. 数据层次与查询路径

数据库里有**三层可查询的费率数据**，从底层到业务层：

```
Layer 1 (底层): fact_commission_rate  12,505行
├── 维度: carrier × tier × product × 缴费期 × 年龄 × 折扣码
├── 特点: 最细粒度，不含伙伴名
├── 查法: 需要 JOIN partner_tier_rules 才能关联到伙伴
└── 适合: 内部审计、规则验证

Layer 2 (宽表): agg_source_commission_wide  2,741行
├── 维度: carrier × license × tier × product (Y1-Y10展开)
├── 特点: 首年到第10年费率平铺，按 tier 查
├── 查法: 知道 tier_code 直接查
└── 适合: 费率表制作、tier对比

Layer 3 (业务层): agg_market_commission_tier_rate  6,804行  ← 业务团队首选
├── 维度: 伙伴 × 保司 × 产品 × 制表类型 (中文列名！)
├── 特点: 已经关联好伙伴名称、保司名称、产品中文名
├── 查法: 直接按伙伴或产品查，无需任何 JOIN
└── 适合: 日常业务查询、对外报价
```

**结论**: 业务团队的查询工具应该优先基于 Layer 3 `agg_market_commission_tier_rate` 构建，因为：
- 中文列名，业务人员看得懂
- 23 个伙伴已预关联，不需要 SQL JOIN
- 覆盖 14 种制表类型（B2B/C2B/银行/券商/天领/ICLUB等）
- 10年期佣金展开，一目了然

## 3. 五大业务场景 × 推荐查询模板

### 场景 A: "这个伙伴卖这个产品，佣金多少？"

**谁在问**: BD团队、伙伴经理、运营
**频率**: 每天多次
**数据源**: `agg_market_commission_tier_rate` (直查，无需JOIN)

```sql
-- 输入: 伙伴编码 + 保司 (可选)
SELECT
    合作伙伴名称,
    保险公司,
    产品名称,
    缴费期,
    fyc档位          AS 首年层级,
    fyc              AS 首年佣金率,
    总佣金_y1        AS Y1佣金,
    总佣金_y2        AS Y2佣金,
    总佣金_y3        AS Y3佣金,
    佣金模式,
    客户类型,
    递交截止日期
FROM agg_market_commission_tier_rate
WHERE 合作伙伴编码 = {{partner_code}}
ORDER BY 保险公司, 产品品类, 缴费期
```

**优化点**: 比原来的 3 表 JOIN 版本简单 10 倍，而且返回结果更丰富（含佣金模式、截止日期等）。

### 场景 B: "同一产品，不同渠道/伙伴的费率差多少？"

**谁在问**: Teresa、战略团队
**频率**: 每周/季度
**数据源**: `agg_market_commission_tier_rate`

```sql
-- 输入: 产品SKU
SELECT
    合作伙伴名称,
    合作伙伴分类     AS 渠道类型,
    制表类型,
    fyc档位          AS 层级,
    缴费期,
    fyc              AS 首年佣金率,
    总佣金_y1        AS Y1,
    总佣金_y2        AS Y2,
    总佣金_y3        AS Y3
FROM agg_market_commission_tier_rate
WHERE 产品sku = {{product_sku}}
ORDER BY fyc DESC
```

**价值**: 一眼看出同一产品在 MGA、B2B、银行、券商等不同渠道的费率差异，支撑定价决策。

### 场景 C: "这个伙伴的基本信息和合作状态？"

**谁在问**: BD团队、运营、合规
**频率**: 每天
**数据源**: `dim_partner` + `bridge_partner_ka` + `dim_ka`

```sql
-- 输入: 伙伴代码或名称关键词
SELECT
    p.partner_code    AS 伙伴代码,
    p.partner_name    AS 公司名称,
    p.partner_category AS 类型,
    p.partner_status  AS 状态,
    p.payment_cycle   AS 付款周期,
    p.first_contract_date AS 首签日期,
    p.contract_expiry_date AS 合同到期,
    k.ka_name         AS 所属KA,
    k.ka_tier         AS KA层级,
    k.market_segment_code AS 市场细分
FROM dim_partner p
LEFT JOIN bridge_partner_ka b ON p.partner_code = b.partner_code AND b.is_current = true
LEFT JOIN dim_ka k ON b.ka_id = k.ka_id
WHERE p.partner_code ILIKE ('%' || {{keyword}} || '%')
   OR p.partner_name ILIKE ('%' || {{keyword}} || '%')
ORDER BY p.partner_name
```

### 场景 D: "某保司有哪些产品？各类别分布？"

**谁在问**: 产品团队、BD团队
**频率**: 每周
**数据源**: `dim_product_sku` + `dim_product_id`

```sql
-- 输入: 保司代码
SELECT
    s.product_category  AS 产品类别,
    s.business_line     AS 业务线,
    s.product_sku       AS 产品SKU,
    s.chinese_standard_name AS 产品名,
    COUNT(DISTINCT i.product_id) AS 产品ID数,
    s.clawback_period_months AS 回扣期_月,
    s.cooling_off_days  AS 冷静期_天,
    CASE WHEN s.is_premium_financing THEN '是' ELSE '否' END AS 支持保费融资
FROM dim_product_sku s
LEFT JOIN dim_product_id i ON s.product_sku = i.product_sku
WHERE s.carrier_code = {{carrier_code}}
GROUP BY s.product_category, s.business_line, s.product_sku,
         s.chinese_standard_name, s.clawback_period_months,
         s.cooling_off_days, s.is_premium_financing
ORDER BY s.product_category, s.product_sku
```

### 场景 E: "某制表类型下所有伙伴的费率汇总"

**谁在问**: 财务、运营主管
**频率**: 每季度出表
**数据源**: `agg_market_commission_tier_rate`

```sql
-- 输入: 制表类型 (如 "同行经代（B2B）", "ICLUB", "SLC天领业务")
SELECT
    合作伙伴编码,
    合作伙伴名称,
    产品品类,
    COUNT(DISTINCT 产品sku)         AS 产品数,
    ROUND(AVG(fyc::numeric), 4)     AS 平均首年佣金率,
    ROUND(MAX(fyc::numeric), 4)     AS 最高首年佣金率,
    ROUND(MIN(fyc::numeric), 4)     AS 最低首年佣金率
FROM agg_market_commission_tier_rate
WHERE 制表类型 = {{table_type}}
GROUP BY 合作伙伴编码, 合作伙伴名称, 产品品类
ORDER BY 合作伙伴编码, 产品品类
```

## 4. 当前模板的问题与优化方向

### 现有模板 (v1)

| # | 模板 | 问题 |
|---|------|------|
| 1 | 伙伴佣金费率查询 | 基于 3 表 JOIN (partner_tier_rules + fact_commission_rate + dim_partner)，查询复杂且只覆盖 tier_rules 里的 44 个伙伴条件 |
| 2 | 伙伴搜索 | 只查 dim_partner 基本信息，缺少 KA 关联和合同状态 |
| 3 | 保司产品清单 | 只查 dim_product_sku，缺少产品 ID 数量和融资支持等关键字段 |

### 核心优化

| 优化项 | 说明 |
|--------|------|
| **数据源切换** | 佣金查询从 3 表 JOIN → 直接查 `agg_market_commission_tier_rate`，简单且数据更准确 |
| **新增场景** | 增加"产品费率对比"和"制表类型汇总"两个高频场景 |
| **信息增强** | 伙伴搜索增加 KA 归属、合同到期日；产品清单增加回扣期、冷静期 |
| **中文友好** | agg_market 表本身就是中文列名，业务人员直接看结果不需要翻译 |
