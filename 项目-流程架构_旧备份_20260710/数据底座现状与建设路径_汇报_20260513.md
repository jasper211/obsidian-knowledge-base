# 企业流程架构 × 数据底座现状与建设路径
> 汇报日期：2026-05-13
> 汇报对象：Mark
> 准备人：Jasper（赵琦）
> 数据来源：EA数据底座（400条L4/82个L3）× 数据字典（46张表/731字段）

---

## 一、核心结论（一页纸）

| 结论 | 数字 | 含义 |
|------|------|------|
| **数据底座覆盖率** | **11%** | 400条流程活动中，只有44条有直接对应的数据产出表 |
| **数据应用覆盖率** | **72%** | 400条流程活动中，有288条可以读取到相关数据 |
| **数据字典精准匹配** | **41/46张** | 现有46张数据表中，41张已精准定位到对应的流程活动 |
| **数字化建设缺口** | **161条L4** | 理论上可数字化（Auto/Aug）但尚未建立产出数据表 |
| **线下活动** | **81条L4** | 完全无数据支撑，是长期数字化转型的目标范围 |

**一句话结论**：当前数据建设覆盖了核心交易结算链路，但流程架构的绝大多数经营活动尚无数据底座，数字化建设仍处于早期阶段。

## 二、现状盘点

### 2.1 数据字典与流程架构的匹配全景

当前数据字典共46张表、731个字段，覆盖以下域：

| 所属域 | 表数 | 代表表 |
|--------|------|--------|
| 产品与供应域 | 12张 | DIM_PRODUCT_SKU / fact_insurance_plan_header |
| 费率确认域 | 9张 | FACT_COMMISSION_RATE / CONFIG_PRODUCT_COMMISSION_FORMULA |
| 核心交易域 | 7张 | FACT_POLICY / AGG_SALES_BASE |
| 策略叠加域 | 6张 | CONFIG_STRATEGY_TIERS / BRIDGE_STRATEGY_ROUTING |
| 商业伙伴域 | 4张 | DIM_PARTNER / DIM_KA |
| 财务结算域 | 3张 | DIM_PAYEE / MAP_PARTNER_PAYEE |
| 其他域 | 5张 | 基础设施/目标管理/系统管理 |

**46张表中有41张精准匹配到对应L4，5张为全平台基础设施表（时间维/编码字典/ETL审计），不归属任何单一流程活动。**

### 2.2 从流程架构视角看数据覆盖

以400条L4（流程活动）为基准，数据覆盖情况如下：

```
400条L4
├─ 有产出数据表（有专属表）：44条（11.0%）
│   → 该流程活动直接产出/写入数据表，是数字化的真实底座
│
├─ 有关联数据表（有关联表）：244条（61.0%）
│   → 该流程活动能读取相关数据，但不直接产出结构化记录
│
├─ 无数据表（线下/协同）：81条（20.2%）
│   → 活动以线下文档/邮件/协同系统承载，尚未数字化
│
└─ 无数据表（外部系统）：31条（7.8%）
    → 数据存在于HR/合规/LMS/服务商等外部系统，未纳入当前数据字典
```

### 2.3 数据建设集中在哪些流程

当前有产出数据表的44条L4，主要集中在：

| 流程域 | 代表L4 | 数据表 |
|--------|--------|--------|
| 佣金管理 | 佣金政策接收、差异化拆解、整合外发 | FACT_COMMISSION_RATE / AGG_MARKET_COMMISSION_TIER_RATE |
| 产品上架 | 产品元数据录入、服务上架 | DIM_PRODUCT_SKU / MAPPING_PRODUCT |
| 权益配置 | 权益包配置、规则迭代 | CONFIG_STRATEGY_TIERS / BRIDGE_STRATEGY_ROUTING |
| KA管理 | KA线索管理、协议签订 | DIM_KA / DIM_BINDER_AGREEMENT |
| 合作伙伴 | 合作资格预审、赋能成本分摊 | DIM_PARTNER / CONFIG_LICENSE_COST_DEDUCTION |
| 计划书 | 方案移交、目标设置 | fact_insurance_plan_header / fact_insurance_plan_lines |

**特征**：当前数据建设偏向「交易结算结果」和「配置参数管理」，对「过程执行」和「销售行为」的数据记录严重不足。

## 三、关键缺口分析

### 3.1 数字化建设的核心缺口：161条Auto/Aug L4无产出数据表

按Agent化程度分类，400条L4的数字化潜力如下：

| Agent化程度 | L4数 | 占比 | 已有产出数据表 | 缺口 |
|------------|------|------|--------------|------|
| Auto（可完全自动化） | 77条 | 19.3% | 部分已有 | 高优先建设 |
| Aug（AI辅助人工） | 108条 | 27.0% | 部分已有 | 高优先建设 |
| Hybrid（人机协同） | 176条 | 44.0% | 少量已有 | 中优先建设 |
| Human（纯人工） | 39条 | 9.8% | 极少 | 长期方向 |

**Auto+Aug共185条L4，是数字化投入产出比最高的区域，但其中161条（87%）尚无产出数据表，是数据建设的核心缺口。**

### 3.2 价值流维度的数据密度分布

| 价值流 | 已有精准匹配数据表 | 数据密度评级 | 主要缺失 |
|--------|----------------|------------|---------|
| VS-1 经代销售与招募 | 5张 | 低 | 销售行为/线索转化/活动记录 |
| VS-2 客户转化与维护 | 6张 | 低 | 服务记录/客户互动/续约数据 |
| VS-3 佣金与结算 | 3张（核心表） | 中 | 税务处理/争议记录 |
| VS-4 产品引入与运营 | 1张 | 极低 | 产品生命周期/上下架记录 |
| VS-5 合作伙伴与保司 | 6张 | 低 | 合作评估/服务质量/权益兑现 |
| 内部管理（非VS） | 11张 | 中 | KPI追踪/目标管理 |

**VS-4产品引入与运营的数据覆盖最为薄弱，仅1张精准匹配表，与其在业务中的重要性严重不匹配。**

### 3.3 当前无法回答的关键问题

## 四、下一阶段工作方向

### 4.1 当前分析的局限性

本阶段采用的是**反向映射**逻辑：

```
已有数据表 → 业务定义 → 核心交付物 → 匹配L4
```

这个逻辑的天花板是「已有数据表」，只能描述**现状**，无法回答「应该有什么」。

### 4.2 下一阶段：正向推导（提前量分析）

建议启动**正向推导**逻辑：

```
L4核心交付物
    ↓ 结合L5经营活动步骤
应产生哪些数据字段？
    ↓ 对照已有46张表的731个字段
① 已有字段（已建）
② 缺失字段（应建未建）
③ 部分字段（已有但不完整）
    ↓ 业务方确认字段来源
哪个L5活动产生这个字段？
在哪个系统录入？
是否需要新建表或扩展字段？
```

**这个分析的产出将直接回答：400条L4理论上应该建立多少张数据表、多少个字段，从而明确数据建设的完整路线图。**
