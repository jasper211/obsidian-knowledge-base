# Mark任务协同规则
> **版本**：v0.5 | **更新日期**：2026-06-03
> **前序版本**：v0.4（2026-05-28）
> **适用范围**：服务器双数据库环境下，以Boss_DB为任务源、以Partner_DB为执行场的、由运营中台主导的协同项目
> **适用角色**：运营中台全体成员（Terresa/Carrie/袁林/Jasper等）及其各自使用的AI助手
> **与F2关系**：本文件是F2（AI协作规范_多终端_v0.5）的上游规范，F2在Phase D阶段开始激活
> **归档路径**：Partner_DB/08_任务与跟进/AI上下文/Mark任务协同规则_v0.5.md
> **归档类型**：团队协同规则类 → 团队第二大脑（R9规则）

## 一、文档定位

### 1.1 这份文件解决什么问题

在服务器双数据库环境下，任务从**Boss_DB**获取，在**Partner_DB**执行，结果回传供Mark的AI读取。运营中台多位成员（使用不同AI工具）参与此流程，涉及跨数据库路径映射、权限隔离、异步反馈、多成员协同等问题。

本文件覆盖从**监控任务更新通知 → 读取任务MD → 分析评估 → 规划执行 → 回执归档**的完整可复用协同路径。

### 1.2 与现有规范的关系

```
本文件（Mark任务协同规则 v0.5）
  ↓ Phase D阶段开始调用
F2（AI协作规范_多终端_v0.5）
  ↓ 执行层任务包下发
OpenCode / Qoder / 各成员AI助手 执行
```

| 规范文件 | 解决什么 | 激活时机 |
|---|---|---|
| 本文件 | 双数据库环境下团队如何将任务变成可执行任务 | 收到服务器更新通知时 |
| F2 AI协作规范v0.5 | 任务包如何设计和下发给执行终端 | Phase D规划阶段 |
| F3 教训库 | 历史教训防止重蹈覆辙 | Phase B前置分析时参考 |

### 1.3 角色定义

**任务负责人**：Mark在任务MD中指定的运营中台成员。
- 默认一人承担：任务认领 + 执行 + 回执
- 涉及多人协作时：任务负责人自行分配子任务，但对Mark的回执统一由任务负责人提交
- 使用自己的AI助手完成分析、规划、执行

**授权裁定方**：Mark
- 通过Boss_DB下发任务MD
- 解阻塞/裁定/验收回执
- 不直接参与执行层

**安全规则**：
- 任何终端**只读**Boss_DB，禁止向Boss_DB写入、修改、删除文件
- 所有产出、回执、日报必须存放在Partner_DB的指定路径下

## 二、双数据库目录树

### 2.1 Boss_DB（Mark侧）

```
EA项目_jasper/（或Mark的项目根目录）
└── 08_任务与跟进/
    ├── 任务状态/        ← Mark的任务规划与进度跟进
    │                     Mark用来确认运营中台是否按他的节奏推进
    │                     Mark的AI在此读取并评估任务整体进度
    ├── 收件箱/          ← 接收运营中台的非任务反馈
    │                     Mark在此回复，命名区别于任务回执
    ├── 项目规划/        ← Mark对任务的规划视角
    ├── AI上下文/        ← Mark自用的AI上下文文件
    └── Mark决策会议/    ← 会议记录与决策存档
```

### 2.2 Partner_DB（运营中台侧）

```
流程架构项目_jasper/（或运营中台项目根目录）
└── 08_任务与跟进/
    ├── 任务状态/        ← 各成员汇报MD + 任务回执
    │                     Mark的AI来此读取回执，了解执行进展
    │                     文件命名和框架见第三节
    ├── 项目规划/        ← 任务书/CP追踪/任务本身质量评估
    │                     任务执行质量的自评在此，不提交Boss_DB
    └── AI上下文/        ← 各成员自用方法论/F文件/SKILL等
                           按使用人独立管理，不混用
```

**实际产出文件**存放于各自域的子目录（如`02_过程成果/规则分析/`），不放在08层。汇报MD中标明产出文件的完整路径，Mark的AI按路径自行读取。

### 2.3 文件流向

```
Mark在Boss_DB/任务状态/或项目规划/下发任务MD
    ↓ 企业微信群收到服务器更新通知
任务负责人读取任务MD，带入AI助手执行
    ↓ 执行完成
任务回执MD → Partner_DB/08_任务与跟进/任务状态/
    ↓ Mark的AI读取回执
非任务反馈 → Boss_DB/收件箱/
    ↓ Mark在收件箱内回复
Mark收件箱回复 → Boss_DB/收件箱/（同目录，命名区分）
```

## 四、完整协同闭环（六阶段）

```
企业微信群收到服务器更新通知
    ↓ 任务负责人读取Boss_DB任务MD
[Phase A] 任务获取与解读
    ↓
[Phase B] 前置分析
    ↓
[Phase C] 可执行性评估（三档判定）
    ↓
[Phase D] 规划与任务包 ← 调用F2 R1-R9
    ↓
[Phase E] 执行与质检
    ↓
[Phase F] 回执归档与闭环判定
    ↓
  ┌────────────────────────────┐
  │ 闭环：监控新任务通知        │  Boss_DB无新反馈
  │ 继续：基于反馈再执行        │  Boss_DB回执区收到问题反馈
  │ 关闭：新任务触发            │  Boss_DB出现新任务MD
  └────────────────────────────┘
```

---

### Phase A · 任务获取与解读

**触发条件**：企业微信群收到服务器更新通知，任务负责人在Boss_DB指定路径读取新任务MD。

**动作主体**：任务负责人（读取文件并带入AI助手）+ AI助手（结构化解读）

**AI助手执行动作**：

读取Boss_DB任务MD全文，输出结构化解读摘要：

```
【任务解读摘要】
任务名称：[简短命名]
任务负责人：[Mark在MD中指定的人]
任务来源：Boss_DB / 路径：[任务MD完整绝对路径]
核心要求：[一句话]
涉及范围：[L3/流程/文件/人员，注明位于哪个数据库]
明确截止：[有/无]
隐含期望：[AI助手识别到的未明说意图，标注「AI判断」]
初步复杂度：简单 / 中等 / 复杂
数据库映射：输入来自Boss_DB，产出存放Partner_DB
```

**卡点**：解读摘要需任务负责人确认"理解正确"后进入Phase B。

---

### Phase B · 前置分析

**触发条件**：Phase A解读摘要经任务负责人确认

**动作主体**：AI助手（分析）+ 任务负责人（裁定阻塞项）

**AI助手执行动作**：

1. **依赖链梳理**（按数据库归类）：
   - Boss_DB依赖：参考文件是否已可读取？
   - Partner_DB依赖：是否依赖其他成员的产出？
   - 外部依赖：是否需要其他线输入？

2. **阻塞项识别**：编号为QX，关注跨数据库访问和跨成员协作的潜在阻塞

3. **参考F3教训库**

4. **跨数据库路径强制声明**（每次必须）：

```
【跨数据库路径声明】
输入源（Boss_DB，只读）：
  - 任务MD：[完整绝对路径]
  - 参考文件：[完整绝对路径]
工作区（Partner_DB，读写）：
  - 产出目录：[完整绝对路径]
安全规则：禁止任何终端向Boss_DB写入、修改、删除文件
```

**卡点**：有阻塞问题时，必须先推动相关方确认，不得强行进入Phase C。

---

### Phase C · 可执行性评估

**触发条件**：Phase B前置分析完成

**动作主体**：AI助手（评估）+ 任务负责人（裁定）

**三档判定**：

| 档位 | 条件 | 后续动作 |
|---|---|---|
| ✅ 可直接执行 | 无阻塞，双数据库路径清晰 | 进入Phase D |
| 🟡 部分可执行 | 有阻塞但可拆分 | 无阻塞部分进Phase D，阻塞部分挂起 |
| 🔴 不可执行 | 核心阻塞未解除 | 整理Q清单通知相关方，挂起等待 |

---

### Phase D · 规划与任务包

**触发条件**：Phase C结论为✅或🟡

**动作主体**：AI助手（规划+出包）+ 任务负责人（确认+授权）

**调用F2规范**：全面激活F2 R1-R9

**任务包必须包含路径与权限声明**：

```
【路径与权限声明】
输入源（Boss_DB，只读）：
  - [完整绝对路径] （用途：[说明]）
工作区（Partner_DB，读写）：
  - 产出目录：[完整绝对路径]
安全规则：
  - 禁止向Boss_DB写入、修改、删除文件
  - 所有产出必须存放在Partner_DB指定路径下
```

---

### Phase E · 执行与质检

**触发条件**：任务负责人授权，执行终端启动

**执行终端义务**：
- 严格按任务包执行
- 完成后逐项对照Done Criteria自检
- 回传时注明「已自检，结论：[通过/X项不符]」

**AI助手初审义务**：
- 全量检查，不抽查
- 必须检查路径合规性（产出是否写入了Partner_DB正确位置）
- 初审结论格式：

```
【AI助手初审结论】
Done Criteria逐项核验：□通过 □部分通过 □不通过
路径合规检查：□通过 □发现问题（描述）
建议处置：修订重做 / 可提交验收
```

**任务负责人验收**：拥有最终验收权。

---

### Phase F · 回执归档与闭环判定

**触发条件**：任务负责人完成验收

**动作主体**：任务负责人（整理+归档）+ AI助手（协助起草）

**执行动作**：
1. 按第三节框架结构产出回执MD
2. 存入Partner_DB/08_任务与跟进/任务状态/
3. Mark的AI读取回执，了解执行进展

**闭环判定**：

```
回执MD归档至Partner_DB/任务状态/
    │
    ├─ Boss_DB无新反馈
    │   → 台账标注「完成-等待新任务」
    │
    ├─ Boss_DB出现针对本任务的问题反馈
    │   → 重新进入Phase A，开启新轮次
    │
    └─ Boss_DB出现新任务MD
        → 旧任务标注「已关闭-新任务触发」
```
