## 0. 为什么先画 VS-1 局部而不是全图

**M2 经验**: 组织架构是一次容易触发架构级修正的节点 (M2 时有 3 次架构级修正,都在设计细节时被 Mark 一句话点破)。

**先画 VS-1 局部 的好处**:
1. **可验证性**: VS-1 的 A/B 两族是 M3.2 已完成的 2 个 JD,骨架最稳定,适合画出来验证
2. **风险隔离**: 如果架构设计出问题,只需返工 VS-1,不影响其他 5 族
3. **快速验证**: 你看一张图就能判断"对不对",不需要看完整 6 族才能评价
4. **迭代空间**: VS-1 对了,C~G 可以复用同一结构哲学;VS-1 错了,及早纠正

**不画全图的原因**:
- C~G 5 族 JD 还没做,强行画会又一次陷入"数据不足做预测"的陷阱
- 全图的复杂度会掩盖 VS-1 本身的设计问题

## 2. 4 个备选结构

### 结构 1 — 纯行政线 (传统金字塔)

```
                    Mark (CEO)
                        │
                        │ (唯一汇报)
                        ▼
                  A 族 保司交付 (1)
                        │
        ┌───────┬───────┼───────┬───────┐
        ▼       ▼       ▼       ▼       ▼
      B-01     B-02    B-03    B-04    B-05
    (永明+   (战略2~3) (常规3)  (常规3)  (新开发)
     深度2)
```

**组织哲学**: 一人一主管,清晰汇报,最简单

**优点**:
- ✅ 汇报线清晰,权责明确
- ✅ Mark 减负最大化 (只对接 1 人)
- ✅ 管理成本最低
- ✅ 符合传统管理学范式

**缺点**:
- ❌ **战略级保司关系可能降温** — Mark 不直接接触永明,关系可能走形
- ❌ **关系级危机响应慢** — 保司决策层变动 (EP-093) 需要 Mark 亲自,但信息要经 A 族中转
- ❌ 与 M2 裁定 "战略级保司差异化" 不一致

**与 V0.2 减负清单的兼容度**: ⚠️ 部分冲突 — V0.2 保留的 EP-055/093/094/096 都需要 Mark 直接参与战略级保司,纯行政线阻碍这一点

---

### 结构 2 — 战略双线 (JD V0 里推荐的)

```
                       Mark (CEO)
                      ╱          ╲
                     ╱            ╲ (战略直连)
                    ╱              ╲
              A 族 保司交付         B-01
              (1, 归口)          永明+深度2
                    │            (双线)
                    │
        ┌───────────┼───────────┬───────┐
        ▼           ▼           ▼       ▼
      B-02         B-03        B-04    B-05
    (战略2~3)     (常规3)      (常规3)  (新开发)
```

**组织哲学**: 战略关系 CEO 亲自保留,日常运营归口管理,权责有限分离

**B-01 的双线**:
- **行政线** (日常/考核/培训) → A 族保司交付
- **战略线** (Phase 3 升级/关系变动/年度战略 review) → Mark

**优点**:
- ✅ 兼顾 Mark 减负 (日常由 A 管) 和战略级关系 (永明直连 Mark)
- ✅ 与 M2 裁定 "战略级保司差异化" 一致
- ✅ 与 V0.2 保留的 8 条战略级保留项兼容 (EP-055/093/094/096)
- ✅ B-01 有 Mark 背书,在永明面前更有话语权

**缺点**:
- ⚠️ **双线汇报可能模糊责权** — B-01 接到 A 族和 Mark 不同指令时怎么办?
- ⚠️ **B-01 有绕过 A 族的风险** — 日常问题也跑去找 Mark
- ⚠️ 组织治理复杂度略高

**双线的边界规则** (必须在 JD 里写清):
- **必须走 A 族**: 规则执行/日常合同/OKR 汇报/考核/培训
- **可以走 Mark**: 战略级决策 (Phase 3/重大让步/关系升级)/关系变动危机
- **Mark 拒绝权**: Mark 可以随时把"B-01 找我"的事拍回 A 族

**与 V0.2 减负清单的兼容度**: ✅ 高

### 结构 3 — 人机混合 (M4 前瞻)

```
                    Mark (CEO)
                        │
                        ▼
                  A 族 保司交付 (1)
                        │
        ┌───────┬───────┼────────┬───────┐
        ▼       ▼       ▼        ▼       ▼
      B-01    B-02~05            Agent 运维节点
                                 (虚拟, 0.5 FTE)
                                 │
                       ┌─────────┼─────────┐
                       ▼         ▼         ▼
                    保司情报   竞品监控   Pipeline
                      agent    agent     agent
```

**组织哲学**: Agent 是组织正式成员,与肉身并列

**新增节点**: Agent 运维岗 (0.5 FTE 或虚拟) — 负责维护保司相关 agent

**优点**:
- 🔮 为 M4 提前预留接口,体现"肉身+agent"形态
- 🔮 Agent 责任人明确 (不是"大家一起管")
- 🔮 符合 M3 北极星 "M4 组织接口"

**缺点**:
- ❌ **M3 阶段 agent 还没建**,这个节点是"空的",有务虚嫌疑
- ❌ 0.5 FTE 岗位在当前组织文化可能不容易建立
- ❌ 过于超前,M3 组织变革已经很多

**适合时机**: M4 启动后的结构,M3 提前预留接口但不实体化

### 结构 4 — 战略双线 + Agent 节点 (推荐)

```
                       Mark (CEO)
                      ╱          ╲
                     ╱            ╲ (战略直连)
                    ╱              ╲
              A 族 保司交付         B-01
              (1, 归口)          永明+深度2
                    │            (双线)
                    │
        ┌───────────┼───────────┬───────┬───────┐
        ▼           ▼           ▼       ▼       ▼
      B-02         B-03        B-04    B-05   [M4预留]
    (战略2~3)     (常规3)      (常规3)  (开发)  Agent运维节点
                                              (虚拟)
                                                 │
                                      ┌──────────┼──────────┐
                                      ▼          ▼          ▼
                                    保司情报    竞品监控   Pipeline
                                      agent     agent      agent
```

**组织哲学**: 结构 2 + 为 M4 预留 Agent 节点 (虚拟或实体可选)

**M3 阶段 Agent 节点的处理**:
- **选项 a**: M3 阶段**预留接口不建**,在图上画出但不任命人
- **选项 b**: M3 阶段**找现有 IT/数据人员**兼任 0.2~0.5 FTE
- **选项 c**: M4 启动时再建实体岗位

**优点**:
- ✅ 继承结构 2 的战略双线优势
- ✅ 同时体现 M3→M4 的过渡设计
- ✅ 符合北极星最严格的 "M4 组织接口" 要求
- ✅ 不增加 M3 阶段的实体编制压力 (虚拟预留)

**缺点**:
- ⚠️ 组织图稍复杂 (但符合真实业务形态)
- ⚠️ Agent 节点 M3 阶段是"理论存在",可能让现有团队觉得"画饼"

## 4. 我的推荐: **结构 4** (战略双线 + Agent 预留节点)

**一句话理由**: 结构 4 同时满足 M3 的实操需求 (减负+战略级保护) 和 M3 北极星的前瞻要求 (M4 组织接口)。

**具体推荐细节**:
- **M3 阶段**: 实体化 A 族 (1人) + B 族 (3~5人) + **Agent 节点用虚线预留** (不任命人)
- **M4 阶段**: Agent 节点转为实体 (0.5~1 FTE,可能是 IT/数据兼任)

**Agent 节点的 M3 形态**:
```
[M4 预留]
Agent 运维节点 (虚拟, 待 M4 实体化)
  ├─ 保司情报 agent (规划中)
  ├─ 竞品监控 agent (规划中)
  ├─ Pipeline agent (规划中)
  └─ 预警 agent (规划中)

现阶段责任人: 待定 (建议 M4 启动前由 Carrie/IT 临时兼任)
```

**与 V0.2 减负清单的协同**: B 族执行规则时,可以"指挥" Agent 做数据准备/竞品监控/预警,B 族只做关系决策,agent 做情报工作。这是 M4 "1:10~20 agent" 愿景在 VS-1 的第一个落地场景。

## 6. 架构图的 "边界" 与 "未说出的假设"

这里我想提醒几个本图**没有明说但隐含的假设**,如果你不同意,需要回退:

### 隐含假设 1: "保司交付" 是 VS-1 唯一归口人
- 含义: 所有保司相关的日常管理都经过 A 族一个人
- 风险: 如果 A 族那个人休假/离职,VS-1 业务会瘫痪 (单点失效)
- 应对: A 族需要**可备份机制** — B-02 可作为"代理 A 族",但这违反 Mark Q2 "只 1 正"

### 隐含假设 2: Mark 和 A 族之间没有中间层
- 含义: Mark 直接管 A 族,没有"VS-1 VP" 之类的角色
- 理由: 你目前的公司规模不需要这一层
- 风险: 未来公司扩张时可能需要

### 隐含假设 3: B 族内部没有层级
- 含义: 5 个 B 族成员是平级,没有"B 族组长"
- 理由: 人数少 (3~5),扁平化即可
- 风险: 如果 B 族扩张到 8~10 人可能需要组长

### 隐含假设 4: Mark 和 B-01 的战略线不需要写进 JD/合同
- 含义: "战略线" 是组织图上的线,但 B-01 的正式汇报是 A
- 风险: B-01 可能滥用战略线,A 族可能失去控制权
- 应对: JD 里明确写"战略线仅限 X/Y/Z 场景"
