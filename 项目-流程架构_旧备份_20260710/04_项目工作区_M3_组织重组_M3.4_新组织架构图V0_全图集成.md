## 2. 全图的结构说明 (分层解读)

### 第 0 层: CEO (1 人)
- **Mark**: 唯一战略决策者, 保留 11 条核心战略介入点 (V0.3)

### 第 1 层: 业务归口人 + 横切能力负责人 (4 人)
所有向 Mark 直接汇报的"L1 级" 岗位:
- **A 族 保司交付** (1 M3): VS-1 归口
- **C0 机构业务归口人** (1 M3): VS-2 归口
- **D-1 代理人事业部运营总监** (1 M3): VS-4 代理人事业部
- **D-2 永明事业部运营总监** (1 M3): VS-4 永明事业部
- **F 族 权益中台负责人** (1 M3): L1-05 横切能力

**额外战略直连** (不算正式汇报):
- **B-01 永明+深度合作**: 行政线向 A 族, 战略关系直连 Mark

**第 1 层合计**: 4 正式 + 1 双线 = 5 人 (M3 级)

### 第 2 层: 执行层 (10~13 人)
向第 1 层汇报的专业/执行岗位:
- **B-02~B-05**: 保司关系经理 4 人 (P5~P6)
- **C1 开发+交付经理** (1~2 P5~P6)
- **C2 运营+续约经理** (2~3 P5)
- **E 族 理财师辅导长** (2~3 P5~P6, KPI 防火墙向 D 汇报)
- **B-01** (已在 1 层但行政属 2 层, 1 P6)

**第 2 层合计**: 4 + 1~2 + 2~3 + 2~3 + 1 = **10~13 人**

### 第 3 层: 横切能力层 (M4 预留)
不直接承担业务,提供横切服务:
- **Agent 节点** (Carrie 挂名 0.2 FTE): 服务 3 条 VS 的 agent 治理
- **G 族 佣金合规** (0.5 FTE 兼职): 委员会成员

**第 3 层合计**: **0.7 FTE** (都是兼职/虚拟)

### 第 4 层: 职能层 (约 10~15 人)
不属于业务线的支撑职能:
- **HR 职能** (含 Ivan): 人力资源 + 行政
- **CFO 职能**: 财务 + 预算
- **合规部**: 法律+监管
- **法务**: 合同审查
- **其他**: IT/数据 (Carrie 主责)

**第 4 层合计**: **~10~15 人** (具体数字待 HR 数据核算)

## 4. 全图的 5 个创新符号 (集中展示)

M3 设计过程中创造了 5 种传统组织图里没有的符号:

### 符号 1: ╲╱ 战略双线 (B-01 永明)
```
         Mark
        ╱    ╲
       ╱      ╲ (战略直连)
      A 族   B-01 (双线)
```
**含义**: 战略关系由 CEO 亲自保留, 行政关系归业务归口人

### 符号 2: ╔═╗ 防火墙框 (E 族)
```
  D 族
   │
   ▼
 ╔═══════╗
 ║ E 族   ║  ← 虚线框
 ╚═══╤═══╝
     ▼
  Mark+Ivan+D 三方联签
```
**含义**: 考核权从汇报权中剥离, 防止功能漂移

### 符号 3: ↑↓ 双向考核箭头 (F 族 KPI 混合)
```
  Mark ↑↓ F 族 ↑↓ A/C0/D
  (60% 战略)  (40% 服务质量)
```
**含义**: 岗位同时向上向下被考核, 权重不同

### 符号 4: ┌─────┐ 虚拟委员会框 (G 族)
```
┌───────────────┐
│ 佣金争议裁定委员会 │
│ CFO + G + 业务 + 合规 + Ivan │
└───────────────┘
```
**含义**: 非个人岗位的治理节点, 只在事件发生时激活

### 符号 5: [M4 预留] 虚拟横切能力层
```
[M4 横切能力层 — Carrie 挂名]
├ Agent 节点 (虚拟)
└ G 族 (兼职)
```
**含义**: 未来实体化的横切层, M3 阶段是占位

## 7. 全图暴露的 3 个战略问题 (需 Mark 对焦)

画完全图后,有 3 个战略问题在之前局部图中没有完全暴露,必须在 M3 正式完成前对齐:

### 战略问题 1: B-01 双线是否导致组织不平衡

B-01 永明是 VS-1 的一个特殊岗位,它:
- 在图上与 A 族平级 (双线)
- 但实际等级是 P6 (比 A 族 M3 低)
- 但战略关系直通 Mark

**风险**: B-01 成为"非正式的第 6 个 M3",可能引起 A 族不满 (A 族是 M3 但 B-01 直接找 Mark)

**应对选项**:
- a) 提升 B-01 为 M3 (与 A 平级,但只管永明 1 家)
- b) 明确 B-01 的"双线"只在特定情境 (重大决策),不是日常
- c) 取消双线,B-01 完全归 A 族管

**推荐 b** — 权威感不来自等级,来自明确的场景边界。

### 战略问题 2: D-1 和 D-2 的合并可能性再讨论

M3.2 D+E 族 JD V0 时我们选了"D 族 2 人 (不合并)",但画到全图里看,D-1 和 D-2 都向 Mark 汇报,这是 **Mark 对接人数从 5 个变 6 个**,略增 Mark 负担。

**重新考虑选项**:
- a) 保持 D-1 + D-2 独立 (当前 JD V1 的决定)
- b) 合并为 1 位 D 族 (VS-4 统一总监),代价是两个事业部文化融合难
- c) D-1 / D-2 之上再加一层 "VS-4 总监" (但违反 "层级最少化" 原则)

**推荐 a** — 代价最小,Mark 对接 6 人仍然可行。

### 战略问题 3: 职能层 10~15 人的具体构成

全图里我写了 "HR/CFO/合规/法务/IT = 10~15 人",但这是估算。真实的职能层需要:
- HR: 几人? (Ivan 团队)
- CFO/财务: 几人?
- 合规+法务: 几人? (现有 8 合规 + 法务待定)
- IT/数据: 几人? (Carrie 团队)

**HR 模板回传后可精确化**。V0 暂以 12 人作为基准 (10~15 的中位)。
