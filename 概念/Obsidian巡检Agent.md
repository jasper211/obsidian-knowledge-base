# Obsidian 巡检 Agent

## 一句话定义
Obsidian 巡检 Agent 是**知识库基础设施能力线的设计入口**，目标是承担知识库状态巡检、调用准则和读取/写入治理边界校准；具体能力是否正在运行，必须按日期和运行证据分别判断。

## 核心属性
- **服务对象**: 全部 AI 工具 + 知识库
- **核心问题**: "各 AI 调用知识库/工具的准则一致吗？"
- **输入**: 各 AI 工具调用请求 + 知识库变更
- **设计输出**: 知识库状态、调用日志与一致性检查结果
- **设计触发**: 持续或定期巡检
- **2026-07-25快照**: 已有实际代码；OB巡检与每日提炼被源文档列为生产级自动化，其中每日提炼由已激活的定时任务执行
- **未实现边界**: 业务Agent产出实时写回vault仍无技术方案；PTA/VNW/AIT读取OB的调用侧仍为零接入
- **当前状态限制**: 本页未核当前代码、调度配置或日志，不能把2026-07-25快照延展成今天仍持续运行的证明

## 设计工作流位置
```
AI 工具调用 → Obsidian 巡检 Agent → 知识库状态检查 → 调用日志 → 一致性报告
```

该链路表示设计职责，不是端到端运行验收记录。

## 我的思考
- Obsidian 巡检 Agent 是**基础设施层**
- 不对应业务产出，是其他 4 个 Agent 的公共支撑
- 2026-07-25已有部分巡检与每日批处理能力，不应退回“完全未启动”的叙事
- 读取侧接入、业务产出实时写回和跨Agent文档维护仍需分别闭环
- 当前 `ob` heartbeat 是本vault的增量治理调度，不等同于源设计中的Obsidian巡检Agent已按原架构完整实现
