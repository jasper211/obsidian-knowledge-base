# 方法论转正 Agent

## 一句话定义
方法论转正 Agent 是**治理经验与行业自学习双线 Agent**，负责把各 Agent 的踩坑、验证、协作规则转成可复用方法，同时维护行业自学习线。

## 核心属性
- **服务对象**: 全部 Agent（含自己）
- **核心问题**: "这次踩的坑该怎么变成规则？"
- **输入**: 各 Agent 执行记录/踩坑记录
- **输出**: 更新后的 SOP/定义文档 + 验证标准清单
- **触发频率**: 每个 Agent 归档节点触发
- **当前定位**: 现行口径下应理解为 `经验治理与验证规则统一层`，不是一张还停留在“待启动”的新提案页

## 工作流位置
```
Agent 执行 → 踩坑记录 → 方法论转正 Agent → 更新 SOP → 验证标准清单
```

## 我的思考
- 方法论转正 Agent 是**验证独立**原则的实现
- 当前不能再简单理解为“未启动的新提案”
- 验证标准统一维护，不各自发明
- 方法论转正 Agent 是项目的重要交付物

## 当前口径说明
- 这页保留的是方法论转正 Agent 的职责定义，不再沿用“内部治理线未启动”作为主判断
- 当前 Jasper 经验层已经存在 `验证标准清单`、`双Agent协作契约` 与相关经验原子，因此它更适合作为现行治理层来理解
- 后续新增项目进入 OB 时，方法论转正 Agent 负责承接“哪些经验应转成规则、哪些规则应回写主库”的统一判断
