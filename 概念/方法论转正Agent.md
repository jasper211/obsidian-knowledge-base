# 方法论转正 Agent

## 一句话定义
方法论转正 Agent 是**治理经验与行业自学习双线设计**：内部治理线拟把各 Agent 的踩坑、验证和协作规则转成可复用方法，行业自学习线负责摄入外部材料并形成方法论知识产品。两条线的当前证据成熟度不同。

## 核心属性
- **服务对象**: 全部 Agent（含自己）
- **核心问题**: "这次踩的坑该怎么变成规则？"
- **输入**: 各 Agent 执行记录/踩坑记录
- **输出**: 更新后的 SOP/定义文档 + 验证标准清单
- **目标触发**: 每个 Agent 归档节点、验证新异常、AIT规则不稳定或累计踩坑达到阈值时触发
- **当前定位**: 行业自学习线有真实人工 ingest 产出；内部治理线有规则和知识资产，但未见 Agent 自动触发、执行日志或持续运行证据

## 工作流位置
```
Agent 执行 → 踩坑记录 → 方法论转正 Agent → 更新 SOP → 验证标准清单
```

该链路是目标治理流程，不是当前已经自动运行的事实描述。

## 我的思考
- 方法论转正 Agent 是**验证独立**原则的目标实现
- 不能把整套双线都归为“未启动”：行业自学习线在2026-07-23至2026-08-03留下11次 ingest 记录和对应知识产品
- 验证标准统一维护，不各自发明
- 内部治理线的文档资产存在，不等于治理 Agent 已自动执行

## 当前证据分层

- **行业自学习线已有真实产出**：`方法论知识库/行业学习/wiki/log.md`记录11次 ingest，形成源摘要、对比页和索引；日志描述的是逐次摄入成果，不能据此推定定时扫描或无人值守运行。
- **内部治理线仍缺运行闭环**：架构与触发规则已经写明，经验层也已有验证标准、协作契约和经验原子；本轮未见方法论转正 Agent 的调度配置、触发回执、执行日志或自动回写记录。
- **当前 OB 维护属于过渡期人工代管**：现有 `ob` heartbeat 在 Codex 回合中按状态板继续治理，不等于方法论转正 Agent 已部署，也不证明它已经接通各业务 Agent 的归档事件。

## 使用边界

- 可用这页理解双线职责、人工形成的行业知识产品和内部治理目标。
- 不可用这页证明方法论转正 Agent 当前自动运行、每次归档必然触发或 SOP 已被自动回写。
- 后续新增项目进入 OB 时，“哪些经验转成规则、哪些规则回写主库”仍由当前 OB 治理流程代管，直到出现可核验的 Agent 运行与交接证据。
