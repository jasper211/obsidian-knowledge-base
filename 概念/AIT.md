# AIT（AI 协同转型咨询 Agent）

## 一句话定义
AIT 是**AI 协同转型 Agent**，负责承接 VNW 已形成的 SOP 与规则成果，做三轨道拆解并推进 AI 化方案、Agent 化方案与人机边界设计。

## 核心属性
- **服务对象**: 协同部门 AI 转型
- **核心问题**: "这个部门怎么 AI 化？"
- **设计输入**: VNW事实快照、分析任务与负责人确认记录；必要时结合部门访谈和流程文档
- **设计输出**: 三轨道归属、AI化/Agent化方案、人机介入点与后续治理输入
- **已见实现**: AIT目录已有CLI和`track_router.py`，可读取VNW快照与决策记录，把任务分到机器规则、人的规则或待定，并为Aug/Hybrid标注固定/条件关卡
- **已见产物**: `L3-COM`有2026-07-28负责人决策记录及轨道分配JSON；这是单L3最小路由样例，不是Agent构建、SOP生成或生产执行证明
- **未实现/未核边界**: 当前代码未体现“协同新规则”第三轨道、Agent生成或方案执行闭环；本轮未见AIT README/执行记录，也未核测试、调度、日志或持续运行
- **当前定位**: `VNW 下游延伸段 + 跨项目咨询转译能力`，不是脱离主流水线独立运行的咨询岛

## 当前可证工作流
```
VNW模型快照 + 负责人决策 → 轨道判定 → L3轨道分配JSON
```

`AI方案 -> Agent设计 -> SOP/方法论流转`仍是后续设计目标，不能用轨道JSON替代完成证据。

## 我的思考
- AIT 是**战略价值最高**的主 Agent
- AIT 当前更应理解为 VNW 流水线的后段，而不是完全独立的咨询岛
- AIT 是 AI 协同转型咨询的核心工具
- AIT 需持续迭代和优化
- AIT 是 Jasper AI 协同经验引擎与 RW 权益项目的桥梁

## 当前口径说明
- AIT已不再是只有config和需求定义：至少已有可运行的轨道路由代码及L3-COM样例产物
- 当前更重要的是明确它在 Jasper 经验域里的位置：`承接上游规则成果，先形成可追溯轨道判断，再向具体项目输出 AI 化方案`
- 机器/人的规则两类已有最小路由，协同新规则轨道及后续构建执行链仍不能宣称完成
- 如果后续 P&L 或其他项目需要类似咨询转译能力，也应优先复用这套定位，而不是重新定义一类新 Agent
