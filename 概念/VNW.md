# VNW（价值节点驱动工作流 Agent）

## 一句话定义
VNW 是**价值节点驱动工作流 Agent**，负责把价值节点清单、流程蓝图和权威数据转成可追溯事实快照、Gate 判断、统一分析包与规则治理视图。

## 核心属性
- **服务对象**: 价值节点分析工作流
- **核心问题**: "这个域的规则空白是什么？"
- **输入**: 价值节点清单 + 流程蓝图
- **输出**: 信号基线 + 规则空白地图
- **工程基线**: VNW README标记v0.6.0、2026-07-30，已形成01-11工程结构、只读事实快照、Gate、统一分析包与React前端
- **更新机制快照**: 2026-08-03执行记录显示已建立源头更新检查/应用两步链，并安装每1800秒只读扫描的LaunchAgent；扫描只生成候选变化，不自动应用事实、调用模型或回写源头
- **运行限制**: 数据底座和前端仍需显式重跑同步/应用链；前端本地更新不等于线上发布，模型草稿与技术校验也不等于业务确认
- **当前核验**: 本页未检查今天的LaunchAgent、数据库连接、扫描日志、前端进程或测试结果，不能把截至2026-08-03的记录延展为持续运行证明

## 已实现的只读主链
```
权威数据/补充文件 → 可追溯事实快照 → Gate M/E/A → 分析包 → 本地前端
```

源头变化处理采用 `check -> 人工判断 -> apply`，不是监测到变化后自动改写正式事实。`--watch-dir`或定时源检查的存在也不等于语义盲区扫描已经实现。

## 我的思考
- VNW 是**业务价值最直接**的主 Agent
- VNW 与流程架构项目紧密关联
- VNW 是价值节点驱动工作流的核心执行者
- VNW 应按“只读闭环 + 前端展示 + Gate治理 + 半自动源更新检查”理解，而不是早期 config.json 草稿
