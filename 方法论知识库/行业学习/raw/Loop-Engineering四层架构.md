# Loop Engineering 循环工程：LangChain 官方博文深度拆解

## 核心观点总结

**大模型本身不是壁垒，Loop Engineering 循环工程才是真正拉开差距的关键。**

这套理论在 **2026 年 6 月正式被定义**，形成系统化理论。

---

## 为什么现在必须做 Loop Engineering？

### 大模型已成商品化

- 顶尖商用模型调用接口随处可得
- 最新开源模型权重易于获取
- **差异化竞争不在模型本身**

### 传统程序 vs AI 系统的根本差异

#### 传统程序（Deterministic）
- 运行逻辑固定不变
- 规则设定后永不出错
- 一次写好可长期稳定运行

#### AI 系统（Stochastic）
- 输出具备**随机性**
- 相同输入在不同时段返回不同内容
- 容易出现：
  - 信息编造（Hallucination）
  - 逻辑出错
  - 输出效果随使用时间逐步偏移

### Loop Engineering 的核心价值

**搭建自检机制**：系统发现输出有问题 → 自动重新调整重试

**将各类自检、重试的逻辑完整搭建、串联起来**，就是 Loop Engineering。

### 职能转变的体现

**Claude Code 负责人 Boris Cherny 的核心观点**：

> "I don't prompt Claude anymore. I have loops running that prompt Claude. My job is to write loops."
> 
> 翻译：开发者不用再手动反复给模型发指令，核心工作转为搭建可持续自主运行的循环流程。

---

## Loop Engineering 四层循环完整架构

### 第一层：智能体循环（Agent Loop）

**定位**：最底层、最基础的核心单元

#### 工作原理

```
用户需求 
  ↓
模型判断 → 调用哪些工具？
  ↓
执行工具操作
  ↓
重新调取模型处理结果
  ↓
循环直到模型不再需要调用工具 → 任务完成
```

**核心逻辑**：模型自主反复调用配套工具，一步步推进直到完成全部任务。

#### 实例：文档智能体

```
优化接口文档的需求
  ↓
Agent Loop 依次完成：
  1. 拉取代码仓库
  2. 读取现有文档
  3. 编写修改方案
  4. 提交 PR 申请
  ↓
完成任务
```

---

### 第二层：验证循环（Verification Loop）

**定位**：给智能体产出的内容加一道统一质检工序

#### 工作流程

```
完整智能体循环
  ↓
校验模块评分（对照预设标准）
  ↓
产出不达标？
  ├─ Yes → 反馈问题给模型 → 重新生成
  └─ No → 全部合格，终止流程
```

#### 校验模块的两类机制

##### 1. 固定规则校验（Deterministic）
- 自动检测链接能否正常访问
- CI 流程运行状态
- 代码书写格式等硬性标准
- **特点**：完全自动化，无歧义

##### 2. 大模型评审校验（LLM-based）
- 调用另一款大模型
- 搭配人为设定的评判标准
- 针对偏主观维度打分审核：
  - 内容完整度
  - 目标受众适配度
  - 专业性、清晰度等

#### 实例：文档智能体验证

生成文档 PR 后，校验模块自动检测：

1. ✅ 文档内所有超链接可正常打开
2. ✅ 代码 CI 流程无报错
3. ✅ 修改范围与原始需求完全匹配
4. ✅ 内容完整度达标
5. ✅ 目标受众适配度达标

**任意一项不通过** → 系统整理完整问题清单 → 推送回智能体重新调整

---

### 第三层：事件驱动循环（Event-driven Loop）

**定位**：从单次手动启动 → 全天候自动运行

#### 工作流程

```
外部业务事件触发
  ↓
自动调用验证循环 + 智能体循环
  ↓
全部处理完成
  ↓
同步更新业务后台数据
  ↓
等待下一次业务事件
```

#### 核心升级

| 第一二层 | 第三层 |
|---------|--------|
| 单次手动启动 | 全天候自动启动 |
| 临时运行脚本 | 正式业务服务 |
| 被动等待 | 主动监听 |

#### 实例：文档智能体事件驱动

```
用户提交文档优化需求（触发事件）
  ↓
自动唤醒验证 + 执行流程
  ↓
文档修改合并上线
  ↓
系统同步更新知识库索引
  ↓
持续等待下一条用户需求
```

**价值**：智能体嵌入业务流水线，实现规模化自动化运行

---

### 第四层：爬坡循环（Hill Climbing Loop）

**定位**：四层架构里价值最高的一层

#### 前三层 vs 第四层

| 前三层 | 第四层 |
|--------|--------|
| **基础工作自动化** | **自主优化自动化** |
| 执行既定流程 | 改进流程本身 |
| 被动运行 | 主动学习 |

#### 工作流程

```
业务事件触发前三层完整循环
  ↓
全程留存详细运行轨迹日志
  ↓
分析智能体扫描日志
  ↓
定位反复出现的系统性漏洞
  ↓
自动调整优化方案：
  ├─ 更新提示词
  ├─ 调整配套工具
  └─ 修改校验规则
  ↓
反向优化底层三层循环的运行逻辑
```

#### 日志收集的完整维度

- 模型推理记录
- 工具调用记录
- 校验失败反馈
- 多次重试记录
- **全部运行轨迹**

#### 实例：LangSmith Engine 轨迹分析

```
定期扫描全部文档修改日志
  ↓
识别多次出现的同类问题：
  ├─ API 参数说明缺失
  ├─ 代码示例运行报错
  └─ 文档结构不清晰
  ↓
系统自动生成优化工单
  ↓
更新方案：
  ├─ 生成更优化的基础提示词
  ├─ 补充专属校验规则
  └─ 增强工具配置
  ↓
从根源减少后续同类错误出现
```

#### 核心认识

> 如果说前三层循环是让 AI 接手人工重复工作，
> 第四层爬坡循环就是让 AI 自主优化自身的工作逻辑。

## 人机协同设计：四层循环预留的人工介入入口

### 设计理念：人在回路中（Human in the Loop）

四层循环整套流程都预留了人工介入入口，应对全自动运行风险较高的场景。

### 具体介入点

#### 1. 智能体执行阶段

**高风险工具调用 → 强制人工审批**

- 数据库操作
- 资金流转
- 权限变更
- 系统配置修改

#### 2. 内容校验阶段

**复杂/对外内容 → 人工参与评审**

- 复杂业务文稿
- 面向客户对外展示内容
- 法律/合规相关文档
- 技术决策文档

#### 3. 事件服务阶段

**生成交付 → 人工确认 → 正式上线**

```
智能体生成完整交付内容
  ↓
人工确认审阅
  ↓
通过 → 同步更新正式业务系统
```

#### 4. 自主优化阶段

**自动生成的方案 → 人工审核 → 正式上线**

```
系统自动生成的优化方案：
  ├─ 新提示词
  ├─ 工具配置调整
  └─ 校验规则更新
  ↓
人工审核（评估对系统的影响）
  ↓
通过 → 正式上线应用
```

### 机器-人类的职能分工

#### 机器负责

- ✅ 标准化工作
- ✅ 重复性任务
- ✅ 大批量检测工作
- ✅ 数据处理和分析
- ✅ 执行预设规则

#### 人类负责

- ✅ 价值判断
- ✅ 行业专业内容打磨
- ✅ 高风险环节决策
- ✅ 创新和优化方向定义
- ✅ 异常情况处理

### 协同原则

> 机器负责标准化、重复性、大批量的检测工作，
> 人类负责价值判断、行业专业内容打磨、高风险环节决策，
> 二者相互配合，不存在一方完全取代另一方的情况。

## 行业趋势与未来工程师职能转变

### 从"提示词工程"到"循环工程"

#### 过去（Prompt Engineering 时代）
- AI 工程师 80% 工作时间：反复调整提示词
- 核心技能：找到 magic prompt
- 局限：依赖个人经验，难以规模化

#### 现在/未来（Loop Engineering 时代）
- AI 工程师核心工作转向：
  - ✅ 搭建多层反馈循环
  - ✅ 制定完善校验标准
  - ✅ 打通日志分析自主优化链路
- 系统特性：
  - ✅ 自主生成、迭代调整提示词
  - ✅ 自主优化执行策略
  - ✅ 持续自我改进

### 差异化竞争力的来源

**过去**：堆砌大模型能力 + 精调提示词 → 易被复刻

**现在**：多层循环嵌套搭建的完整管控体系 → 难以复刻

> 真正能形成差异化竞争力的，是多层循环嵌套搭建出的完整管控体系。

---

## 总结

### 核心认识

1. **大模型已商品化**：调用接口或开源权重随处可得
2. **AI 与传统程序本质差异**：
   - 随机性输出需要多轮反馈
   - 不能依赖单次执行
   - 需要自检和重试机制
3. **Loop Engineering 是差异化壁垒**：
   - 四层循环嵌套的管控体系
   - 自动化与人工相互配合
   - 从被动执行到主动优化
4. **职能转变的必然性**：
   - 工程师从"调提示词"转向"搭循环"
   - 从单点优化转向系统优化
   - 从手工作坊转向自动化流水线

### 关键启示

> Boris Cherny: "My job is to write loops."
> 
> 这句话精准概括了 AI 工程的未来方向：
> 核心不再是与 AI 对话，而是设计让 AI 自主、持续、可控地运行的循环系统。
