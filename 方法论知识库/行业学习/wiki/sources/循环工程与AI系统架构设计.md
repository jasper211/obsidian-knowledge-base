# 循环工程与 AI 系统架构设计

## 核心命题

**大模型本身不是壁垒，Loop Engineering 循环工程才是真正拉开差距的关键。**

这套理论在 **2026 年 6 月正式被定义**，标志着 AI 工程从 "提示词工程" 时代向 "循环工程" 时代的转变。

---

## 问题诊断：为什么需要 Loop Engineering？

### 1. 大模型已成商品化

| 商品化维度 | 表现 |
|----------|------|
| 商用模型 | 调用接口随处可得 |
| 开源模型 | 权重易于获取 |
| 部署成本 | 已成标准化 |

**结论**：差异化竞争不在模型本身，而在**如何用好模型**。

### 2. AI 系统与传统程序的根本差异

#### 传统程序（Deterministic Logic）
- 运行逻辑固定不变
- 规则一旦设定永不出错
- 可长期稳定运行

#### AI 系统（Stochastic Output）
- 输出具备**随机性**
- 相同输入在不同时段返回不同内容
- 常见问题：
  - 信息编造（Hallucination）
  - 逻辑出错
  - 输出质量随使用时间逐步偏移

**核心困境**：无法依赖单次执行获得合格结果

### 3. Loop Engineering 的价值主张

**搭建自检机制**：系统发现输出有问题 → 自动重新调整 → 重试

**将各类自检、重试的逻辑完整搭建、串联起来** = Loop Engineering

### 职能范式转变

**Boris Cherny（Claude Code 负责人）的核心观点**：

> "I don't prompt Claude anymore. I have loops running that prompt Claude. My job is to write loops."

**含义**：
- ❌ 旧范式：工程师手动给 AI 发指令，反复迭代
- ✅ 新范式：工程师设计可自主持续运行的循环流程

## 四层循环架构详解

### 第一层：智能体循环（Agent Loop）

**层级定位**：最底层、最基础的核心单元

#### 工作原理

```
用户需求 → 模型判断(需要调用什么工具?) 
         → 执行工具操作
         → 重新调取模型处理结果
         → 循环直到不需要工具调用
         → 任务完成
```

#### 核心特征

- 模型**自主反复**调用配套工具
- 一步步推进任务
- 直到完成目标

#### 实例：文档优化智能体

```
需求：优化接口文档

Agent Loop 执行流程：
1. 拉取代码仓库
2. 读取现有文档
3. 编写修改方案
4. 提交 PR 申请

→ 任务完成
```

---

### 第二层：验证循环（Verification Loop）

**层级定位**：质量保证层，对智能体产出进行评估和反馈

#### 工作流程

```
智能体循环完成
    ↓
校验模块对标预设标准评分
    ↓
产出达标？
├─ NO  → 反馈完整问题清单 → 智能体重新生成
└─ YES → 合格，流程终止
```

#### 校验模块的双重机制

##### A. 固定规则校验（Deterministic）

完全自动化，无主观性：
- ✅ 链接可正常访问
- ✅ CI 流程无报错
- ✅ 代码格式符合规范
- ✅ 文件大小合规

**特点**：绝对正确性，可 100% 自动化

##### B. 大模型评审校验（LLM-based）

调用另一款大模型 + 人为设定标准：
- 内容完整度（是否涵盖所有必要信息）
- 目标受众适配度（是否符合读者需求）
- 专业性（技术准确性、术语规范）
- 清晰度（逻辑连贯、易于理解）

**特点**：处理主观维度，需人为标准定义

#### 实例：文档智能体验证流程

```
生成文档 PR
    ↓
自动校验（5 项检查）：
├─ ✅ 所有超链接可正常打开
├─ ✅ 代码 CI 无报错
├─ ✅ 修改范围与需求完全匹配
├─ ✅ 内容完整度 ≥ 80%
└─ ✅ 目标受众适配度 ≥ 85%

任意不通过 → 问题清单反馈 → 重新调整
```

#### 校验价值

- 🔒 稳定交付质量
- 🔄 自动化质检流程
- 🎯 明确质量标准
- 📊 可度量、可追踪

---

### 第三层：事件驱动循环（Event-driven Loop）

**层级定位**：从手动脚本 → 持续服务，系统与业务的对接层

#### 工作流程

```
外部业务事件触发
    ↓
自动启动验证循环 + 智能体循环
    ↓
全部处理完成
    ↓
同步更新业务后台数据
    ↓
等待下一次事件
```

#### 层级升级的意义

| 第一二层 | 第三层 |
|---------|--------|
| 单次手动启动 | 全天候自动启动 |
| 脚本式运行 | 服务化运行 |
| 被动等待 | 主动监听 |
| 临时性 | 常态化 |

#### 实例：文档智能体事件驱动

```
事件：用户提交文档优化需求

自动流程：
1. 系统监听到事件
2. 启动验证 + 执行循环
3. 生成优化方案
4. 完成质检
5. 文档修改合并上线
6. 同步更新知识库索引
7. 等待下一条需求

→ 全天候自动运行，无需人工启动
```

#### 价值体现

- 🚀 从脚本升级为服务
- 📈 规模化自动化运行
- ⏰ 实时响应业务事件
- 🔗 嵌入业务流水线

---

### 第四层：爬坡循环（Hill Climbing Loop）

**层级定位**：四层架构中价值最高的层，实现系统自主优化

#### 前三层 vs 第四层的根本差异

| 维度 | 前三层 | 第四层 |
|-----|--------|--------|
| **目标** | 执行既定任务 | 优化任务执行方式 |
| **能力** | 工作自动化 | 优化自动化 |
| **学习** | 被动执行 | 主动学习 |
| **进化** | 固定逻辑 | 持续自我迭代 |

#### 工作流程

```
业务事件触发前三层完整循环
    ↓
全程留存详细运行轨迹日志：
├─ 模型推理记录
├─ 工具调用记录
├─ 校验失败反馈
└─ 重试数据

    ↓
分析智能体扫描日志
    ↓
定位反复出现的系统性漏洞
    ↓
自动生成优化方案并执行：
├─ 更新提示词
├─ 调整工具配置
└─ 修改校验规则

    ↓
反向优化前三层循环的运行逻辑
```

#### 实例：LangSmith Engine 轨迹分析

```
定期扫描全部文档修改日志
    ↓
识别重复出现的问题模式：
├─ API 参数说明缺失（出现 15 次）
├─ 代码示例运行报错（出现 12 次）
└─ 文档结构不清晰（出现 8 次）

    ↓
系统自动生成优化工单：
├─ 更新智能体基础提示词（强调 API 参数重要性）
├─ 补充代码示例校验规则
└─ 增强文档结构校验

    ↓
应用优化方案
    ↓
后续同类错误率显著下降
```

#### 核心认识

> **如果说前三层循环是让 AI 接手人工重复工作，**
> **第四层爬坡循环就是让 AI 自主优化自身的工作逻辑。**

这是从 "任务执行" 到 "系统进化" 的质的飞跃。

## 人机协同设计：四层循环中的人工介入机制

### 设计哲学：人在回路中（Human in the Loop）

四层循环预留了多个人工介入入口，以应对全自动运行风险较高的场景。

### 具体介入点与机制

#### 1. 智能体执行阶段

**规则**：高风险工具调用 → 强制人工审批

```
高风险操作包括：
├─ 数据库操作（增删改查生产数据库）
├─ 资金流转（财务相关操作）
├─ 权限变更（系统访问权限修改）
└─ 系统配置修改（关键配置变更）

执行流程：
AI 提议操作 → 人工审批 → 通过后执行
```

**价值**：防止 AI 误操作导致的风险

#### 2. 内容校验阶段

**规则**：复杂/对外内容 → 人工参与评审

```
需要人工参与的内容：
├─ 复杂业务文稿
├─ 面向客户对外展示内容
├─ 法律/合规相关文档
├─ 技术决策文档
└─ 品牌宣传物料

评审流程：
AI 生成内容 → 人工评审 → 提反馈或批准
```

**价值**：确保专业性、合规性和品质

#### 3. 事件服务阶段

**规则**：交付前需人工确认

```
交付流程：
1. AI 生成完整交付内容
2. 通过所有自动验证
3. 推送人工确认界面
4. 人工审阅和签署
5. 同步更新正式系统

特例处理：
- 小改动可快速通过
- 重大变更需详细审查
- 高风险操作需负责人签字
```

**价值**：最后一道质量防线，确保更新的有效性

#### 4. 自主优化阶段

**规则**：系统优化方案需人工审核通过

```
优化流程：
1. 系统分析日志和问题
2. 自动生成优化方案：
   - 新提示词
   - 工具配置调整
   - 校验规则更新
3. 提交人工审核
4. 评估影响范围
5. 人工批准 → 正式上线
6. 效果监测

审核重点：
- 是否会影响其他功能
- 是否降低安全性
- ROI 是否合理
```

**价值**：防止盲目优化引入新问题

### 机器 vs 人类的职能分工

#### 机器（AI 系统）负责

✅ 标准化工作
- 遵循明确规则的任务
- 如数据格式验证、重复检查

✅ 重复性任务
- 批量处理
- 标准化流程执行

✅ 大批量检测工作
- 扫描、分类、标记
- 模式识别

✅ 数据处理和分析
- 日志解析
- 统计分析
- 趋势识别

#### 人类负责

✅ **价值判断**
- 什么值得做、什么不应该做
- 优先级决策
- 业务目标评估

✅ **行业专业内容打磨**
- 技术准确性验证
- 业界标准和规范遵循
- 创新方向引导

✅ **高风险环节决策**
- 财务、安全、法律风险评估
- 突发异常情况处理
- 跨界协调决策

✅ **创新和优化方向定义**
- 新功能设计
- 流程优化方向
- 长期战略规划

✅ **异常情况处理**
- 系统无法自动处理的情况
- 突发事件应对
- 边界情况判断

### 协同原则

> **机器负责标准化、重复性、大批量的检测工作，**
> **人类负责价值判断、行业专业内容打磨、高风险环节决策，**
> **二者相互配合，不存在一方完全取代另一方的情况。**

这是 **互补而非替代** 的关系。

**Jasper 核心理念**：明确 AI 与人的分工

- 机器负责标准化、重复性、大批量工作
- 人类负责价值判断、专业打磨、风险决策
- 四层循环每一层都预留人工介入点

**对标强度**：✅✅✅✅✅ **完全一致**

**新贡献**：Loop Engineering 给出了更具体、更可落地的分工模型

### 2. AI 是判断力放大器

**Jasper 核心理念**：AI 放大人的判断力，而非替代

**Loop Engineering 体现**：
- 第一层：AI 执行工具调用，人做决策
- 第二层：AI 自动校验，人做最终判断
- 第三层：AI 全自动运行，人做监督
- 第四层：AI 生成优化方案，人做审核批准

**对标强度**：✅✅✅✅✅ **深度呼应**

**新维度**：四层循环展示了判断力放大在不同规模应用中的具体体现

### 3. 知识工程方法（新映射）

**理论基础**：隐性规则的显式化

**Loop Engineering 体现**：
- 第一层 Agent Loop：将业务需求显式化为工具调用序列
- 第二层 Verification Loop：将质量标准显式化为规则集
- 第四层 Hill Climbing Loop：将优化知识显式化为提示词和配置

**对标强度**：✅✅✅✅ **补充映射**

## 行业趋势与工程师职能转变

### 从 "提示词工程" 到 "循环工程" 的范式转变

#### 2024-2025：Prompt Engineering 时代

**特征**：
- AI 工程师 80% 时间用于反复调整提示词
- "Magic Prompt" 理论横行
- 依赖个人经验和直觉
- 难以规模化和标准化

**局限**：
- 成果具备个人性色彩
- 难以复制和传播
- 效率难以进一步提升

#### 2026+：Loop Engineering 时代

**新工作方向**：
- ✅ 搭建多层反馈循环
- ✅ 制定完善的校验标准
- ✅ 打通日志分析与自主优化链路
- ✅ 设计人机协同机制

**系统特性**：
- ✅ 自主生成和迭代调整提示词
- ✅ 自主优化执行策略
- ✅ 持续自我改进和进化
- ✅ 可规模化应用

**优势**：
- 💪 形成可复制的系统
- 💪 标准化流程和结果
- 💪 持续改进的能力
- 💪 降低对个人的依赖

### 差异化竞争力的新来源

#### 过去

❌ 堆砌大模型能力 + 精调提示词
→ 易被同行快速复刻
→ 产品同质化严重

#### 现在

✅ **多层循环嵌套搭建的完整管控体系**
→ 难以被快速复刻
→ 形成技术护城河

**原因**：
- 循环架构涉及多层复杂度
- 需要积累大量运行数据
- 需要建立完善的评估标准
- 涉及人机协同的深度融合

> 真正能形成差异化竞争力的，是多层循环嵌套搭建出的完整管控体系。

## 核心启示与总结

### 三大基础认识

1. **大模型已成商品化**
   - 调用接口随处可得
   - 开源权重易于获取
   - 成本快速下降

2. **AI 系统与传统程序的本质差异**
   - AI 输出随机性 ≠ 传统程序确定性
   - 需要多轮反馈和重试
   - 单次执行不可靠

3. **Loop Engineering 是差异化壁垒**
   - 四层循环嵌套的管控体系
   - 自动化与人工的完美协同
   - 从被动执行到主动优化

### 职能转变的必然性

**从**：调提示词 + 看结果
↓
**到**：搭循环系统 + 优化架构

**体现**：
- 单点优化 → 系统优化
- 手工作坊 → 自动化流水线
- 被动等待 → 主动学习

### 关键金句

> **"I don't prompt Claude anymore. I have loops running that prompt Claude. My job is to write loops."**
>
> ——Boris Cherny，Claude Code 负责人

这句话精准概括了 AI 工程的未来方向：
- ❌ 不再是与 AI 对话
- ✅ 而是设计让 AI 自主、持续、可控地运行的循环系统

### Loop Engineering 的终极目标

从 **"人驱动 AI"** → **"AI 自驱，人监督"**

- 🎯 第一层：AI 执行，人监督
- 🎯 第二层：AI 自检，人把关
- 🎯 第三层：AI 全自动，人远程监督
- 🎯 第四层：AI 自优化，人认可策略

最终实现：**可控、可持续、持续进化的 AI 系统**
