# AI 能力接入与发布上线

## 课程定位

**课程**：AI编程与产品开发系列·模块五（完结）
**目标**：从本地产品到互联网可访问产品
**核心**：完成上线闭环，让产品从只有自己看到变成别人也能访问
**成果**：可分享的公网链接、GitHub代码资产、安全的API调用

---

## 核心理念转变

### 从本地到线上的本质差异

```
本地运行：localhost:5173
  ↓ 只有自己能访问
  ↓ 用于开发和测试

线上运行：your-site.vercel.app
  ↓ 互联网用户均可访问
  ↓ 真正的产品、真正的价值
```

**核心原则**：
> **本地能跑不代表线上一定能跑，构建和环境变量是两大关键**

---

## 上线闭环的8步流程

```
Step 1: 检查本地项目
  ↓ npm run dev 正常运行

Step 2: API升级为Serverless代理
  ↓ 完善错误处理，隐藏密钥

Step 3: 创建GitHub仓库
  ↓ git init → git add → git commit → git push

Step 4: 导入部署平台
  ↓ 选择 Vercel 或 EdgeOne Pages

Step 5: 配置构建命令
  ↓ Framework: Vite, Build: npm run build, Output: dist

Step 6: 部署获得链接
  ↓ 点击Deploy，获得公网访问地址

Step 7: 绑定域名DNS
  ↓ 自有域名解析、HTTPS证书签发

Step 8: 验证上线完成
  ↓ 别人能打开你的产品链接
```

**关键原则**：每一步依赖上一步完成，不要跳步

---

## 常见上线失败的原因

| 问题 | 原因 | 解决方案 |
|------|------|--------|
| **本地构建失败** | 依赖缺失或语法错误 | 先跑 npm run build 检查 |
| **GitHub提交错误** | 代码没推送成功或遗漏文件 | 检查git add和git push |
| **构建配置错误** | Build或Output填错 | Vite使用dist作为输出目录 |
| **框架识别失败** | 平台没正确识别项目 | 重新导入仓库 |
| **环境变量缺失** | API Key没配到线上 | 在平台后台设置环境变量 |
| **密钥暴露** | API Key写在代码里 | 改用Serverless代理 |

## Serverless API 代理机制

### 为什么需要代理？

```
❌ 本地开发（不安全）：
  前端直连 DeepSeek API
  → API Key暴露在浏览器
  → 被扒代码可获得密钥
  → 账户被滥用

✅ 线上正式（安全）：
  前端 → 自己的Serverless函数 → DeepSeek API
  → API Key存在服务端环境变量
  → 前端看不到真实密钥
  → 安全隔离
```

### 实现原理

```
1. 用户在前端页面输入信息
2. 前端向自己网站的API发送请求
3. Serverless函数接收请求
4. 读取环境变量中的API Key
5. 转发请求给DeepSeek API
6. DeepSeek返回内容
7. Serverless函数转发给前端
8. 前端展示结果
```

**关键**：API Key永远不暴露在前端代码中

### 核心参数
- **请求地址**：api.deepseek.com/chat/completions
- **格式兼容**：OpenAI Chat Completions（直接适配）

### 2026年7月更新
- **峰谷定价**：高峰9-12/14-18时价格翻倍
- **缓存优化**：缓存命中价格仅未命中的1/120
- **旧接口迁移**：deepseek-chat于7月24日停用
- **成本控制**：使用缓存可省50%

### 定价参考
```
Flash输出：平时 2元/百万token，高峰 4元
Pro输出：平时 6元/百万token，高峰 12元
```

|------|------|------|
| **访问范围** | 只有自己电脑 | 互联网用户均可 |
