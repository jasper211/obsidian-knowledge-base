## 三、Step 2：交付物四标签分析

---

### 交付物1 · 《合作资格预审与流程启动计划》

**交付物定位**：L3-IBRD准入阶段第一道门槛，决定机构是否进入后续牌照核查和尽调流程。

#### A · 交付物类型规则风险

- **交付物类型**：准入评估类交付物
- **类型规则风险**：准入标准不一致会导致合作方质量参差，低质量机构进入后续流程将产生佣金结算和合规连锁风险
- **核心规则信号**：资格预审标准（哪些机构可以合作/排除条件是什么/有无量化指标）**未书面化**

#### B · 交付物责任与执行断点

- **责任模式**：C族-机构BD主责，但预审标准由谁定义不明确 → **责任断点🔴**
- **执行断点**：预审结论无复核机制（自填自审风险：一个TR认为"可以通过"，另一个可能认为"不行"）
- **字段级补充**：⛔（本交付物无直接关联数据表）

#### C · 交付物流转验证断点

- **验证链位置**：L3-IBEC《转介信息包》→ **资格预审** → 《计划》→ Step 2牌照核查
- **断点类型**：**交接断点**（预审标准未定义，不同执行人结论可能不一致）
- **验证盲区**：预审通过/不通过的标准是什么？有无量化指标？预审不通过的机构是否进入观察池？观察池管理规则是什么？

#### D · 交付物授权级别

- **授权级别**：🔴 **高**（准入确权——决定一个机构能否进入合作流程）
- **裁定责任人**：Mark / C族负责人
- **匹配性**：❌ **不匹配**（预审标准缺失，实际执行中授权边界模糊——TR可以自行决定通过/不通过，但标准不明）

**综合优先级：P0**（B=🔴责任断点/无复核 + D=🔴高授权 + ❌调研未覆盖预审标准）

### 交付物2 · 《牌照核查与保司确认记录》

**交付物定位**：L3-IBRD合规核心交付物，牌照信息直接决定合作路径（9付/UNIVIN/DW），是准入决策的关键输入。

#### A · 交付物类型规则风险

- **交付物类型**：合规核查类交付物
- **类型规则风险**：牌照信息错误直接导致合作路径错误（出单牌照错误），引发合规和财务连锁风险
- **核心规则信号**：牌照类型→合作路径的映射规则**未系统化**（A-02 v1.2决策树为口头规则，未沉淀为系统配置）

#### B · 交付物责任与执行断点

- **责任模式**：L4-IBRD-04主责=菲菲，协作=Alice（保司确认）。但牌照信息录入config由业务人员维护 → **自填自审🔴**
- **执行断点**：IA网站查询→记录→保司确认，三步之间无系统校验；查询结果与config配置可能不一致
- **字段级补充**（有旧版数据表信息）：dim_license.license_type（自填自审，单点责任，直接影响A-02判断节点0）

#### C · 交付物流转验证断点

- **验证链位置**：IA网站查询 → 《牌照核查记录》 → 保司Alice确认 → **config_partner_routing配置**
- **断点类型**：**交接断点**（核查记录与系统配置之间无自动同步，人工录入可能出错）
- **验证盲区**：牌照过期后是否自动阻断合作？过期预警机制是否存在？

#### D · 交付物授权级别

- **授权级别**：🔴 **高**（合规准入——牌照是合作的前提条件）
- **裁定责任人**：合规部门 / Mark
- **匹配性**：❌ **不匹配**（自填自审无独立复核，高授权交付物缺少审批链）

**综合优先级：P0**（B=🔴自填自审 + D=🔴高授权 + ❌牌照→路径映射未系统化）

- **交付物类型**：运营管理类交付物
- **类型规则风险**：沟通机制缺失会导致信息传递不畅，但风险相对可控（非准入核心）
- **核心规则信号**：沟通频次/联络人/信息共享规则**未标准化**

#### B · 交付物责任与执行断点

- **责任模式**：C族-机构BD主责
- **执行断点**：沟通机制建立后由谁维护？联络人变更时谁负责更新？

#### C · 交付物流转验证断点

- **验证链位置**：建立沟通机制 → 双方执行
- **断点类型**：**验收标准缺失**（怎么算"沟通机制已建立"？有无确认书或邮件记录？）
- **验证盲区**：沟通机制失效时（联络人离职/失联）有无fallback方案？

- **授权级别**：🟢 **低**（日常运营支持，不涉及准入或结算决策）
- **裁定责任人**：C族-机构BD

### 交付物4 · 《尽职调查执行记录》

**交付物定位**：L3-IBRD核心合规交付物，是准入决策的直接依据，输出至L3-NG谈判底稿。流程蓝图V1.3确认当前为"分散记录（口头沟通+微信记录+牌照截图+入系统记录，无标准化文档）"。

#### A · 交付物类型规则风险

- **交付物类型**：合规尽调类交付物
- **类型规则风险**：尽调记录是准入决策的核心依据，记录不完整或标准不一致会直接导致合作风险（高风险机构被误判为低风险）
- **核心规则信号**：尽调记录当前为**口头/微信/截图形式，无标准化模板**（流程蓝图V1.3已确认；A-03整改任务M4.1前完成）

#### B · 交付物责任与执行断点

- **责任模式**：C族-机构BD主责，但当前为口头/微信/截图形式 → **自填自审🔴**
- **执行断点**：尽调内容无统一标准，不同TR的尽调深度不一致（有的只查牌照，有的深入查团队背景和业务模式）
- **字段级补充**（有旧版数据表信息）：dim_partner.partner_status（尽调结论→合作伙伴状态映射未定义）；partner_tier_rules.fyc_tier（档位判断标准未定义）

#### C · 交付物流转验证断点

- **验证链位置**：尽调执行 → 《尽调记录》 → **L3-NG谈判底稿**
- **断点类型**：**交接断点**（尽调记录如何传递至谈判？传递哪些内容？什么格式？）
- **验证盲区**：尽调结论"低风险/中风险/高风险"的判断标准未定义；尽调记录是否需要CO审核？

#### D · 交付物授权级别

- **授权级别**：🔴 **高**（合规/准入确权——尽调结论直接决定能否合作）
- **裁定责任人**：合规部门 / CO
- **匹配性**：❌ **不匹配**（尽调记录无标准化模板，审核无据可依；自填自审无独立复核）

**综合优先级：P0**（B=🔴自填自审/无标准化 + D=🔴高授权 + ❌尽调模板缺失）
