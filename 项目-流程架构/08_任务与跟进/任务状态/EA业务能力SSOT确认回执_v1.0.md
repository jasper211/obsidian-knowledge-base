**SSOT 指定为 B（L1 价值链，5条）**，价值流（A）作为二级维度保留，C（业务能力地图）不作为现行权威。

## 逐项回执

### Q1：哪套是"业务能力"的 SSOT？

**结论：B（L1 价值链）**

| 结构 | 状态 | 理由 |
|------|------|------|
| A 价值流（5条） | 保留为二级维度 | 利益相关者旅程视角，非能力分类，不适合作业务锚 |
| **B L1 价值链（5条）** | **✅ 指定为 SSOT** | 已完整落地于 DIM_PROCESS，每条 L4 均有 l1_code 直接属性，IE 可零推导直接聚合 |
| C 业务能力地图（11条） | 不采纳 | 外部输入原始材料（存放路径：01_原始材料-外部导入/M-02_架构全景），从未经 Mark 正式确认为 EA 产出物；其 L4 编码体系（L4-MA/VP/GTM 等）与 DIM_PROCESS 完全独立，不可混用 |

---

### Q2：三套的派生关系是什么？

**A、B 为正交的两个视角，非上下级关系。**

- **A（价值流）** = 利益相关者端到端旅程（谁经历这个旅程）
- **B（L1 价值链）** = 运营职能阶段（做什么类型的事）
- 两者通过 **dim_vs → l3_primary → dim_process.l1_code** 的关联路径已在数据库中建立交叉映射，具体如下：

| 价值流 | 名称 | 涉及 L1 |
|--------|------|---------|
| VS-1 | 保司资源投放旅程 | L1-02 |
| VS-2 | 机构合作伙伴旅程 | L1-02、L1-03、L1-04、L1-05 |
| VS-3 | KA上架旅程 | L1-02、L1-03、L1-04 |
| VS-4 | 理财师发展旅程 | L1-03 |
| VS-5 | 权益服务企业客户旅程 | L1-05 |

> 注：L1-01（资源获取与产品整合）目前在 dim_vs 主键 L3 关联中无对应 VS，可能存在于非主键 L3 中，建议 IE 在投影时保留 L1-01 作为独立锚点，不合并。

**C（业务能力地图）** 为外部参考框架，未与 A/B 建立正式映射，暂不纳入派生关系。

---

### Q3：C（业务能力地图 11 一级能力）是否现行权威版？

**否。**

- 存放路径为 `01_原始材料-外部导入/M-02_架构全景/`，属于**外部导入原始资料**，不是 EA 生产的成果物
- 颗粒度不均，部分能力仅有 2~4 行，未经系统化验证
- 从未在 EA 正式文件（DIM_PROCESS、价值节点清单、L3 调整记录等）中被引用或落地
- **现行权威的能力清单 = DIM_PROCESS 中的 l1_code（5条 L1 价值链）**

---

### Q4：临时权威源（供 IE 搭骨架）

**直接采用 B（L1 价值链），无需标记 provisional。**

IE 可从 DIM_PROCESS 中直接取数：

```sql
SELECT DISTINCT l1_code, l1_name
FROM process_analytics.DIM_PROCESS
WHERE is_current = true
ORDER BY l1_code;
```

结果即为 5 条业务锚：

| l1_code | l1_name |
|---------|---------|
| L1-01 | 资源获取与产品整合 |
| L1-02 | 市场设计与合作伙伴发展 |
| L1-03 | 运营反馈与路由决策 |
| L1-04 | 能力赋能与增长驱动 |
| L1-05 | 价值增值与生态绑定 |

如需 VS 作为二级标签，通过上述交叉映射表附加即可，不影响锚点本身。
