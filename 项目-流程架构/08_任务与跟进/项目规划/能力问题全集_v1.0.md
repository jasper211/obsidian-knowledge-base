> 起草: 协调角色 2026-06-13 / 状态: BO-1.1 完成，待 Mark 阅 + 作 BO-1.2 锚点重审输入
> 性质: 对 EA 价值链「5 价值流全部阶段 + 全部价值节点三 Gate」做一遍系统收割，得能力问题全集。

## 0. 一句话

能力问题不是设计的，是从已建好的价值链里**收割**的。本次对两张 EA 权威表做一遍机械收割，产出 **703 条能力问题**，每条带 VS/VN/L3 出处。其中最有价值的不是问题本身，而是收割时**顺带暴露的能力缺口**：48 个 Gate 判定为 FAIL、分布在 25 个价值节点上——这 25 个就是 BO-1.2 锚点重审该自顶向下覆盖的能力洞。

## 1. 收割机制（两腿四来源，全部带出处）

| 腿 | 来源表 | 收割逻辑 | 产出条数 |
|---|---|---|---|
| 腿 1 价值流阶段 | `价值流_价值阶段_价值活动_全量表_V3.csv`（359 活动） | 每个 VS×阶段 → "该利益相关者是否具备完成其价值活动的能力与产出物?" | 36 |
| 腿 2 节点三 Gate | `D2_价值节点_L3映射表_V1.12.csv`（72 节点×L3 行 / 67 节点） | 每节点 ×（Gate①挂数 / Gate②落地 / Gate③追溯）→ 3 条，带实际判定 | 216 |

| | | **合计** | **703** |

> 腿 2/3/4 的"节点"按 D2 表的 72 个 节点×L3 映射行展开（5 个节点映射到 2 条 L3，故 72 行 / 67 个 distinct 节点）。腿 1 在 VS×阶段 层聚合（不逐活动展开），359 条活动作每阶段的证据计数。

### 3.3 熔断优先级节点（priority 含"熔断"，3 个）

VN-PAY-04 转介费派发确认台账（P0 熔断，三门全失 + IA 50%/88% 红线）· VN-PAY-09 体系外对账表 · VN-URD-01 联合运营需求诊断报告。

### 3.4 系统性发现

1. **Gate③ 追溯 是最普遍的失败门**：25 个 FAIL 节点里绝大多数栽在"能否 100% 回溯 L3+原始输入"——这是一个**横切能力缺口**（数据债的本体表现），不是单点问题。
2. **四属性层**：FAIL 38 / PARTIAL 18 / 待调研 44（共 288 条），其中"物理对应/数据验证"是主要欠缺面。
3. **缺口按 L1 能力域聚合**即 BO-1.2 候选锚点的自顶向下骨架——尤其 L1-04（代理人发展，21 节点）与财务/佣金链（VN-PAY/BAM/CFM）缺口集中，与 EE 既有诊断（佣金链 SPOF、IA 合规无系统拦截）方向一致。

## 5. 诚实标注与边界（防 fab / 不以"够用"延期）

1. **价值流全量表为 🟠 草稿态**（confirmation_status 字段）——腿 1 的 36 阶段问题出处是草稿态映射，定稿前不得当已确认事实。

3. **节点计数双口径**：72 节点×L3 行 / 67 distinct 节点，文中已分别标注，未混用。
4. **全集 = CSV**：本文是框架+缺口综述+样本；703 条机器可验明细在 `能力问题全集_v1.0.csv`（16 列含 cq_id/leg/question/出处链）。本文所有数字由脚本 stdout 派生，未手抄。
