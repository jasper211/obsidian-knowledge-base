## 一、映射框架总览

### 1.1 两套独立映射体系

本项目存在两套独立的L3归属映射，不可混淆：

| 维度 | L1-L3映射 | VS-L3映射 |
|------|----------|----------|
| 映射方向 | L3 → L1（价值链节点） | L3 → VS（价值流） |
| 映射性质 | L3的**能力归属**（组织内部视角） | L3的**价值交付归属**（外部利益相关者视角） |
| 数量关系 | 1个L3 = 1个L1（强制单属） | 1个L3 = 0或1个VS（可不属于任何VS） |
| 数量 | 82个L3全部归属5个L1 | 67个L3归属5条VS，16个不属于任何VS |
| 权威文件 | L1-L3映射分析逻辑与标准.md | **本文档** |

### 1.2 关键差异：L1 ≠ VS

| 维度 | 价值链节点(L1) | 价值流(VS) |
|------|---------------|-----------|
| 视角 | 内部能力分解（我们怎么运作） | 外部利益相关者旅程（客户怎么获得价值） |
| 触发者 | 内部战略/KPI | 外部角色（保司/机构/KA/理财师/客户） |
| 数量 | 5个 | 5条 |
| 对应关系 | L1-01~05 | VS-1~VS-5 |
| 是否一对一 | **否** | — |

> ⚠️ L1与VS不是一对一关系。L1-05（权益中台）是横切能力层，被VS-2/VS-4/VS-5消费，不是独立价值流。

## 三、L3归属价值流的判断逻辑

### 3.1 核心判断问题（3问检验法）

对任意一个L3流程，依次回答以下三个问题：

```
Q1：这个流程服务的直接外部利益相关者是谁？
  ├── 保司                              → 候选 VS-1
  ├── 机构/经代                          → 候选 VS-2
  ├── KA客户                            → 候选 VS-3
  ├── 理财师                            → 候选 VS-4
  ├── 终端客户                          → 候选 VS-5
  └── 没有直接外部利益相关者              → 非VS级（进入Q2）

Q2：这个流程的触发事件是什么？
  ├── 由外部利益相关者发起（签约请求/上架请求/入职请求等）→ 候选对应VS
  └── 由内部战略/KPI/合规需求驱动                       → 非VS级

Q3：这个流程的最终交付物接收方是谁？
  ├── 外部利益相关者收到价值              → 确认归入该VS
  ├── 内部团队收到（战略报告/合规记录等）  → 确认非VS级
  └── 多条VS的价值阶段都会调用           → 非VS级（横切能力）
```

## 五、非VS级L3的判断逻辑

### 5.1 三类非VS级L3

不属于5条价值流中任何一条的L3分为三类：

| 类型 | 数量 | 判断依据 | Mark裁定状态 |
|------|------|---------|-------------|
| **战略赋能层(L1-01)** | 8个 | 内部战略/KPI驱动，无直接外部利益相关者 | ❌ Mark未直接裁定，由方法论规则1推导 |
| **佣金合规层(L1-04)** | 4个 | 内部结算能力，无独立外部利益相关者旅程 | ⚠️ Mark说佣金归L1-02/L1-03，映射表归L1-04，不一致 |
| **权益中台横切层(L1-05)** | 4个 | 横切能力，被多条VS消费，非独立VS | ✅ Mark明确裁定（方法论纠偏六点五节） |

### 5.2 判断规则

**规则A：外部性检验（来源：方法论纠偏规则1）**

```
如果 L3 的触发者 = 内部战略/KPI/合规需求
  → 不通过外部性检验 → 不属于任何VS
```

适用于：8个PROC战略流程（L3-MIO/VPV/MED/CAS/SPE/SRE/MEI/SFC）

**规则B：横切能力检验（来源：方法论纠偏六点五节）**

```
如果 L3 满足以下全部条件：
  1. 组织归属中台
  2. ≥2条VS的价值阶段会调用该能力
  3. 有独立治理（L3流程、KPI、RACI）
  → 识别为横切能力 → 归L1-05，不属于任何单一VS
```

适用于：L3-EO/RSD/SLCM/SLM

**规则C：内部结算能力检验（来源：方法论纠偏五节"消失的构件"）**

```
如果 L3 的核心职能 = 佣金结算/合规验证
  → 属于内部结算能力 → 不构成独立价值流
```

适用于：L3-CBD/CMU/COM/CVI

### 5.3 非VS级L3与价值流的消费关系

非VS级L3虽然不属于任何VS，但会被VS消费。消费关系如下：

## 九、强制规则

### 规则1：VS映射严格基于外部性检验

> L3归属VS必须通过方法论纠偏规则1的"外部性检验"：
> - 利益相关者必须是外部角色
> - 触发者必须是外部
> - 交付物必须由外部接收
>
> 不通过检验的L3归入"非VS级"，不得强行挂接到VS。

### 规则2：L3至多归属1条VS

> 每个L3编码至多归属1条价值流。若某L3被≥2条VS的价值阶段调用，则该L3归入"非VS级（横切能力）"，并在消费关系表中记录调用关系。

### 规则3：VS归属变更必须留有裁定记录

> 任何对vs_suggested的修改必须记录：
> - 修改前后的VS归属
> - 变更依据（逻辑推导 / 人工裁定）
> - 裁定类别（A类：无需讨论 / B类：需人工确认）
> - 裁定人（Mark / Teresa）

### 规则4：L1归属与VS归属独立判断

> L3归L1 ≠ L3归VS。两个映射体系独立运作：
> - L3归L1-05 ≠ L3归VS-5（L1-05是横切能力层，不是VS-5）
> - L3归L1-01 ≠ L3不属于任何VS（需看具体流程是否有外部利益相关者）
> - L3归L1-04的佣金流程 ≠ 佣金属于某条VS（佣金是内部结算能力）

## 十、裁定流程

### 10.1 A类：逻辑清晰，直接更新

满足以下全部条件：
1. L3名称与VS定义**明显吻合**
2. 目标VS唯一且无歧义
3. 通过外部性检验（Q1~Q3）

> 示例：L3-IAO（保司合作接洽与评估）→ VS-1，名称含"保司"，触发者是保司，无歧义

### 10.2 B类：需人工裁定

满足以下任一条件：
1. L3可归入2条以上VS（横切能力边界模糊）
2. L3在L1-L3映射中归L1-05，但VS-5也声称该L3
3. L3名称含"市场""策略"等跨L1关键词
4. 当前归属与Mark历史裁定冲突

> 示例：L3-SRA（服务需求诊断与分析流程）— L1-05横切能力表标注跨VS-2/3/5，但"诊断"是VS5-S1核心活动，需裁定
