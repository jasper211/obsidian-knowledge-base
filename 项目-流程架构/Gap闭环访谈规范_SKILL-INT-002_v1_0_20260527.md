# Gap闭环访谈规范
> **文档代号**：SKILL-INT-002
> **版本**：v1.0 | **建立日期**：2026-05-27
> **适用范围**：所有三层递进提取法产出的规则清单，凡存在Gap即触发本规范
> **在三层递进中的位置**：第三层规则回填产出后 → 本规范覆盖 → SOP撰写前
> **与SKILL-INT-001的关系**：
>   SKILL-INT-001覆盖「访谈 → 标准记录MD」；
>   本规范覆盖「规则清单Gap → 无Gap规则清单」
> **归档路径**：01_上下文文件（AI协作）/Gap闭环访谈规范_SKILL-INT-002_v1_0_20260527.md
> **归档类型**：AI协同规则类 → 本地第二大脑（R9规则）

## 一、文档定位

### 1.1 为什么需要这份规范

三层递进提取法执行完毕后，产出的是规则清单——但**有Gap的规则清单不是完成品**，不能直接进入SOP撰写。

原因：
- Gap代表信息缺失、岗位边界未跨越、或系统设计问题未裁定
- 直接基于有Gap的规则清单撰写SOP，会导致SOP覆盖不全或依据不牢
- 多轮访谈各自独立产出规则回填，但Gap闭环需要跨轮次追踪

本规范定义了从「有Gap的规则清单」到「无Gap规则清单」的完整闭环机制，确保SOP的输入基础是可靠的。

### 1.2 触发条件

规则清单中**任何一条规则的Gap字段不为空**，即触发本规范。
触发后必须执行Gap分级 → 二次访谈 → 回填 → 验证的闭环流程，
直至所有Gap清零或进入C类裁定挂起状态。

### 1.3 在完整工作链路中的位置

```
三层递进提取法（方法论v2.3）
  │
  ├── 第一层：四标签 + 规则空白地图
  ├── 第二层：访谈工具包 + 访谈执行
  │     └── SKILL-INT-001：访谈 → 标准记录MD
  └── 第三层：规则回填
        │
        └── 产出：规则清单（可能含Gap）
              │
              ▼
        ┌─────────────────────────────┐
        │ 本规范（SKILL-INT-002）      │
        │ Gap分级 → 多轮访谈 → 验证   │
        └──────────────┬──────────────┘
                       ▼
              无Gap规则清单
                       │
                       ▼
                  SOP撰写
```

**关键规则**：SOP撰写的前置条件是SKILL-INT-002确认「无Gap验证通过」。未通过验证的规则清单不得进入SOP阶段。

## 二、Gap分级与处理路径

Gap按成因和处理方式分为三类。每条Gap在FIN003-A规则清单中必须标注A/B/C类别。

### 2.1 A类·信息缺失Gap

| 要素 | 内容 |
|---|---|
| **定义** | 受访者在访谈中未提供足够信息，但该信息在该受访者岗位认知范围内 |
| **识别标志** | 转录中对应问题未获答案 / 回答模糊 / 回答有矛盾但需同一人澄清 |
| **处理路径** | 二次访谈同一受访者 → 回填规则清单 → 无Gap验证 |
| **执行终端** | 访谈：Jasper | 转录：通义听悟 | 记录MD：Kimi（SKILL-INT-001）| 回填：Claude |
| **示例** | 蔡依娜未详细描述字段填写SOP、14种账单状态枚举不完整 |

### 2.2 B类·岗位边界Gap

| 要素 | 内容 |
|---|---|
| **定义** | 当前受访者不知晓的信息，属于其他岗位的职责范围 |
| **识别标志** | 受访者明确表示"这不是我的范围"/"需要问XXX"/"我不清楚" |
| **处理路径** | 安排对应岗位的首次或二次访谈 → 回填规则清单 → 无Gap验证 |
| **执行终端** | 同上，但访谈对象为其他岗位 |
| **示例** | 彭文负责基本法审批链、Carrie负责同行支付率校验 |

### 2.3 C类·系统裁定Gap

| 要素 | 内容 |
|---|---|
| **定义** | 信息缺口非人力可补，属于系统设计或管理层决策事项 |
| **识别标志** | 涉及系统功能改造 / 管理制度设定 / 多部门权责划分 / 无明确责任人 |
| **处理路径** | 整理裁定选项 → 提交Mark/管理层 → 等待裁定结果 → 回填或挂起 |
| **执行终端** | 整理：Claude | 提交：Jasper | 裁定：Mark |
| **示例** | 应派复核层是否设置、IA硬指标系统化校验、驳回SOP制定 |

### 2.4 混合型Gap处理规则

当同一规则下存在多种Gap类型时，按以下顺序处理：

```
1. 先处理C类裁定Gap（不裁定则A/B类回填可能白做）
     ↓
2. 再推B类岗位边界Gap（跨越岗位获取信息）
     ↓
3. 最后处理A类信息缺失Gap（在同一岗位内补充信息）
```

**注意**：C类裁定在等待Mark回复期间可标注「裁定挂起·不阻塞」，A/B类可并行推进。

## 三、多轮迭代规则

### 3.1 轮次定义

| 轮次 | 定义 | 输入 | 输出 |
|---|---|---|---|
| **第1轮** | 首次访谈后的规则回填结果（FIN003-A v1.0） | 标准访谈记录MD（SKILL-INT-001产出）| 规则清单（含初始Gap）|
| **第2轮** | 二次访谈后的回填更新 | 二次访谈记录MD + 第1轮Gap清单 | 规则清单（Gap减少）|
| **第N轮** | 第N次迭代后的回填 | 上轮Gap清单 + 本轮访谈记录 | 规则清单（Gap进一步减少）|
| **无Gap版** | 所有Gap清零（或仅剩C类裁定挂起）| 上一轮规则清单 | **无Gap规则清单（可进入SOP）** |

### 3.2 版本号规则

| 场景 | 版本变化 | 示例 |
|---|---|---|
| 部分Gap解决（仍有A/B类Gap残留）| 小版本递增 | v1.0 → v1.1 |
| 全部A/B类Gap解决（仅剩C类裁定挂起）| 大版本升级 | v1.x → v2.0（无Gap版）|
| 无Gap版发布后新发现Gap | 小版本递增 | v2.0 → v2.1 |
| C类裁定完成回填后 | 小版本递增 | v2.1 → v2.2 |

### 3.3 每轮结束后必做动作

1. **更新Gap状态**：逐条在规则清单中标注「已解决/待解决/裁定挂起」
2. **更新轮次台账**：按第五节格式记录当轮进展（见第五节）
3. **判定是否终止**：逐项检查终止条件（见3.4）

### 3.4 轮次终止条件

以下4项**全部满足**时，方可终止多轮迭代：

| # | 终止条件 | 验证方式 |
|---|---|---|
| 1 | A类Gap全部清零 | 逐条确认：所有信息缺失Gap已通过二次访谈补全 |
| 2 | B类Gap全部清零 | 逐条确认：所有岗位边界Gap已通过换岗访谈补全 |
| 3 | C类Gap全部挂起或已裁定 | 逐条确认：每条C类Gap已标注「裁定挂起·不阻塞」或已获得裁定结果并回填 |
| 4 | 无Gap验证通过（见第四节） | 通过5维验证标准 + 6项自检 + Claude初审 |

**终止后产出**：无Gap规则清单，版本号升级至v2.0，可进入SOP撰写。

### 3.5 C类裁定Gap挂起规则

C类裁定Gap在Mark未回复时的处理：

- 在规则清单中标注「**裁定挂起·不阻塞**」
- 在SOP中对应规则标注「**待裁定**」
- **不阻塞A/B类闭环继续推进**
- Mark回复后，按裁定结果回填规则清单，移除「裁定挂起」标签
- Jasper负责在台账中追踪裁定回复状态

## 四、无Gap验证标准

### 4.1 五个验证维度

| 维度 | 验证内容 | 通过标准 |
|---|---|---|
| **完整性** | 原始规则清单中每条规则是否有对应回填 | 27条规则空白（P0/P1/P2）全部有回填记录，无遗漏 |
| **归属性** | 每条规则回填的岗位来源是否正确 | 回填内容与访谈对象岗位职责一致，无跨岗位越界 |
| **一致性** | 同一规则的多轮回填/多岗位回填是否一致 | 无矛盾。如有不一致，已标注差异并给出处理建议 |
| **可溯源性** | 每条规则回填是否有数据锚点 | 至少标注「表名.字段名 — 口述确认/文档佐证/系统验证」|
| **无Gap性** | A/B类Gap是否全部清零 | 所有A/B类Gap标注为「否」，C类Gap标注为「裁定挂起·不阻塞」或已回填 |

### 4.2 执行终端自检Checklist

规则清单产出终端（Claude）在提交无Gap验证前，必须逐项自检：

- [ ] 全部27条规则空白均有对应规则回填，无遗漏
- [ ] 每条规则的数据锚点（表名.字段名）已标注，无空值
- [ ] 每条规则的外化状态（已文档化/口头经验/完全未记录）已标注
- [ ] A类Gap全部清零（逐条确认为「否」）
- [ ] B类Gap全部清零（逐条确认为「否」）
- [ ] C类Gap已标注「裁定挂起·不阻塞」或已回填

### 4.3 Claude初审标准

Jasper验收前，Claude执行初审，按以下格式输出结论：

```
【Claude初审结论 · Gap闭环验证】

5维验证结果：
  - 完整性：□通过 / □不通过（如有不通过，列出缺失项）
  - 归属性：□通过 / □不通过（如有不通过，列出越界项）
  - 一致性：□通过 / □不通过（如有不通过，列出矛盾项）
  - 可溯源性：□通过 / □不通过（如有不通过，列出未标注项）
  - 无Gap性：□通过 / □不通过（如有不通过，列出残留Gap）

6项自检复核：□终端自检通过 / □发现遗漏（列出）
总体判定：□可提交Jasper验收 / □退回修改（附修改要求）
```

**注意**：初审为全量检查，不抽查。Claude初审不替代Jasper最终验收。
