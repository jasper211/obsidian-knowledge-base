## 一、为什么需要这些数据

M3的核心产出之一是**过渡路径** — 从"当前组织"迁移到"AI组织化新组织"。没有当前组织的基线(多少人/什么编制/现岗职责/薪资结构),无法做任何迁移规划。

M2已经通过 `L4-Agent化评估报告.md` 证明:
- 68% L4 可由Agent主导 (Auto 80 + Aug 91 = 171条)
- 肉身核心介入点 ≈ 88条
- 新组织规模估计: 10~20人核心团队 + 200+ agents

这组数字与当前实际人数的差异,就是"人效400→800万"的杠杆空间。

## 二、4类基线数据清单

### 类型1: 在编人员总数与分布 (P0)

**需要字段**:
| 字段 | 示例 | 用途 |
|------|------|------|
| 员工ID/工号 | 匿名化即可 | 基线对齐 |
| 所属业务线/部门 | 权益中台/代理人事业部/BD/技术/职能 | 映射到L1飞轮 |
| 当前岗位名称 | 如"高级业务发展经理" | 映射到现有岗位族 |
| 汇报对象 | 上级岗位 | 画当前报告线 |
| 入职日期 | - | 计算资历 |
| 雇佣类型 | 正式/外包/顾问 | 组织边界 |

**交付形式**: 脱敏XLSX,可替换真实姓名为编号 (如 E-001/E-002)

---

### 类型2: 编制 vs 实际人数 (P0)

**需要字段**:
| 部门/业务线 | 编制数 | 实际人数 | 缺口 | 过剩 | 备注 |
|-----------|-------|--------|-----|-----|------|
| - | - | - | - | - | - |

**用途**: M3.5过渡路径中,缺口岗位可优先落入新架构,过剩岗位需要转岗方案

---

### 类型3: 现岗职责清单 (P0)

**需要字段** (每个唯一岗位名一行):
| 字段 | 示例 |
|------|------|
| 岗位名称 | 高级业务发展经理 |
| 岗位等级 | P5 / M2 |
| 主责领域 | 机构合作开发 |
| KPI核心3项 | 新签机构数/合作深度/流水贡献 |
| 当前所属价值流/业务线 | VS-2 机构合作伙伴旅程 |
| 能力关键词 | BD能力/关系管理/谈判 |
| 在编人数 | 6 |

**用途**:
1. 映射到M2的47个L3协同框架,找到现岗→L3的对应关系
2. M3.1 介入点聚类时,作为"现岗基线"对照

---

### 类型4: 薪资结构概览 (P1,不需要具体数字)

**需要字段** (按岗位族聚合,不要个人数据):
| 岗位族 | 人数 | 薪资区间(月薪) | 总包成本范围 | 占比 |
|-------|-----|-------------|-----------|-----|
| 高管层 | - | - | - | - |
| 业务线负责人 | - | - | - | - |
| 中层 | - | - | - | - |
| 一线专业 | - | - | - | - |
| 一线执行 | - | - | - | - |
| 职能支撑 | - | - | - | - |

**用途**:
1. 计算当前人效基线 (总收入/总人力成本)
2. 评估"人效400→800万"的杠杆空间
3. M4 agent化的ROI分析 (agent成本 vs 人力成本)

**隐私**: 只需区间+总额,不需要个人薪资
