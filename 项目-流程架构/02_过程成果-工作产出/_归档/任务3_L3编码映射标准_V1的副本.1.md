# L3流程编码映射标准
> 版本：V1.1 | 日期：2026-04-22
> 用途：数据库导入时的L3/L4编码统一标准，所有来源文件的编码在入库前必须按本标准转换
> 适用范围：02.EA包A知识库全部CSV/md/txt文件
> 维护人：流程小组（Teresa）
> 依据：L3流程编码全量表（AI平台提取）+ 数据字典V1 + L3编码注册表

## 一、编码格式标准（SSOT）

所有入库的L3/L4编码必须符合以下格式，来源于数据字典V1（DP-006 / DP-012）：

```
L3标准格式：^L3-[A-Z]{2,6}$
示例：L3-IAO、L3-KASC、L3-CMU

L4标准格式：^L4-[A-Z]{2,6}-\d{2}[a-z]?$
示例：L4-IAO-01、L4-CMU-03、L4-BME-05a
```

**不合规格式（入库前必须转换）**：
- 带数字序号后缀：`L3-COM-01`、`L3-PROC-05`、`L3-BMC-03` → 不合规
- 带字母后缀：`L3-RSD-RW`、`L3-RSD-JD` → 不合规

**格式验证结果**：经AI平台全量提取和本次映射处理后，104条保留记录中标准编码**格式合规率100%**，无待处理异常。

### R4：编码拆分（L3-ISD → 8个独立编码）

L3-ISD原为"统一服务执行流程"，实际对应8个不同服务商的独立流程。通过**名称关键词**识别后拆分为8个独立L3编码。

| 名称中的识别关键词 | 标准L3代码 | 标准L3名称 |
|----------------|----------|---------|
| 机酒车 / 出行公司（无其他服务商标注） | **L3-TRVL** | 出行公司机酒车服务执行 |
| 商考 / 活动（出行公司） | **L3-ACTV** | 出行公司商考活动服务执行 |
| 迪邦 / 移民教育 | **L3-IMED** | 迪邦移民教育服务执行 |
| 保了么 / 教练陪跑 | **L3-COCH** | 保了么教练陪跑服务执行 |
| 新动力 + 课程/培训 | **L3-TRNG** | 新动力课程培训服务执行 |
| 新动力 + 品牌/营销 | **L3-BRND** | 新动力品牌营销服务执行 |
| 比域 / 咨询 | **L3-CONS** | 比域咨询服务执行 |
| 塞尔斯 / 结算 | **L3-STLM** | 塞尔斯结算服务执行 |

**入库规则**：
1. 读取到`L3-ISD`时，检查对应L3名称包含的关键词
2. 按上表匹配，映射到对应标准编码和标准名称
3. 含"统一"或"8服务商"字样的记录：**删除，不入库**
4. 无法匹配任何关键词的记录：**标记"待人工确认"，不自动入库，推送告警**

| 原L3代码 | 判断规则 | 标准L3代码 | 标准L3名称 |
|---------|---------|----------|---------|
| L3-RSD-RW | 直接映射（编码后缀-RW） | **L3-RSD** | 权益方案框架设计 |
| L3-RSD（名称含"权益"/"方案"/"框架"/"设计"） | 名称关键词判断 | **L3-RSD** | 权益方案框架设计 |
| L3-RSD-JD | 直接映射（编码后缀-JD） | **L3-RSJD** | 经代机构销售业务执行流程 |

**判断优先级**：编码后缀 > 名称关键词 > 标记"待人工确认"（两者均不满足时）

## 五、入库执行流程

```
读取源文件中的L3编码和L3名称
        ↓
Step 1：检查编码是否在删除列表（RD规则）
        ├── 是 → 丢弃，记录日志，不入库
        └── 否 → 继续
        ↓
Step 2：检查编码是否在R1~R5映射表中
        ├── R1（名称统一）→ 保留编码，替换名称为注册表标准名称
        ├── R2（编码修改+名称统一）→ 替换编码和名称
        ├── R3（编码纯字母化）→ 替换编码，名称保留
        ├── R4（ISD拆分）→ 检查名称关键词，映射到8个新编码之一
        │        └── 无法匹配 → 标记"待人工确认"，不入库
        ├── R5（RSD合并修改）→ 按编码后缀或名称关键词映射
        │        └── 无法判断 → 标记"待人工确认"，不入库
        └── 不在任何映射表中
                ├── 格式符合 ^L3-[A-Z]{2,6}$ → R6，直接入库
                └── 格式不符合 → 标记"待人工确认"，不入库，推送告警
        ↓
Step 3：同步更新对应L4编码前缀（按第四节规则）
        ↓
Step 4：写入数据库
        └── confirmation_status根据来源文件打标（见A0数据溯源标准）
```
