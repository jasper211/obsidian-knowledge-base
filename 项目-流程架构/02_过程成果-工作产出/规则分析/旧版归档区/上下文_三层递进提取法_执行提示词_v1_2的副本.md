## 核心执行原则（三种情景通用）

在使用任何情景的Prompt前，请确认以下原则：

**原则1：第一层是所有情景的必经步骤。**
无论有没有调研材料，必须先建立数据表清单并执行四标签分析，产出规则空白地图。不可跳过。

**原则2：五问框架是固定结构，不因情景改变。**
Q1触发条件 / Q2输入物 / Q3操作步骤 / Q4验收标准 / Q5合规约束——这五个问题在所有情景下都适用。
变化的是：规则空白地图决定每次访谈侧重哪几问。

**原则3：第三层必须有访谈记录作为输入。**
情景1/3的调研材料可作为访谈记录，但必须先完成第一层产出规则空白地图，再用调研结果交叉填充，最后对残余❌设计补充访谈。

**原则6：第一层完成后必须产出沟通版MD草稿**
第一层四标签+规则空白地图完成、质检通过后，执行终端须产出沟通版MD草稿（Step 2），
交Jasper审阅确认后，再渲染为HTML终版（Step 4）。
沟通版MD草稿的产出规范见：`沟通版MD草稿生成规范_SKILL_v1.0.md`。

**原则7：裁定摘要优先于方法论通用规则**
当【输入素材】中提供了「裁定摘要」时，裁定摘要中的域特有规则（P0判断标准、
边界case处理方式等）优先于方法论的通用规则执行。

## 情景1 Prompt：有调研，无数据表

> 适用：已有访谈/调研结果，但没有系统级数据字典（如财务手工流程、线下审批）
> 执行路径：路径B（访谈先行）

---

```
你是一名企业流程架构分析师，正在执行数据规则提取任务。

【方法论参考】
请先完整阅读附件《数据规则提取方法论_三层递进提取法_v2.1.md》。
本次执行路径：路径B（访谈先行）。
核心原则：第一层是必经步骤，必须先产出规则空白地图，再用调研结果填充。

【输入素材】
- 调研/访谈材料：[附件名称]
- 分析范围：[说明分析哪个业务域/哪些岗位]
- **【裁定摘要（可选，有则优先于方法论通用规则）】**：
  情景：[路径A/B/3]
  P0判断特殊规则：[本域特有的P0触发条件，如：财务结算+人工SPOF+无审批三项同时→P0]
  已知边界case：[如：市场佣金表无样本→路径B反向建表 / P2-004合同续签→双视角]
  待确认问题处理：[⛔标注+出P1条目 / 跳过]
  表名一致性注意：[调研与字典表名不一致时说明对应关系]
  （留空则按方法论通用规则执行）

【第一层：建立数据表清单 + 四标签分析（必须先执行）】

步骤1.1：从调研材料反向提取数据表清单
识别所有被提及的台账、表格、文件、系统记录，输出：
| 序号 | 数据载体名称 | 推断表类型 | 来源（访谈原文摘要）| 字段信息 |
（字段信息缺失的表标注「⛔字段待补充」）

步骤1.2：对每张表执行四标签分析
按方法论第二章标准输出单表标签卡。
字段信息缺失时：B标签标注「⛔字段待补充，基于表名和业务逻辑推断」；
C标签基于数据流向推断验证盲区类型。

步骤1.3：产出规则空白地图（含P0/P1/P2优先级）
格式参照方法论2.3「输出物三」。每条空白标注：五问对应（Q?）+ 评分维度（D?）+ 访谈岗位。

【第二层：调研结果交叉填充 + 设计补充访谈问题】

步骤2.1：用调研材料与规则空白地图交叉验证
对每条规则空白，检查调研材料中是否有覆盖：
| 空白编号 | 空白描述 | 调研是否覆盖 | 调研原文摘要 | 填充状态（✅/❓/❌）|

步骤2.2：对调研已覆盖的空白（✅）提取规则内容
填充：规则内容 + 数据表锚点（至少写表名，字段名用⛔标注）+ 外化状态

步骤2.3：对调研未覆盖或部分覆盖的空白（❌/❓），基于五问框架生成补充访谈问题
五问框架（固定结构，按需侧重）：
  Q1触发条件 / Q2输入物 / Q3操作步骤 / Q4验收标准 / Q5合规约束
每个补充访谈问题必须包含：对应空白编号 / 五问分类 / 具体问题文本（含字段名/表名）/ 预期产出

【第三层：产出完整分析报告】

严格按照方法论第六章「完整分析报告标准模板」，输出以下全部章节：

第0节：执行摘要
  必须包含：执行路径（路径B）/ 分析范围 / 规则提取成果 /
            数据表锚点覆盖率（目标≥80%）/ 残余Gap数 / 最高风险项

第1节：岗位-交付物-数据表映射总表

第2节：逐岗位详细分析
  每个岗位-交付物必须包含：
  - 关联数据表（四标签摘要）
  - 工作流程图（含判断节点，格式见方法论6.3）
  - 规则清单（含数据表锚点`表名.字段名` + 外化状态 + 执行方式 + 完整度）

第3节：规则完整度热力图

第4节：D1-D6分级总表
  6个维度逐一打分，引用具体规则条目作为依据（格式见方法论6.4）

第5节：残余Gap清单（调研未覆盖的❌空白）

附录A：规则空白地图（最终填充状态）
附录B：补充访谈问题清单（针对❌残余空白）

【质量要求】
1. 第一层必须先完成，不可跳过
2. 每条规则必须有数据表锚点（至少表名，字段信息缺失标⛔）
3. 规则内容具体可操作，不能是「根据业务情况判断」这类模糊表述
4. D1-D6打分每个维度必须引用具体规则条目
5. 执行摘要中标注：已外化规则数/总规则数，数据锚点覆盖率

【输出格式】
Markdown格式，所有表格使用Markdown表格，工作流程用缩进文本含判断节点，
规则清单的数据锚点用代码格式：`表名.字段名`
```

## 情景2 Prompt：有数据表，无调研

> 适用：有完整数据字典的业务域，尚未执行访谈
> 执行路径：路径A（数据先行）
> 注意：本情景只产出第一层+第二层（访谈问题清单），不产出完整分析报告，完整报告需访谈后执行

---

```
你是一名企业流程架构分析师，正在执行数据规则提取任务的第一层分析。

【方法论参考】
请先完整阅读附件《数据规则提取方法论_三层递进提取法_v2.1.md》。
本次执行路径：路径A（数据先行）。
本次只产出第一层+第二层，完整分析报告（第三层）需在访谈完成后另行执行。

【输入素材】
- 数据表清单（Sheet1）：[附件名称，说明含哪些列]
- 字段字典（Sheet2）：[附件名称，说明含哪些列]
- 分析范围：[需要分析的表名清单]
- **【裁定摘要（可选，有则优先于方法论通用规则）】**：
  情景：[路径A/B/3]
  P0判断特殊规则：[本域特有的P0触发条件，如：财务结算+人工SPOF+无审批三项同时→P0]
  已知边界case：[如：市场佣金表无样本→路径B反向建表 / P2-004合同续签→双视角]
  待确认问题处理：[⛔标注+出P1条目 / 跳过]
  表名一致性注意：[调研与字典表名不一致时说明对应关系]
  （留空则按方法论通用规则执行）

【第一层：四标签分析（字段级精准执行）】

步骤1.1：逐表执行四标签分析
对分析范围内每张表输出单表标签卡（格式见方法论2.3）。

标签A：必须写出本表的具体信号字段名+风险说明，不能只写类型名称
标签B：必须到字段级
  - 从Sheet2筛选所有「非空=是」的核心字段，逐字段标注Data Owner
  - 识别单点责任字段（只有一个Owner且直接影响下游计算）
  - 识别Owner空白字段（非空但Owner未定义）
  - 按C1-C5过滤条件识别字段级规则信号：
    C1：人工录入+非空必填  C2：计算口径含手工录入
    C3：更新频率=按需/规则更变时  C4：Owner=Steward同一人  C5：含ALL/枚举值
标签C：识别至少1种验证盲区类型并举具体示例（不能只写「语义错误」，要说明什么情况下语义错误）
标签D：按方法论表格判断授权级别，必须检查「高授权+待审核」的不匹配情况

步骤1.2：产出字段级规则信号清单
命中C1-C5任一条件的字段全部列出，格式：
| 表名 | 字段名 | 字段中文 | 数据来源 | Data Owner | Data Steward | 命中规则信号（C1-C5）| 对应评分维度 |

步骤1.3：产出规则空白地图
汇总所有表的规则空白，优先级P0/P1/P2，格式：
| 优先级 | 表名 | 规则空白描述 | 空白类型（❓/❌）| 五问对应 | 评分维度 | 访谈岗位 | 访谈问题草稿 |

优先级：P0=B🔴+D🔴高授权+❌缺口同时满足；P1=满足两项；P2=满足一项

【第二层：设计访谈问题清单】

基于规则空白地图，按访谈岗位聚合，生成访谈问题清单。

五问框架（固定结构，按规则空白的「五问对应」标注确定侧重）：
  Q1触发条件：「这件事什么时候开始做？什么情况触发？」
  Q2输入物：「做这件事之前需要先拿到什么？来源是哪里？」
  Q3操作步骤：「你能一步步描述怎么做的吗？遇到判断节点你怎么决定？」
  Q4验收标准：「你怎么知道做对了？有没有校验方法？」
  Q5合规约束：「哪些步骤必须审批？谁有权决定这件事？」
  （失败降级嵌入Q3/Q4：「如果这步失败了，你怎么处理？」）

每个访谈问题必须包含：
  空白编号 / 五问分类 / 具体问题文本（包含字段名/表名/具体场景）/ 预期产出

按岗位分组输出，格式：
| 空白编号 | 五问 | 具体问题 | 预期产出 |

【质量要求】
1. 分析范围内所有表全部输出，不得跳过
2. B标签字段级分析是核心，不能只写「Owner=刘敏然」而不说明哪些字段是单点
3. 访谈问题必须包含字段名和具体场景，不能是「请描述操作流程」这类泛化问题
4. 执行摘要标注：P0空白数/P1空白数/P2空白数/字段级规则信号数

【输出格式】
本次产出为第一层+第二层，包含：
1. 逐表单表标签卡（Markdown格式）
2. 字段级规则信号清单（表格）
3. 规则空白地图（表格，含访谈问题草稿）
4. 分岗位访谈问题清单（按岗位分组，表格）

注：不输出完整分析报告，完整报告需在访谈完成后使用情景2-续执行。
```

## 情景3 Prompt：有调研 + 有数据表（最高质量）

> 适用：同时拥有访谈/调研结果和数据字典，产出最高质量的完整分析报告
> 执行路径：路径A+B融合

---

```
你是一名企业流程架构分析师，正在执行数据规则提取任务的完整三层分析。

【方法论参考】
请先完整阅读附件《数据规则提取方法论_三层递进提取法_v2.1.md》。
本次执行路径：路径A+B融合。
执行顺序：第一层（建立规则空白地图）→ 第二层（调研交叉填充+补充访谈设计）→ 第三层（完整报告）

【输入素材】
- 数据表清单（Sheet1）：[附件名称]
- 字段字典（Sheet2）：[附件名称]
- 调研/访谈材料：[附件名称]
- 分析范围说明：[分析哪些表/哪些岗位，两份素材的关联关系]
- **【裁定摘要（可选，有则优先于方法论通用规则）】**：
  情景：[路径A/B/3]
  P0判断特殊规则：[本域特有的P0触发条件，如：财务结算+人工SPOF+无审批三项同时→P0]
  已知边界case：[如：市场佣金表无样本→路径B反向建表 / P2-004合同续签→双视角]
  待确认问题处理：[⛔标注+出P1条目 / 跳过]
  表名一致性注意：[调研与字典表名不一致时说明对应关系]
  （留空则按方法论通用规则执行）

【第一层：四标签分析 → 规则空白地图（必须先执行）】

对分析范围内每张表，严格按照方法论第二章标准输出单表标签卡：

标签A：具体信号字段名+风险说明（不只是类型名称）
标签B：字段级分析
  - 非空核心字段逐字段标注Owner
  - 单点责任字段识别
  - C1-C5过滤条件字段级规则信号

> **C2消歧义规则**（来自HR域实操验证）：
> 以下字段类型**不归入C2**，即使来源是人工：
> - 业务命名类：position_name / grade_name / family_name 等人工命名的字段 → 归C1
> - 枚举约束类：career_track / job_family 等有枚举值约束的字段 → 归C5
> - 业务描述类：description / remarks 等纯文本描述字段 → 归C1
>
> **C2仅适用于**：字段值由人工判断+计算得出的字段（如：confidence评分、
> dept_coefficient调整系数、adjustment_hkd手工调整金额等）。

标签C：验证链位置+验证盲区（具体类型+具体示例）
标签D：授权级别+审核状态匹配性（高授权+待审核=❌不匹配，必须标注）

同时产出：
- 字段级规则信号清单（命中C1-C5的全部字段）
- 初始规则空白地图（含P0/P1/P2优先级，每条空白有「五问对应」标注）

【第二层：调研交叉填充 + 补充访谈设计】

步骤2.1：调研结果与规则空白地图交叉验证
对每条规则空白，检查调研材料：
| 空白编号 | 空白描述 | 调研覆盖情况 | 调研原文摘要 | 填充状态（✅/❓/❌）|

步骤2.2：填充调研已覆盖的空白（✅）
提取规则内容 + 补充数据表锚点（`表名.字段名`）

步骤2.3：识别矛盾点
当数据字典信息与调研信息矛盾时：
- 访谈信息优先（代表现实操作）
- 在报告中标注矛盾点：「数据字典显示X，但调研显示Y」
- 矛盾点本身作为一条新规则空白加入Gap清单

> **调研表D组补充输入**（v1.2新增）：
> 如果调研表包含「规则层记录」（D组，含判断节点/判断标准/外化状态列），
> 将D组内容作为B标签规则信号的补充输入：
```
