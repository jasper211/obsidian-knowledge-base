### R001 · P0-002：IA硬指标校验机制（拨出率≤50%/同行支付≤88%）

| 属性 | 内容 |
|:---|:---|
| **规则编号** | P0-002 |
| **优先级** | P0 |
| **规则主题** | 拨出率≤50%/同行支付≤88%的IA硬指标在应派环节无系统实时校验；规则已明确但未代码化 |
| **关联价值节点** | VN-PAY-03 · 应派清单三件套 |
| **关联数据表/字段** | FACT_PAYABLE_V1 / 拨出率、同行支付率 |
| **规则空白地图来源** | FIN001-V2 P0级（❌缺口 / Q5+Q3 / D6+D2） |
| **回填状态** | **已回填·待确认** |

#### 待确认原因

1. 边界值处理未定（49.9%按四舍五入还是严格大于拦截）；
2. 拨出率需跨期汇总，跨期口径未确认；
3. 硬拦截 vs 检出提醒的策略待Mark裁定。

#### 待确认方

Mark裁定（硬拦截策略+边界值） + Carrie+蔡依娜二次确认（跨期口径）

#### 规则正文

1. **如果**持牌经纪拨出，**则**拨出率 ≤ **88%**。（来源：「持牌经纪拨出率 ≤88%」— AI回复）

2. **如果**非持牌人员拨出，**则**拨出率 ≤ **50%**。（来源：「其他 ≤50%」— AI回复）

3. **如果**计算拨出率，**则**公式 = **成本实派 ÷ 牌照实收**，且需**跨期汇总**。业务规则SSOT已明确（编号ST-03），但视图`v_payout_ratio`未编码。当前为手工校验，应派环节无系统自动拦截。（来源：AI回复）

5. **v1.1补充·录音** 如果未来系统校验，则公式为「所有年期应派合计 ÷ 所有源头佣金合计」，产出一张拨出率检查表，识别超标部分，**由系统提醒结算员查看异常**。不一定做硬拦截，因业务上确有特殊情况。是否硬性拦截由业务部门决定。（来源：录音「不一定会去拦截，因为他们业务上也确实有挺多特殊情况的…做到的就是可以给他检出这种异常的情况」）
