### 1.2 关键发现

1. **数据底座覆盖率仅11.0%**：在400个L4中，仅有44个L4有明确的「产出数据表」（即直接写入/创建数据表）。这反映了当前流程数字化建设的真实深度——大多数L4活动虽然能读取数据（应用覆盖率72.0%），但并不直接产生结构化数据资产。

2. **V1的72.0%覆盖率被「高估」**：V1将「有关联表」（读取关系）与「有专属表」（写入关系）混为一谈。V1.1拆分后，真正具备数字化产出的L4仅占11.0%，其余61.0%仅有数据读取依赖。

3. **L3数据密度大幅下调**：基于数据底座覆盖率评级，82.9%的L3被评为「低」（V1仅32.9%）。仅4个L3（4.9%）被评为「高」。

## 二、方法论升级说明

### 2.1 V1 → V1.1 的核心变化

| 维度 | V1 | V1.1 |
|:---|:---|:---|
| 匹配逻辑 | 数据表业务含义 → 核心交付物 → L4 | 在V1基础上，进一步区分**写入关系** vs **读取关系** |
| 覆盖状态 | 有专属表 / 有关联表 / 无数据表 | **有专属表**（有产出表）/ **有关联表**（仅有输入表）/ **无数据表** |
| 支撑数据表 | 单一列（混合产出+输入） | 拆分为**产出数据表** + **输入数据表**两列 |
| 覆盖率指标 | 单一覆盖率 | **数据底座覆盖率**（有产出表）+ **数据应用覆盖率**（有输入或产出表） |
| 密度评级依据 | (专属+关联)/总数 | **有产出表/总数**（底座覆盖率） |

### 2.2 产出/输入判断规则（按优先级）

| 优先级 | 规则 | 说明 |
|:---|:---|:---|
| P0 | 18条强规则映射 | 基于业务语义明确的L4→产出表映射（如COM-03→Agg_Commission_Payable） |
| P1 | L4编码特定规则 | 基于L4活动名称中的明确创建/写入关键词判定 |
| P2 | 关键词匹配 | L4名称或交付物含「建档/录入/配置/上架/签订/生成」等关键词，且匹配对应表域 |
| P3 | 单表+创建类活动启发式 | V1仅关联1张表，且活动含创建关键词，推测为产出表（置信度「低」） |
| P4 | 兜底 | 无法判定产出关系 → 全部归为输入表 |

### 2.3 约束条件

- 语义推导来源的L4（109条）：产出表判定置信度上限为「中」
- 产出数据表每行最多2张（本批次无超过2张的情况）
- 分析/报告/监控/评估类活动，即使有创建关键词，也不判定为产出表
