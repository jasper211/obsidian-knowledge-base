## 枚举值规范

- **gap_id**: G7-PAY[节点后两位]-[三位序号]，例：G7-PAY01-001
- **gap_type**: 调研未覆盖 / 结构性 / 定义模糊
- **gap_subtype**: 流程空白 / 制度（标准）空白 / 工具空白
- **l_layer**: L3层 / L4层 / 数据架构层 / 治理层
- **status**: 未处理（初始值，处理中更新）
- **target_class**: B类·规则线索（全部固定）
- **resolution_result**: 待处理（初始值）/ 已转B类：[lead_id] / 已关闭 / 已确认·无需处理

## 扩展说明

### 去重说明
v1.9 Step5经过B类规则线索去重，删除了与Step4 B类重叠的5条冗余空白，保留16条独立空白。T7仅包含这16条去重后的空白。

### 已删除不纳入T7的5条
以下5条已归入T3 B类规则线索，不在T7中重复出现：
- 对账差异原因码分类体系（归入T3 S3-PAY02-001）
- IA合规规则具体条款（归入T3 S3-PAY04-001）
- 银行付款回执获取方式（归入T3 S3-PAY04-002）
- 阈值实时监控仪表盘（归入T3 S3-PAY04-003）
- 四类协议参数字段（归入T3 S3-PAY06-001）

### 新增子字段说明（v2.0）
v1.9对Gap信号空白进行了结构化拆解，新增3个子字段：
- **next_action**：针对该空白的下一步行动建议（如"需访谈XX岗位确认XX"）
- **target_class**：转化目标分类，全部固定为「B类·规则线索」
- **resolution_result**：处理结果，初始为「待处理」，处理后可更新为已转B类、已关闭等

### 与T3/T4的关系
- T7是未覆盖的盲区
- T3 B类是已有线索但需访谈确认的内容
- T4 C类是需要执行的建设工作
- T7空白经分析后可转化为T3 B类线索（target_class固定为B类·规则线索）
