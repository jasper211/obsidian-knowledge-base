# P2-2补充：数据平台文件三层分类 — 人工交付物 vs Agent元数据 vs Agent产出

> 赵琦 | 2026-04-17
> 核心问题：哪些文件是"人工最终交付物"（校准基准），哪些是"Agent可用的元数据"（输入），哪些是"Agent产出"（需要与人工比对）

---

## 一、三层数据血缘关系

```
Layer 0: 外部原始数据（保司给的）
    │
    ▼
Layer 1: 人工维护的维度表/配置表（Carrie手工交付物 = 校准基准）
    │
    ▼  Agent读取Layer 0 + Layer 1 → 自动生成
Layer 2: Agent输出（需要与Carrie历史人工版本比对）
```

---

## 四、结论与建议

### 现状
1. **config/ 13个文件 = 双重角色**：既是Carrie的人工最终交付物，也是Agent的输入元数据
2. **etl/output/ 5个文件 = Agent产出**：但缺少Carrie的人工历史版本作为校准基准
3. **3个SOP对应的DIM表不在数据平台中**：DIM_License、DIM_Carrier、DIM_PARTNER（可能在Carrie的本地Excel中，未入库）

### 要解决的问题
1. **找Carrie要人工基线**：问Carrie是否保留了Agent框架建立前她手工做的 Fact_Commission_Rate / Agg_Source_Commission_Wide / Agg_Market_Commission_Tier_Rate 的历史版本
2. **补齐缺失DIM表**：DIM_License / DIM_Carrier / DIM_PARTNER 有SOP但不在数据平台config/中
3. **建立基线比对机制**：一旦拿到Carrie的人工版本，可以建立自动化diff（行数/列结构/关键值抽样比对），作为Agent质量门的一部分
