## 二、逐维度检验规则

### D1：外部利益相关者检验（Q1）

- **检验问题**：这个流程服务的直接外部利益相关者是谁？
- **通过判据**（置信度：**高**）：能明确识别直接外部利益相关者，且为以下五类之一：保司、机构/经代、KA 客户、理财师、终端客户。L3 名称中包含该利益相关者关键词为强信号。
  - 示例：L3-IAO（保司合作接洽与评估）→ 保司；L3-FLM（理财师线索挖掘与招募）→ 理财师。
- **不通过判据**（置信度：**高**）：无直接外部利益相关者，利益相关者为内部团队、战略层或 KPI 驱动。
  - 典型失败案例：8 个 PROC 战略流程（L3-MIO/VPV/MED/CAS/SPE/SRE/MEI/SFC），利益相关者为平台战略层。
- **来源文件章节**：「3.1 核心判断问题」「5.1 规则A：外部性检验」

### D2：触发事件外部性检验（Q2）

- **检验问题**：这个流程的触发事件是什么？
- **通过判据**（置信度：**高**）：由外部利益相关者发起，如签约请求、上架请求、入职请求、服务请求、合作请求等。
  - 示例：L3-KAOP（KA 上架准备）由 KA 入驻请求触发；L3-CDA（权益客户需求诊断）由客户服务请求触发。
- **不通过判据**（置信度：**高**）：由内部战略、KPI、合规需求或运营监控驱动，无外部触发事件。
  - 典型失败案例：L3-SPE（战略目标与绩效体系建立）由内部战略驱动；L3-COM（佣金全链路管理）由内部结算合规驱动。
- **来源文件章节**：「3.1 核心判断问题」「5.1 规则A：外部性检验」

### D3：交付接收方检验（Q3）

- **检验问题**：这个流程的最终交付物接收方是谁？
- **通过判据**（置信度：**高**）：外部利益相关者收到明确价值，交付物为合同、服务成果、权益、赋能成果、上架确认等可感知价值。
- **不通过判据**（置信度：**高**）：
  1. 内部团队收到交付物（如战略报告、合规记录、数据报表）→ 归入非 VS 级（战略层/内部能力链）；
  2. 多条 VS 的价值阶段都会调用该流程的产出 → 归入非 VS 级（横切能力）。
  - 典型失败案例：L3-EO/RSD/SLCM/SLM 被≥2 条 VS 消费，属 L1-05 横切能力，不属任何单一 VS。
- **来源文件章节**：「3.1 核心判断问题」「5.2 规则B：横切能力检验」

### D4：端到端流程定义检验

- **检验问题**：这个流程是否满足 L3 端到端定义？
- **通过判据**（置信度：**高**）：L3 是「实现业务能力的跨部门可执行流程」（BIZBOK 定义），具有明确的流程起点和终点，跨越多个部门/角色协作完成。
- **不通过判据**（置信度：**中**）：
  1. 流程仅为单一部门内部操作，无跨部门协作；
  2. 流程仅为 L4/L5 级活动片段的聚合，非完整端到端（如名称仅为单一动作"数据录入""审核签字"级别）；
  3. 编码不完整或无对应业务流程（如已废弃的 L3-BMD/BME/MSI/MSE）。
  - 典型失败案例：异常短编码 L3-C、L3-CR（编码不完整，无对应业务流程，已被 RD 规则删除）。
- **来源文件章节**：「一、架构层级体系」「RD：删除规则」

### D5：价值链归属唯一性检验

- **检验问题**：这个流程在价值链中是否有唯一归属？
- **通过判据**（置信度：**高**）：
  - **L1 归属唯一**：每个 L3 编码必须且只能归属一个 L1 编码；同一 L3 的所有行（无论 L4/L5 如何切分）的 `l1_code` 和 `l1_name` 必须完全一致。
  - **VS 归属唯一**：每个 L3 编码至多归属 1 条 VS；若被≥2 条 VS 的价值阶段调用 → 识别为非 VS 级（横切能力）。
- **不通过判据**（置信度：**高**）：
  1. 同一 L3 的不同行出现不同 `l1_code` → 违反「L3 单属一 L1」强制规则；
  2. 同一 L3 被强行挂接到多条 VS → 违反「L3 至多归属 1 条 VS」强制规则；
  3. 当存在跨 L1 分裂时未按多数行+语义裁定统一归属。
- **规则冲突待裁定**（置信度：**高**）：
  - 佣金合规类 L3（CBD/CMU/COM/CVI）在文件①中标注「Mark 说佣金归 L1-02/L1-03，映射表归 L1-04，不一致」；文件②当前映射表将其归入 L1-03。扫描时遇到归属争议须标注「规则冲突待裁定」。
- **来源文件章节**：「规则1：L3单属一L1」「规则2：L3至多归属1条VS」「5.1 规则C：内部结算能力」

### D6：编码命名规范性检验

- **检验问题**：L3/L4 编码是否符合标准格式？
- **通过判据**（置信度：**高**）：
  - L3 标准格式：`^L3-[A-Z]{2,6}$`，示例：L3-IAO、L3-KASC、L3-CMU；
  - L4 标准格式：`^L4-[A-Z]{2,6}-\d{2}[a-z]?$`，示例：L4-IAO-01、L4-CMU-03；
  - L4 编码前缀必须与 L3 编码匹配（L4 前缀 = L4-{L3 字母部分}）。
- **不通过判据**（置信度：**高**）：
  1. 带数字序号后缀：`L3-COM-01`、`L3-PROC-05`、`L3-BMC-03` → 属旧版过渡编码，须映射为标准编码；
  2. 带字母后缀：`L3-RSD-RW`、`L3-RSD-JD` → 须按 R5 规则分流为 L3-RSD 或 L3-RSJD；
  3. L4 前缀与 L3 不匹配 → 违反 L3-L4 层级一致性；
  4. 异常短编码/组合编码：`L3-C`、`L3-CR`、`L3-KART` → 不入库，直接丢弃。
- **来源文件章节**：「一、编码格式标准」「四、L4编码同步更新规则」「RD：删除规则」

### D7：L4 物理交付物反向验证

> **用途说明**：本维度属 L4 层规则，作为判断 L3 是否被正确拆解为 L4 的**反向验证工具**，不直接用于 L4 层 Agent 化评估。

- **检验问题**：L3 下的 L4 是否均有合格物理交付物？
- **通过判据**（置信度：**高**）：L3 下的每个 L4 均有明确的核心交付物，且该交付物为「可交付、可验证、可归档的业务实体」（文档/数据表/系统记录/签字文件/凭证）。
- **不通过判据**（5 项子检验，置信度：**高**）：

| 子项编号 | 检验名称 | 不通过判据 | 典型失败案例 |
|:--------:|---------|-----------|------------|
| D7-1 | **交付物存在性** | `physical_deliverable` 字段为空 | L4 记录缺少核心交付物字段 |
| D7-2 | **交付物唯一性** | 一个 L4 对应多个物理交付物，或无明确单一交付物 | 某 L4 同时产出"合同+报告+系统记录"但未拆分 |
| D7-3 | **交付物类型合规** | 填写的是动作描述而非业务实体 | "完成沟通""发起审批""执行培训" |
| D7-4 | **交付物非状态化** | 填写的是状态变化而非产出物 | "已就绪""已完成""待确认" |
| D7-5 | **L3-L4 层级连续性** | L4 编码前缀与 L3 编码不匹配，或 L3 下无 L4 覆盖 | L3-XXX 下出现 L4-YYY-01（前缀不一致）|

- **来源文件章节**：「规则3：L4唯一物理交付物原则」「8.1 自动校验项」

## 三、综合判定规则

执行顺序：**D6 → D5 → D1~D3 → D4 → D7**，依次递进判定。

| 标签 | 判定条件 | 处理动作 |
|:----:|---------|---------|
| **✅ 通过** | D6 通过 ∧ D5 通过 ∧ D1~D3 全部通过 ∧ D4 通过 ∧ D7 无异常 | 判定为合格的端到端 L3，可直接进入 EFA-002 合规确认 |
| **⚠️ 存疑** | D1~D3 中部分维度通过（如 Q1 有外部利益相关者但 Q2/Q3 存在模糊），或 D7 出现 1~2 项轻微异常 | 需进一步确认：补充 L4/L5 内容判断，或核对历史裁定记录；不得直接判定为通过 |
| **🔄 建议拆合** | D4 不通过（非跨部门可执行或仅为活动片段），或 D6 不通过（编码格式违规需拆合映射），或 D5 发现同一 L3 被多条 VS/L1 调用且无法裁定 | 结构性问题：建议拆分（一个 L3 实际包含多个端到端流程）或合并（多个 L3 实际是同一流程的片段），或按映射规则重组编码 |
| **❌ 待裁定** | D1~D3 的 VS 归属与 D5 的 L1 归属冲突；或遇到横切能力边界模糊 L3（SRA/SPD/CFRM）；或发现 4 份文件之间存在规则矛盾 | 必须上报 Mark 或 Jasper 裁定，**不得自行取舍** |

### 判定流程图（简化）

```
开始
  │
  ▼
D6 编码规范？
  ├─ 否 → 🔄 建议拆合（编码违规）
  └─ 是 → D5 归属唯一？
            ├─ 否 → ❌ 待裁定（归属冲突）或 🔄 建议拆合
            └─ 是 → D1~D3 3问检验
                      ├─ 全部通过 → D4 端到端定义？
                      │                ├─ 否 → 🔄 建议拆合
                      │                └─ 是 → D7 L4反向验证
                      │                      ├─ 无异常 → ✅ 通过
                      │                      └─ 轻微异常 → ⚠️ 存疑
                      └─ 部分通过 → ⚠️ 存疑
```

## 四、EFA-002 执行注意事项

> 以下陷阱基于本次 4 份文件扫描发现的边界模糊点提炼，Kimi 在扫描 82 条 L3 时必须逐条对照。

### 陷阱 1：将 L1-05 横切能力误判为 VS-5 客户侧流程

- **场景**：L3 名称含"权益""服务""客户"等关键词时，Kimi 易惯性归入 VS-5。
- **风险点**：L1-05（权益中台）的 L3-RSD（权益方案框架设计）、L3-SLCM（权益服务生命周期管理）、L3-SLM（权益上市推广）、L3-EO（理财师权益分级）属中台统一管理视角，被多条 VS 消费，**不属任何单一 VS**。只有真正客户侧特有的流程（L3-CDA/OBC/CDS/COB 等）才归 VS-5。
- **避坑方法**：遇名称含"权益""服务"的 L3，必须先查 Q3（交付接收方）——若被≥2 条 VS 调用 → 非 VS 级。

### 陷阱 2：混淆 L1 归属与 VS 归属两个独立体系

- **场景**：Kimi 扫描时易将 L1 映射结果直接等同于 VS 映射结果。
- **风险点**：
  - L3 归 L1-05 ≠ L3 归 VS-5（L1-05 是横切能力层，不是 VS-5）；
  - L3 归 L1-01 ≠ L3 不属于任何 VS（需看具体流程是否有外部利益相关者）；
  - L3 归 L1-04 的佣金流程 ≠ 佣金属于某条 VS（佣金是内部结算能力）。
- **避坑方法**：扫描输出必须包含两个独立字段——`l1_code`（L1 归属）和 `vs_code`（VS 归属），分别判定，不可混为一谈。

### 陷阱 3：将非 VS 级流程强行挂接到 VS 以追求"全覆盖"

- **场景**：82 条 L3 中 16 条不属于任何 VS（战略赋能层 8 个 + 佣金合规层 4 个 + 横切能力层 4 个）。
- **风险点**：Kimi 可能因"不想让 L3 悬空"而强行将其挂接到某条 VS。文件①强制规则 1 明确：**不通过外部性检验的 L3 归入"非 VS 级"，不得强行挂接**。典型案例：L3-MIO（市场洞察）无外部利益相关者，强行挂接到 VS-1 属违规。
- **避坑方法**：D1~D3 任一维度不通过 → 直接归为非 VS 级，不因"感觉应该属于某 VS"而人工补挂。

### 陷阱 4：忽略 L4 交付物对 L3 的反向验证价值

- **场景**：Kimi 扫描时只看 L3 名称和描述，未检查其下 L4 的核心交付物。
- **风险点**：若某 L3 下的 L4 交付物为空、为动作描述（"完成沟通"）或状态变化（"已就绪"），可能意味着该 L3 被错误拆解，或并非真正的端到端流程。D7-1~D7-5 是发现 L3 结构性问题的低成本手段。
- **避坑方法**：每个 L3 扫描时，必须同步检查其 L4 清单的交付物字段；发现 D7 异常时，优先标记 ⚠️ 存疑 或 🔄 建议拆合。

### 陷阱 5：横切能力边界 L3（SRA/SPD/CFRM）的归属争议

- **场景**：文件①将 L3-SRA/SPD/CFRM 列为"待裁定"（VS-5/L1-05 边界），文件②将其列为"横切能力（L1-05 特殊子集）"。
- **风险点**：**两文件之间存在规则冲突**。Kimi 若自行选择其中一种归属，将造成后续 EFA-002 扫描结果不一致。
- **避坑方法**：扫描时遇到这 3 个编码，**必须标注 ❌ 待裁定**，不得自行推断 VS 归属。在输出中注明「文件①待裁定 vs 文件②横切能力——规则冲突」。

### 陷阱 6：ISD 拆分编码的层级混淆

- **场景**：L3-ISD 已拆分为 8 个子编码（ACTV/BRND/COCH/CONS/IMED/STLM/TRNG/TRVL）。
- **风险点**：Kimi 可能将 8 个子编码各自独立判断 VS 归属，导致同一服务交付流程被碎片化归属。文件①明确：ISD **整体**属于 VS-5（S5 持续服务交付），8 个子编码仅在权威清单中展开。
- **避坑方法**：全量表 V3 层面以 L3-ISD 为单位判断归属（VS-5）；进入 L4 展开时，8 个子编码的 VS 归属继承 L3-ISD，不做单独判断。
