# L3 流程调研方法论：从会议录音到 D1-D4 交付

> **版本**: V1.0  
> **适用范围**: 企业架构（EA）L3 流程调研与交付  
> **目标读者**: 架构负责人、业务负责人、Claude（评估代理）  
> **交付物关联**: 本方法论规范了调研工作流，确保交付物可复现、可评估、可追溯。

---

## 一、工作流总览

```
┌─────────────────────────────────────────────────────────────────────────┐
│  Phase 1          Phase 2              Phase 3           Phase 4        │
│  会议采集    →    调研Excel生成    →   D1-D4生成    →   监控表更新      │
│                                                                        │
│  ┌─────────┐     ┌──────────────┐    ┌──────────┐    ┌─────────────┐  │
│  │录音/纪要│     │L3调研采集表  │    │D1 修正清单│    │L3现状一览   │  │
│  │  →JSON  │     │差异项汇总    │→   │D2 偏差报告│→   │各域状态表   │  │
│  └─────────┘     │L4交付物明细  │    │D3 重构方案│    └─────────────┘  │
│                  │D2价值节点清单│    │D4 Mark裁定│                      │
│                  │(同步产出)    │    └──────────┘                      │
│                  └──────────────┘                                      │
│                                                                        │
│  【数据底座】dim_process (唯一可信源)  【评估点】Claude 逐阶段校验       │
└─────────────────────────────────────────────────────────────────────────┘
```

### 四阶段定义

| 阶段 | 名称 | 核心产出 | 评估标准 |
|---|---|---|---|
| **P1** | 会议采集与结构化 | 会议转录 JSON | 信息完整性、字段可归一化 |
| **P2** | 调研 Excel 生成 | `调研_{业务}_{日期}_V{x.x}.xlsx` + `D2_价值节点清单` | L3/L4 对齐 dim_process、无占位符、价值节点同步绑定 |
| **P3** | D1-D4 交付物生成 | `D1_修正版L4清单` + `D2/D3/D4_Markdown` | 差异项闭环、P0/P1 分级准确、Mark 决策链完整 |
| **P4** | 流程监控表更新 | `流程库状态监控表_L3成熟度跟踪_V{x.x}.xlsx` | 调研状态 100% 同步、L3 生命周期可追溯 |

## 二、Phase 1：会议采集与结构化

### 2.1 输入

- **原始素材**: 业务调研会议录音（如 05-21 经代线路会议）
- **辅助信息**: 与会人名单、议题预设

### 2.2 处理步骤

| 步骤 | 工具/方法 | 输出 | 质量检查点 |
|---|---|---|---|
| S1.1 | 语音转文字（ASR） | 原始转录文本 | 关键人名、术语识别率 |
| S1.2 | 人工整理为结构化 JSON | `会议_{日期}_{主题}.json` | 议题分段、责任人到场确认 |
| S1.3 | 关键词预标注 | JSON 中标注 `L3范围`、`痛点信号`、`行动项` | 为 P2 的自动提取提供锚点 |

### 2.3 JSON 标准格式

```json
{
  "meeting_date": "2026-05-21",
  "participants": ["Mark", "Terresa", "MOMO", "Carrie"],
  "topics": [
    {
      "title": "一军/中银大单与佣金派发流程问题",
      "content": "一季度签订多张中银人寿大单...",
      "keywords": ["大单", "佣金", "L3-JOD", "L3-URF"],
      "pain_signals": ["缺乏规范流程", "口径不统一"]
    }
  ],
  "conclusion": "建立合并口径的数据仓...",
  "full_text": "..."
}
```

### 2.4 评估清单（Claude 校验）

- [ ] 每个议题是否标注了涉及的 L3 范围？
- [ ] 痛点信号是否被独立提取（而非淹没在叙述中）？
- [ ] 行动项是否有明确责任人与时间节点？

## 三、Phase 2：调研 Excel 生成（核心阶段）

### 3.1 输入

- **会议 JSON**（P1 产出）
- **dim_process 标准数据**（唯一可信源，PostgreSQL `process_analytics.DIM_PROCESS`）
- **D2_价值节点_L3映射表**（GBK 编码，`03_发布成果-交付物/权威数据/`）
- **经代 L3L4 调研 Excel**（已有实际状态字段）

### 3.2 处理步骤

| 步骤 | 工具/脚本 | 输出 | 关键规则 |
|---|---|---|---|
| S2.1 | `generate_survey_from_meeting.py` | **调研 Excel 初稿** | `--l3-codes` 限定范围，先规则提取再 Kimi 补全 |
| S2.2 | `fill_gap_analysis.py` | **差异项汇总 Sheet** | 自动对比 dim_process vs 调研数据，生成 Gap |
| S2.3 | `generate_d2_from_survey.py` *(待建)* | **D2 价值节点清单** | 根据 L3 → VN 映射表，同步产出价值节点评估 |
| S2.4 | 人工核实 | **调研 Excel 终稿** | 痛点字段禁止"参见会议记录"，无法识别则留空 |

### 3.3 调研 Excel 标准结构

```
调研_{业务标签}_{日期}_V{x.x}.xlsx
├── 0_调研说明
├── 调研执行记录          ← 日期、调研人、覆盖L3、被调研人
├── L3调研采集表          ← 核心：17字段（触发场景/执行步骤/岗位/痛点/差异）
├── 差异项汇总            ← 结构性/状态性/责任性偏差，P0-P2 分级
├── L4交付物明细          ← dim_process 标准 + 实际状态
└── D2价值节点评估        ← 【同步产出】VN-MGA-01~04，P1熔断结论
```

### 3.4 价值节点清单的同步产出规则

> **关键原则**：价值节点清单不是 D1-D4 的附属产物，而是与调研 Excel **同时生成**的标准交付物。

**触发时机**：当 `L3调研采集表` 中的 L3 在 `D2_价值节点_L3映射表` 中有对应记录时，自动触发价值节点评估。

**产出内容**：

| Sheet | 内容 | 来源 |
|---|---|---|
| 1.价值节点总览 | 节点ID、L3闭环、物理资产、构成、形态、M锚定、KPI、裁定结论 | 映射表 + dim_process |
| 2.节点详情卡 | 4张完整属性卡（业务定位/价值属性/物理对应/数据验证） | 自动填充模板 |
| 3.四属性三重验证矩阵 | Gate①挂数 / Gate②落地 / Gate③追溯 | 根据调研状态判定 PASS/FAIL |
| 4.M0-M8锚定矩阵 | 节点在 M0-M8 战略闭环中的位置 | 映射表固定字段 |
| 5.熔断与行动清单 | 熔断原因、致命缺口、裁定责任人、行动事项、里程碑 | 根据差异项自动推导 |

**评估标准**：
- [ ] 价值节点是否 **100% 覆盖** 调研涉及的 L3？
- [ ] 每个节点的 **4硬性属性 + 3重Gate** 是否全部评估？
- [ ] 熔断结论是否与 D1-D4 中的差异项优先级 **一致**？

## 四、Phase 3：D1-D4 交付物生成

### 4.1 输入

- **调研 Excel 终稿**（P2 产出，人工确认后）
- **差异项汇总**（已填充）
- **D2 价值节点清单**（已产出）

### 4.2 处理步骤

| 步骤 | 脚本 | 输出 | 关键规则 |
|---|---|---|---|
| S3.1 | `generate_d1_d4_from_survey.py` | `D1_修正版L4清单.xlsx` | dim_process 为基线，调研状态为实际，标"修正/新增/废弃" |
| S3.2 | 同上 | `D2_L4偏差分析报告.md` | 按差异类型分组，五大洞察汇总 |
| S3.3 | 同上 | `D3_L3架构重构方案.md` | 端到端原则检查，P0/P1/P2 实施优先级 |
| S3.4 | 同上 | `D4_Mark裁定清单.md` | 独立成册，P0 必须决策 + P1 建议决策，含勾选框 |

### 4.3 D1-D4 交付物详解

#### D1：修正版 L4 清单（Excel）

```
D1_{业务标签}_修正版L4清单_{日期}.xlsx
├── L4清单总览        ← dim_process L4 + 修正标记 + 修正说明
├── 新增L4明细        ← 结构性偏差衍生的新增建议
├── 责任人修正表      ← 责任性偏差汇总
└── D2关键里程碑      ← 价值节点行动事项 + T+N 里程碑
```

**修正标记规范**：

| 标记 | 含义 | 触发条件 |
|---|---|---|
| ✅ 正常 | dim_process 与实际一致 | 无差异项 |
| 📝 修正 | 责任人/状态/定义偏差 | 责任性/状态性偏差 |
| 🔧 需扩展 | 缺少 L4 或粒度不足 | 结构性偏差 |
| ➕ 新增 | 实际存在但 dim_process 未定义 | 新增流程差异 |
| 🗑️ 已废弃 | 流程已合并或淘汰 | 已废弃流程差异 |
| 🔀 合并结果 | 由多个 L3 合并而成 | 合并操作后标注 |

#### D2：L4 偏差分析报告（Markdown）

**强制包含章节**：
1. 差异项按类型分组（结构性/状态性/责任性/已废弃/其他）
2. 五大洞察（Insight Summary）
3. 每个洞察需有 `影响范围` + `量化证据` + `建议行动`

#### D3：L3 架构重构方案（Markdown）

**强制包含章节**：
1. 当前架构问题诊断（差异项数 + 核心问题）
2. L3 变更建议（含合并/拆分/废弃说明）
3. 端到端原则检查（价值流表格）
4. 实施优先级（P0/P1/P2 时间线）

#### D4：Mark 裁定清单（Markdown）

**强制包含章节**：
1. A类 - P0 级裁定（M4.1 前必须决策）
2. B类 - P1 级裁定（M4.1-M4.2 建议决策）
3. 汇总表（序号 | L3 | 类型 | 优先级 | Mark 决策 | 批注）

### 4.4 评估清单（Claude 校验）

- [ ] D1 中每个 L4 是否有明确的修正标记？
- [ ] D2 的五大洞察是否有 **量化证据** 支撑（非定性描述）？
- [ ] D3 的架构变更是否遵循 **L3 变更最小化** 原则？
- [ ] D4 的 P0 项是否全部对应 **P0 熔断规则**（合规/审计/资金安全）？
- [ ] 四个交付物的 L3 编码是否 **完全一致**（无遗漏/多余）？

## 五、Phase 4：流程监控表更新

### 5.1 输入

- **D1-D4 交付物**（P3 产出）
- **流程库状态监控表**（`流程库状态监控表_L3成熟度跟踪_V{x.x}.xlsx`）

### 5.2 处理步骤

| 步骤 | 脚本 | 输出 | 关键规则 |
|---|---|---|---|
| S4.1 | `update_monitor_table.py` | **更新后的监控表** | 遍历所有 Sheet，匹配 L3 编码，更新调研状态 |
| S4.2 | 人工复核 | 确认监控表与 D1-D4 一致性 | 抽样检查 3-5 个 L3 的状态链 |

### 5.3 监控表更新字段

**L3现状一览（主表）**：

| 字段 | 更新规则 | 示例值 |
|---|---|---|
| 调研状态 | 未调研 → `❓ 待调研`；已调研 → `✅ 已调研({业务标签})`；废弃 → `⚠️ 已废弃` | ✅ 已调研（经代） |
| 责任人 | D4 中的裁定责任人 | Mark / BD团队负责人 |
| 备注 | D1-D4 文件路径 + 关键结论 | D1-D4已生成（经代），VN-MGA-01~03 P1熔断 |

**业务域 Sheet（如"经代""佣金"）**：

| 字段 | 更新规则 |
|---|---|
| 价值节点 | 绑定 D2 价值节点清单的节点ID + 裁定结论 |
| 注册状态 | 根据 D1 修正标记更新（正常/修正/扩展/废弃） |
| 协同框架 | D3 中的 L3 变更建议摘要 |

### 5.4 评估清单（Claude 校验）

- [ ] 监控表中已调研 L3 的数量 = D1-D4 中涉及的 L3 数量？
- [ ] 废弃 L3（如 L3-JOD）在监控表中是否标记为 `⚠️ 已废弃`（非直接删除）？
- [ ] 价值节点列是否与 D2 价值节点清单 **一一对应**？
- [ ] 0_填写说明中是否记录了本次更新的 **日期、范围、数据来源**？

### 6.2 跨交付物一致性检查

```
一致性检查矩阵

                    D1-D4报告    D2价值节点    流程监控表
D1-D4报告           —           差异项与VN    L3状态一致
D2价值节点          差异项与VN     —           VN ID一致
流程监控表          L3状态一致    VN ID一致     —
```

**校验规则**：
- 同一 L3 在 D1-D4、D2、监控表中的 `优先级` 必须一致
- 同一 L3 在 D1 中的 `修正标记` 与监控表中的 `注册状态` 必须语义一致
- 同一价值节点在 D2 中的 `裁定结论` 与 D1 中的 `修正说明` 必须一致

## 八、快速评估指南（给 Claude）

当领导要求 Claude 评估本次调研工作成果时，请按以下顺序检查：

### Step 1: 交付物完整性（5分钟）
- [ ] 6个交付物是否全部存在？
- [ ] 文件命名是否符合 7.3 命名规范？
- [ ] 文件修改时间是否在同一批次（±2天）？

### Step 2: 数据一致性（10分钟）
- [ ] 抽取 3 个 L3（如 L3-COM, L3-URD, L3-JOD），检查其在 D1-D4 / D2 / 监控表中的描述是否一致
- [ ] 检查 L3-JOD 是否在 D1 中标注"已废弃"、在监控表中状态为"⚠️ 已废弃"（非直接删除）
- [ ] 检查 L3-UCA 是否在 D1 中标注"合并结果"并有合并说明

### Step 3: 质量深度（15分钟）
- [ ] D2 的五大洞察是否有量化证据？
- [ ] D4 的 P0 项是否全部有 Mark 决策勾选框？
- [ ] 调研 Excel 的痛点字段是否包含"参见会议记录"等占位符？（应为 **0 处**）

### Step 4: 流程规范性（10分钟）
- [ ] 0_调研说明 / 0_填写说明中是否有本次调研的更新记录？
- [ ] 调研执行记录中的覆盖 L3 列表是否与 D1-D4 一致？
- [ ] 价值节点清单是否在 D1-D4 之前产出？（检查文件修改时间）

---

> **结语**：本方法论的核心是 **"dim_process 唯一可信源 + 调研记录实际差异 + 价值节点同步评估"**。任何调研工作若偏离此原则，需在 0_填写说明中记录偏差原因。
