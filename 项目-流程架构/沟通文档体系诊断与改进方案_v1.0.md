## 二、诊断：现有链条的三类问题

### 2.1 问题一：沟通版只有"两端"，缺少"中间层"

| 应该存在的层次 | 实际状态 | 后果 |
|:---|:---|:---|
| **访谈预告**（访谈前发给被访者） | ❌ 缺失 | 被访者不知道"为什么要访谈我""要问什么"，准备不足 |
| **规则确认稿**（访谈后发给被访者确认） | ❌ 缺失 | 访谈完没有即时确认环节，等Gap清单出来已经过了很久 |
| **Gap跟进单**（Gap闭环阶段发给被访者） | ✅ 刚补上 | 但缺少"这个问题是从哪个规则来的"的上下文 |

**具体表现**：
- Chaya在第一轮访谈前，没有看到任何预告文档，不知道要准备什么
- 访谈后也没有即时确认稿，Chaya不知道自己说的内容是否被正确记录
- 等到Gap跟进单发过去时，距离第一轮访谈已经过去4天，记忆可能模糊

### 2.2 问题二：各沟通版之间没有显式链接

| 链接方向 | 当前状态 | 理想状态 |
|:---|:---|:---|
| 体检报告 → 规则空白地图 | ⚠️ 弱链接 | 每条P0/P1/P2规则应标注"规则空白地图中的编号" |
| 访谈工具包 → 体检报告 | ❌ 无链接 | 每个追问问题应标注"对应体检报告中的哪条规则" |
| 规则清单 → 访谈工具包 | ❌ 无链接 | 每条规则正文应标注"来源于哪次访谈、哪个问题" |
| Gap跟进单 → 规则清单 | ⚠️ 弱链接 | 每个待确认问题应标注"对应规则清单中的哪条Gap" |
| Gap跟进单 → 体检报告 | ❌ 无链接 | 被访者不知道"这个差异分类问题"属于P0级（立即处理） |

**具体表现**：
- 体检报告中P0-003叫"差异问题分类规则未书面化"，Gap跟进单中叫"差异分类怎么判断"——名称不统一
- 一线同事回复了Gap跟进单中的问题后，分析团队需要手动把回答映射回规则清单中的Gap编号
- 管理层看体检报告时，不知道"P0-003现在进展到哪一步了"

### 2.3 问题三：沟通版的内容没有按"受众"分层

| 受众 | 关心什么 | 现有文档给TA什么 |
|:---|:---|:---|
| **管理层/Mark** | P0有几条、谁负责、什么时候能补完 | 体检报告给了全景，但没有"进展追踪" |
| **被访者（一线）** | 为什么找我、要问什么、我说的是否被正确记录 | 没有访谈预告，没有确认稿，只有最后的Gap跟进单 |
| **访谈执行者** | 问什么、怎么算完成、上次访谈的结论是什么 | 有工具包和框架，但没有"上次访谈的摘要" |
| **分析团队** | 规则是否闭环、版本是否升级、还有多少Gap | 有规则清单，但沟通版的反馈需要手动回填 |

**具体表现**：
- 体检报告285行，对管理层来说可能太长；对一线来说又缺少操作细节
- Gap跟进单254行，对Chaya来说需要回答16个问题，但没有说明"哪些是你的、哪些是别人的"
- 没有"单人版"——没有把16个问题按收件人拆分成6份小清单

## 三、改进方案：四层沟通文档体系

### 3.1 总体架构

```
┌─────────────────────────────────────────────────────────────┐
│  Layer 1 体检报告（管理层）                                  │
│  → "我们发现27条规则空白，其中5条P0需要立即处理"              │
│  → 每条规则标注：编号 + 访谈岗位 + 当前状态                   │
└─────────────────────────────────────────────────────────────┘
                              ↓ 按岗位过滤
┌─────────────────────────────────────────────────────────────┐
│  Layer 2 访谈预告（被访者，访谈前发送）                       │
│  → "我们基于系统分析，发现你负责的XX环节有3条规则需要确认"     │
│  → 每条规则：1句话背景 + 预计问几个问题 + 你需要准备什么       │
└─────────────────────────────────────────────────────────────┘
                              ↓ 访谈后即时发送
┌─────────────────────────────────────────────────────────────┐
│  Layer 3 规则确认稿（被访者，访谈后24h内发送）                │
│  → "以下是我们整理的你的回答，请确认/补充/修正"               │
│  → 按规则分组：3-5条"如果…则…" + 确认/补充/修正 三栏          │
└─────────────────────────────────────────────────────────────┘
                              ↓ Gap评估后发送
┌─────────────────────────────────────────────────────────────┐
│  Layer 4 Gap跟进单（被访者，Gap闭环阶段发送）                 │
│  → "基于你的回答，我们已经确认了X条，还有Y条需要确认"          │
│  → 已知（已确认）+ 待确认（问题清单）+ 状态追踪                │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 各层文档的设计规范

#### Layer 1 · 体检报告（改进版）

**受众**：管理层/Mark/Lillian  
**时机**：Layer 1完成后  
**改进点**：

| 现有结构 | 改进后结构 | 改进原因 |
|:---|:---|:---|
| 执行摘要 → 数据链 → 集群风险 → P0 → P1 → P2 → 熔断节点 | 同上 + **新增"规则追踪总表"** | 管理层需要随时查"每条规则现在什么状态" |

**新增"规则追踪总表"**（放在执行摘要后面）：

| 规则编号 | 规则主题 | 优先级 | 访谈岗位 | 当前状态 | 首次访谈 | 剩余Gap |
|:---:|:---|:---:|:---|:---:|:---:|:---:|
| P0-003 | 差异问题分类 | P0 | JorJor/Lillian | 🟡 已回填·待确认 | Chaya/Soso 6/1 | 3条 |
| P0-004 | 汇率选取时点 | P0 | JorJor/Lillian | 🟡 已回填·待确认 | Chaya/Soso 6/1 | 4条 |
| P1-002 | 德约机构应派 | P1 | 中台 | 🟡 已回填·待确认 | Chaya/Soso 6/1 | 4条 |

> 这样管理层看体检报告时，可以直接定位到"P0-003现在是什么状态"，而不需要翻585行的规则清单。

#### Layer 2 · 访谈预告（新增）

**受众**：被访者  
**时机**：每次访谈前24-48小时发送  
**内容模板**：

```markdown
# 数据规则确认 · 访谈预告

> **致**：Chaya
> **背景**：我们在梳理财务付款环节的数据规则，系统分析发现你负责的「代理端差异核对」
> 环节有 **2条规则** 目前只存在于口头经验中，需要和你确认后写成书面文档。
> **预计时长**：30分钟
> **形式**：面对面 或 微信语音
> **时间**：2026年6月1日 下午2点（已和你确认）

---

## 我们要确认什么

### 话题1：差异分类怎么判断（约15分钟）

**为什么找你**：系统显示你负责代理端的实收应收差异核对。

**我们会问**：
1. 实收和应收对不上时，你一般怎么判断原因？（分几类？）
2. 如果同时存在多种差异，你怎么处理？
3. 旧单（2014-2023年）的差异核对是谁做？

**你需要准备**：无，凭日常操作经验回答即可。

---

### 话题2：汇率怎么算（约15分钟）

**为什么找你**：系统显示你负责填写汇率字段。

**我们会问**：
1. 不同保司的汇率按什么标准选？
2. 永明的美元汇率固定7.8吗？有没有例外？
3. 人民币账单的月平均汇率从哪儿来？

**你需要准备**：无，凭日常操作经验回答即可。

---

## 这不是考试

- 没有标准答案，我们要记录的是"实际怎么做的"
- 如果你觉得某个问题不该你回答，直接告诉我们"这个我问问XX"
- 访谈后我们会整理成书面规则发给你确认
```

**关键设计原则**：
- **一句话背景**：告诉被访者"为什么找我"
- **问题预告**：列出会问什么，让对方有心理准备
- **零准备负担**：强调"凭经验回答即可"
- **安全提示**：强调"不是考试"，降低防御心理

#### Layer 3 · 规则确认稿（新增）

**受众**：被访者  
**时机**：每次访谈后24小时内发送  
**内容模板**：

```markdown
# 数据规则确认 · 请你核对

> **致**：Chaya
> **来源**：2026年6月5日访谈记录
> **说明**：以下是我们根据你的回答整理的书面规则，请确认是否正确。
> **回复方式**：直接在微信里回复"问题1-1：对的"或"问题1-1：不对，应该是…"

---

## 话题1：差异分类怎么判断

### 规则1-1：差异分三类
**内容**：实收和应收对不上时，差异主要分为三类：①汇率差 ②佣金率错误 ③Over 100% Hold（"不派已转户"）。

**来源**：你说"保司的实收与应收之间的差异，大概讲了两种，一个是汇率汇差…主要就是他给的佣金率不对…over 100百分比的话，他就hold住"

**请你确认**：
- [ ] **确认**：以上理解正确
- [ ] **补充**：还有第四类：______
- [ ] **修正**：不对，实际是：______

---

### 规则1-2：不会同时存在多种差异
**内容**：这三种差异不会同时存在。如果万一同时存在，按金额大小处理：多付的不处理，少付的才处理。

**来源**：你说"不会出现同时有…按金额大小来处理…一般是按一个大小来放"

**请你确认**：
- [ ] **确认**：以上理解正确
- [ ] **补充**：还有一种情况是：______
- [ ] **修正**：不对，实际是：______
```

**关键设计原则**：
- **原文引用**：每条规则下方附上≤15字的原文引用，让对方知道"我确实说了这个"
- **三栏确认**：确认/补充/修正，降低回复门槛
- **规则编号映射**：每条规则标注对应规则清单中的编号（如P0-003-R1），但用小字放在角落，不干扰阅读
