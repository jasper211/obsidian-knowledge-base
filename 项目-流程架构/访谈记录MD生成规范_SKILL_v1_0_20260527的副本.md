# 访谈记录MD生成规范
> **文档代号**：SKILL-INT-001
> **版本**：v1.0 | **建立日期**：2026-05-27
> **适用范围**：所有基于FIN002系列访谈工具包执行的访谈，转录后统一生成标准MD
> **在三层递进中的位置**：第二层访谈执行 → 本规范产出 → 第三层规则回填输入
> **归档路径**：01_上下文文件（AI协作）/访谈记录MD生成规范_SKILL_v1_0_20260527.md
> **归档类型**：AI协同规则类 → 本地第二大脑（R9规则）

## 一、规范定位

### 1.1 为什么需要这份规范

访谈录音经AI工具转录后，产出的是**叙述性摘要**（导读格式），不是结构化规则记录。
叙述性摘要无法直接接入三层递进提取法的规则回填步骤，原因：

- 摘要按访谈时序组织，不按规则空白编号（P0/P1/P2）组织
- 摘要语言是叙述句，规则回填需要「如果…则…」格式
- 摘要未标注数据锚点（表名.字段名）
- 摘要未标注外化状态（已文档化/口头经验/完全未记录）

本规范定义**从转录文字→标准访谈记录MD**的完整转换流程，确保产出可直接用于规则回填。

### 1.2 与三层递进的关系

```
第一层：四标签 + 规则空白地图（FIN001系列）
  ↓ 产出27条规则空白（P0/P1/P2分级）
第二层：访谈工具包执行（FIN002系列）
  ↓ 录音 → 转录文字（通义听悟等工具）
  ↓ 本规范：转录文字 → 标准访谈记录MD  ← 本规范覆盖此步骤
第三层：规则回填
  ↓ 输入：标准访谈记录MD + 规则空白地图
  ↓ 产出：规则清单v1.0
```

## 三、标准访谈记录MD格式

### 3.1 文件命名规范

```
[工具包代号]_访谈记录_[受访人姓名]_[日期]_v[版本].md

示例：
FIN002-A_访谈记录_蔡依娜_20260527_v1.0.md
FIN002-B_访谈记录_JorJor_20260528_v1.0.md
```

### 3.2 文件头（必填）

```markdown
# [工具包代号]_访谈记录_[受访人姓名]
> **访谈日期**：YYYY-MM-DD
> **访谈对象**：[姓名·岗位]
> **工具包版本**：FIN002-V2 工具包[字母]
> **归口规则空白**：[P0-XXX / P1-XXX / P2-XXX，列出本次访谈覆盖的编号]
> **关联价值节点**：[VN-PAY-XX]
> **访谈时长**：约XX分钟
> **转录工具**：[通义听悟/其他]
> **记录版本**：v1.0（原始整理，未人工校对）
> **整理执行**：Kimi（基于本规范SKILL-INT-001 v1.0）
```

### 3.3 问题组记录块（核心结构，每个规则空白一个块）

每个问题组对应FIN002工具包中的一个规则空白编号，格式如下：

```markdown
---
## [规则空白编号]：[规则主题]
**关联价值节点**：[VN-PAY-XX · 节点名称]
**问题组来源**：工具包[字母] 问题组[序号]
**访谈时间戳**：[对应转录文字中的时间段，如 13:30–17:50]

### 访谈回答摘要
[2-4句话，提炼受访者对本问题组的核心表述，用第三人称]

### 提取到的规则
<!-- 每条规则用「如果…则…」格式，一条一行 -->
- 如果 [条件]，则 [动作/结果]
- 如果 [条件]，则 [动作/结果]

### 数据锚点
<!-- 格式：表名.字段名 — 来源类型 -->
- [表名].[字段名] — [口述确认 / 文档佐证 / 系统验证]

### 外化状态
- [ ] 已文档化（位置：___）
- [ ] 口头经验（持有人：___）
- [ ] 完全未记录

### 仍有Gap
- [ ] 是（说明：___）
- [ ] 否

### 回填建议
[「已回填·明确」/ 「已回填·待确认（疑点：___）」/ 「待补充（需___岗位访谈）」]
---
```

### 3.4 覆盖率统计（文件末尾必填）

```markdown
## 本次访谈覆盖率统计

| 规则空白编号 | 规则主题 | 回填建议 | 备注 |
|---|---|---|---|
| P0-001 | [主题] | 已回填·明确 / 已回填·待确认 / 待补充 | |
| P0-002 | [主题] | ... | |
| ... | | | |

**本次访谈归口规则空白**：共[N]条
**已回填·明确**：[N]条（[X]%）
**已回填·待确认**：[N]条（[X]%）
**待补充**：[N]条（[X]%）
```

## 四、执行步骤（Kimi执行标准）

```
Step 1 · 读取三份输入文件
  - 完整读取转录文字稿
  - 完整读取FIN002对应工具包
  - 完整读取FIN001规则空白地图（了解背景）

Step 2 · 建立对照表
  在执行前，先列出本次访谈对象归口的规则空白编号
  （来自工具包封面信息的「归口空白」字段）
  确认本次应处理N条规则空白

Step 3 · 逐条匹配
  对每个规则空白编号：
  a. 在工具包中找到对应问题组
  b. 在转录文字中定位相关时间段
  c. 按3.3格式填写问题组记录块

  匹配原则：
  - 以工具包问题组编号为索引，不以转录时序为索引
  - 转录中未明确提及的规则空白 → 标注「待补充」
  - 转录内容模糊/不完整 → 标注「已回填·待确认」并注明疑点
  - 不得基于常识或行业经验补充规则内容

Step 4 · 填写文件头和覆盖率统计

Step 5 · 自检
  □ 文件头信息完整
  □ 归口规则空白每条均有对应记录块，无遗漏
  □ 每条记录块含：摘要/规则/数据锚点/外化状态/Gap/回填建议
  □ 覆盖率统计数字与正文一致
  □ 未出现常识性规则补充（只来源于转录文字）
```

## 五、质量红线（不可触碰）

| 红线 | 说明 |
|---|---|
| 禁止补充转录未提及的规则 | Kimi不得基于行业经验或常识填写规则内容 |
| 禁止合并多条规则空白 | 每个P0/P1/P2编号必须有独立记录块 |
| 禁止省略数据锚点 | 每条规则必须标注对应表名.字段名 |
| 禁止模糊回填建议 | 三选一：明确/待确认/待补充，不得留空 |
| 发现矛盾时记录为附加观察 | 转录内容与工具包预期不一致时，不自行裁定 |
